# C-051 evidence - the 2D layout

## Verified in the browser (2026-11-09)

A demo plant outside the repository (in the session's scratch folder, nothing of it committed):
the bench (`veredas-maquinar`) serving 22 OPC UA tags on port 4875 (six parcels ramping round a
loop at 0.4 per 50 ms, twelve outlets filling by ramps of different paces, an infeed drawn between
stopped, running and fault every 6 s, a disabled flag, a writable release with a reaction that
empties outlet 3) and a log emitter writing a sort line every 300 ms; one supervisão file serving
one session `loop` on `127.0.0.1:8912`, whose binding has 23 objects (20 on an SVG of a loop, a
scanner, an infeed and twelve outlets) and one dashboard of eleven panels. The page was driven in
the desktop app's built-in browser, by pointer and read back by script and screenshot
(`.zen/evidence/supervisao/`).

Seen, live:
- every bound element taking its object's state: normal, near (amber fill, "■ near full"), warn
  ("■ full", "■ stopped"), alarm (red, "! fault", "! low reads"), disabled (hatched, "▨
  disabled"), stale (dashed, greyed, "◌ stale" / "◌ no value", last value kept);
- levels filling and wrapping, the six markers moving round the loop along the path (their
  transforms read back changing), the value shown over the scanner;
- a selected object (by pointer) outlined in the accent, the side panel with its state, value,
  since when, series, rules and a 30-minute sparkline from portal's window; the attention list
  ordered alarm, warn, near, disabled, stale; the headline in the top bar coloured by state; the
  alarm strip of the latest changes; the layers toggling markers, states and labels; zoom and pan;
- the plant stopped: every object of its source stale within one health refresh, held stale while
  the source retried (this found the "waiting is also a reconnect" gap, C-050).
