# C-047 evidence - veredas-supervisao, the component

## The design (2026-11-09)

The plan (`docs/supervisao-plan.md`) came first (0181602), with the operator's four answers of the
day recorded as `docs/questions.md` Q18 to Q21: Veredas 1's export parsing not carried at all;
supervisão starts the portal sessions in its own process; local, no accounts; 3D later.

A library and one executable, like portal: the host is a library type (`Host`), the executable
its shell. No build script and no embedding crate: the page is three files compiled in with
`include_str!` from a committed `web/dist/` whose names vite is told to keep fixed
(`assets/app.js`, `assets/app.css`). The page is TypeScript built by vite, as Veredas 1's was, so
the operator's stack stands; cargo and CI never run Node.

The drift Veredas 1 could not see (a `dist/` built from older sources) is closed by a hash: the
build writes `dist/source.hash`, FNV-1a 64 over every source of the page (`index.html`, the
package and lock files, the TypeScript and vite configuration, everything under `src/`), each as
its relative path, a NUL, its text with CRLF read as LF, a NUL, in path order; the component test
recomputes it in Rust from the tree. `core.autocrlf=true` checks the sources out CRLF on Windows
and LF on Linux, so the line endings are normalised on both sides.

Its own dependencies are core, portal and the server's crates; the plant's stack (the OPC client,
the database engine, a socket or HTTP client crate) is portal's, reached through portal's library,
so the test asserts the crate's own normal dependencies by name and not the transitive graph,
which carries the engine through portal by design (Q19).

The vendor scan reads every file git holds or could hold under the crate (asked of git, as law L1
reads the tree), not the disk: `web/node_modules/` is ignored by the repository and holds tens of
thousands of files no commit carries, while the built bundle is committed and is read. The names
are portal's (the protocol core's telegram layer came from) and the export, table, plant and
station names of Veredas 1's supervision app, from the survey of its code for this plan. One name
of Veredas 1's tag families was dropped from the list on its first run: flattened to letters it is
the word "sorter" followed by "state", which this plant's own code says (`["sorter"]["state"]`).

## Refute round 1 (2026-11-10, at df948a4): refuted, six gaps in what the test could catch

The critic rebuilt the page on a clean CRLF checkout and got the committed stamp and byte-equal
files, so the tree was right; the test was not strict enough. Each gap was shown by a mutation that
left the component test green: a failed build (an unresolvable import) rewrote `source.hash` beside
the old page, because the stamp was written in `closeBundle`, which runs on failure too; a hand
edit of `dist/assets/app.js`; a file the build reads that the hash did not cover (`web/shared.ts`
imported from `src/`, a `web/.env`), shown by two builds with one stamp and two bundles; a dynamic
import that emitted `assets/app-lazy.js`, which the host answers 404; the accented customer term
written without its accent or decomposed; and a vendor name in a file's name.

The answers. The build writes its hashes in `writeBundle`, after the bundle is on disk, and adds
`dist/output.hash` over the three files as written; the test recomputes it from the page compiled
in. `vite.config.ts` turns off `.env` loading, the `public/` folder and the PostCSS search, refuses
in `generateBundle` (after vite's own plugins) any module outside `src/`, `index.html` and
`node_modules/` and any bundle that is not exactly the three files; both refusals were run once,
on `web/shared.ts` imported from `src/main.ts` ("the page reads .../web/shared.ts, outside src/,
index.html and node_modules/") and on a dynamic `import("./lazy")` ("the page must build into
assets/app.css, assets/app.js, index.html alone, not assets/app-lazy.js, ..."). The test holds
every file under the crate to Cargo.toml, Rust under `src/` or `tests/`, a hashed source or the
page, `web/dist/` to exactly the three files and the two hashes, and pins the guards in the config.
The reader folds Latin-1 accents to their base letters and drops combining marks, the term is kept
in ASCII, and every file's path is read as well. Run against the gaps: a byte appended to `app.js`
(red: edited after its build), an untracked `web/shared.ts` (red: a file outside the crate's code,
the hashed sources and the page) and a `tests/data/<vendor>-export.txt` (red twice: the stray file
and the name in its path). The rebuild with the guards gave the same `app.js`, `app.css` and
`index.html`; the source hash moved with the config (`a0388a6caeb11dc3`), the page's is
`e62b08b835cafae8`.
