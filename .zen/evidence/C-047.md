# C-047 evidence - veredas-supervisao, the component

## The design (2026-11-09)

The plan (`docs/supervisao-plan.md`) came first (0181602), with the operator's four answers of the
day recorded as `docs/questions.md` Q18 to Q21: Veredas 1's export parsing not carried at all;
supervisão starts the portal sessions in its own process; local, no accounts; 3D later.

A library and one executable, like portal: the host is a library type (`Host`), the executable
its shell. No build script and no embedding crate: the page is three files compiled in with
`include_str!` from a committed `web/dist/` whose names vite is told to keep fixed
(`assets/app.js`, `assets/app.css`). The page is TypeScript built by vite, as Veredas 1's was, so
the operator's stack stands; cargo and CI never run Node.

The drift Veredas 1 could not see (a `dist/` built from older sources) is closed by a hash: the
build writes `dist/source.hash`, FNV-1a 64 over every source of the page (`index.html`, the
package and lock files, the TypeScript and vite configuration, everything under `src/`), each as
its relative path, a NUL, its text with CRLF read as LF, a NUL, in path order; the component test
recomputes it in Rust from the tree. `core.autocrlf=true` checks the sources out CRLF on Windows
and LF on Linux, so the line endings are normalised on both sides.

Its own dependencies are core, portal and the server's crates; the plant's stack (the OPC client,
the database engine, a socket or HTTP client crate) is portal's, reached through portal's library,
so the test asserts the crate's own normal dependencies by name and not the transitive graph,
which carries the engine through portal by design (Q19).

The vendor scan reads every file git holds or could hold under the crate (asked of git, as law L1
reads the tree), not the disk: `web/node_modules/` is ignored by the repository and holds tens of
thousands of files no commit carries, while the built bundle is committed and is read. The names
are portal's (the protocol core's telegram layer came from) and the export, table, plant and
station names of Veredas 1's supervision app, from the survey of its code for this plan. One name
of Veredas 1's tag families was dropped from the list on its first run: flattened to letters it is
the word "sorter" followed by "state", which this plant's own code says (`["sorter"]["state"]`).

## Refute round 1 (2026-11-10, at df948a4): refuted, six gaps in what the test could catch

The critic rebuilt the page on a clean CRLF checkout and got the committed stamp and byte-equal
files, so the tree was right; the test was not strict enough. Each gap was shown by a mutation that
left the component test green: a failed build (an unresolvable import) rewrote `source.hash` beside
the old page, because the stamp was written in `closeBundle`, which runs on failure too; a hand
edit of `dist/assets/app.js`; a file the build reads that the hash did not cover (`web/shared.ts`
imported from `src/`, a `web/.env`), shown by two builds with one stamp and two bundles; a dynamic
import that emitted `assets/app-lazy.js`, which the host answers 404; the accented customer term
written without its accent or decomposed; and a vendor name in a file's name.

The answers. The build writes its hashes in `writeBundle`, after the bundle is on disk, and adds
`dist/output.hash` over the three files as written; the test recomputes it from the page compiled
in. `vite.config.ts` turns off `.env` loading, the `public/` folder and the PostCSS search, refuses
in `generateBundle` (after vite's own plugins) any module outside `src/`, `index.html` and
`node_modules/` and any bundle that is not exactly the three files; both refusals were run once,
on `web/shared.ts` imported from `src/main.ts` ("the page reads .../web/shared.ts, outside src/,
index.html and node_modules/") and on a dynamic `import("./lazy")` ("the page must build into
assets/app.css, assets/app.js, index.html alone, not assets/app-lazy.js, ..."). The test holds
every file under the crate to Cargo.toml, Rust under `src/` or `tests/`, a hashed source or the
page, `web/dist/` to exactly the three files and the two hashes, and pins the guards in the config.
The reader folds Latin-1 accents to their base letters and drops combining marks, the term is kept
in ASCII, and every file's path is read as well. Run against the gaps: a byte appended to `app.js`
(red: edited after its build), an untracked `web/shared.ts` (red: a file outside the crate's code,
the hashed sources and the page) and a `tests/data/<vendor>-export.txt` (red twice: the stray file
and the name in its path). The rebuild with the guards gave the same `app.js`, `app.css` and
`index.html`; the source hash moved with the config (`a0388a6caeb11dc3`), the page's is
`e62b08b835cafae8`.

## Refute round 2 (2026-11-10, at 1a12932): refuted, five gaps

The critic built the page each time and kept the component test green through five routes. The
build read files from outside the crate that neither the hash nor the guard saw: a stylesheet's
`@import` (vite records it as a watched file, not a module), a `url()` asset (inlined under 4 KB),
and a `tsconfig.json` `extends`. A byte change in a source that is not UTF-8 left the source hash
unchanged (it was read lossily). The name reader missed a ligature, full-width capitals, an HTML
entity, a macron and a Windows-1252 file. The guards were pinned as text, so `this.error` turned to
`this.warn` and the source stamp moved to `buildEnd` (round 1's first gap again) both passed. And
the page could load files other than its three (a CDN script and stylesheet, a CSS `@import url`).

The answers. The build judges what vite watches as well as its modules (the hashed files at the web
root allowed, everything else outside `src/` and `node_modules/` refused) and inlines no asset, so
a `url()` asset is a fourth file and refused. Both hashes are over bytes, CR LF read as LF, in Rust
and in the build alike (the page's stamps are unchanged). The test holds `vite.config.ts` word for
word, refuses an `extends` in the TypeScript config and an `@import` or an outside `url()` in a
source stylesheet, reads every judged file as UTF-8 (refusing one that is not), folds ligatures,
full-width forms, Latin Extended-A and HTML entities before matching, and reads the page's every
`src`, `href`, `url()` and address. Run against the routes: the outside `@import` and the outside
`url()` refused by the build ("the page reads .../docs/probe-outside.css" and ".../probe-mark.svg"),
a CDN script in `index.html` red in the test.

Not claimed: a hand-edited stamp beside a hand-edited page passes, since CI never runs Node.

## Refute round 3 (2026-11-10, at 7b13d4b): refuted, four gaps and a record too narrow

The critic rebuilt the page under each route and kept the component test green four times. A
TypeScript config under `web/src/` (the build reads the nearest one for each file) extended a file
outside the crate: two builds with one source hash and two bundles, round 2's `extends` route
reopened one folder down. A file git ignores under `web/src/` (a `target/` folder there) was hashed
by the build and by the test, yet listed by git nowhere, so no checkout would carry it. A name
written with a Rust escape (`\u{e3}` for the accent) and a section sign written as an entity
(`&sect;`, `&#167;`) passed the reader, which decoded entities for names only and read the section
sign from the raw line. And the recorded run was the component test alone, while the clause names
the laws on the real tree.

The answers. Every source under `web/src/` is TypeScript or a stylesheet; every hashed source is one
git holds or could hold; the TypeScript config names its compiler options and `src` alone (no
`extends`, `references` or `files`). The reader reads each line twice, its entities decoded and then
its code escapes too (the braced `\u{..}` of Rust and a script, a script's `\u....` and `\x..`, a
stylesheet's hex and its ending space), a name or a section sign in either reading a hit; the plain
reading keeps the letters an escape-like run would swallow (a pattern's `\b` before hex letters,
pinned by a sample). `&sect;` reads as the sign. C-047 is recorded with
`cargo test -p veredas-supervisao -p leis --test component --test real_tree`. The five routes
replayed against the answer, the page rebuilt where the stamp had to match: each refused by its own
assertion ("neither TypeScript nor a stylesheet", "a hashed source git ignores", the config's keys,
the escaped name, the entity's section sign).

Also from the round, outside the gaps: a fresh Windows checkout gives the page's sources CR LF, and
vite keeps one CR of the source in `index.html`, so a rebuild there wrote another page (output hash
730ae080b5b03bf1 against the committed 8bbe95cb535d87cc). `.gitattributes` now checks the page's
folder out with LF on every machine; a fresh checkout under it rebuilt the committed page byte for
byte (8bbe95cb535d87cc).

## Refute round 4 (2026-11-11, at f6e3a19): refuted, three gaps

The critic kept the component test green three ways. The page's references were read only as
double-quoted `src="` and `href="`: an unquoted `href=`, a single-quoted `src='` and a `srcset` in
`index.html`, and a stylesheet's `image-set("...")`, each loaded a file from another host. The name
reader missed Rust's `_` inside a braced escape (`\u{e_3}`), TOML's eight-digit `\U` escape, entity
names for a ligature and a stroke (`&filig;`, `&lstrok;`), and a legacy entity without its `;`, which
a browser and vite both read. And two inputs outside the hashed set reached the bundle with one
source hash: a package under `node_modules/` (ignored by git, allowed by the build's guard) and a
`VITE_*` variable of the process, read through `import.meta.env` (three builds, one source hash,
three pages).

The answers. The test holds the built `index.html` word for word, as it holds `vite.config.ts`; a
source stylesheet or the source page names no address, and `url()` and `image-set()` strings alike
point at nothing but a fragment or a data URI, in the sources and in the built stylesheet. The
build's guard refuses any module or watched file outside `src/` and the hashed files,
`node_modules/` included (the page imports no package; the rebuild under it wrote the same page,
only `source.hash` moved). No source under `web/src/` reads `import.meta` or `process.env`. The
reader reads Rust's `_` in a braced escape, TOML's `\U`, the entity names of the Latin letters with
their marks, strokes and ligatures (and `&eth;`, `&thorn;`, `&eng;` and the like), and a number or a
Latin-1 name without its `;`; a sample pins each. The nine routes replayed against the answer, the
page rebuilt where its stamp had to match: the outside attributes refused ("index.html names an
address"), the `image-set` ("points outside the page"), the four spellings each named by the
reader, the legacy entity by the reader and by the page held word for word, the package by the
build ("the page reads .../node_modules/probe-r4/index.js, outside src/ and the hashed files"), the
environment ("reads the build's environment").

Not claimed: spellings built to evade the reader (mathematical letters, Greek or Cyrillic
look-alikes, entity names beyond the Latin letters). The reader guards against naming by accident,
in every spelling a person, an editor, a converter or a build tool writes; the clause lists them.

## Refute round 5 (2026-11-11, at d5f4c6f): refuted, two gaps and a limit

The build's environment still reached the page through the source `index.html`: vite moves an
inline module script into the bundle and fills it from the environment before writing the built page,
which came out byte for byte as committed, so two builds (`VITE_PROBE` A and B) gave one source hash,
two bundles, both green. And the reader missed a separator written otherwise: `%20` read as `20`,
`&nbsp;` as `nbsp`, a `\n` escape as `n`, so a name of two words stayed hidden in a URL, an editor's
export or a two-line label.

The answers. The test holds the source page word for word too (no inline script, no `%NAME%`
placeholder). The second reading reads a `\n`, `\r` or `\t` escape as a space, any entity naming no
letter as a space, and percent-encoded bytes as UTF-8 (`%C3%A3` an accent); the plain reading keeps
its letters as written, so nothing it saw before goes unseen. A sample pins each spelling. The four
routes replayed: the inline script refused ("web/index.html is not the page this test holds"), the
three split names each named by the reader.

A limit, now stated in the clause: the page is the page written as built by the toolchain
`package-lock.json` names. The installed toolchain (vite, esbuild, rollup under `node_modules/`, the
Node version) is in neither hash; a hand-patched install would build another page under the same
source hash, and CI, which never runs Node, cannot see it.

## Refute round 6 (2026-11-11, at a76f425): refuted, two gaps

A CSS module read a file outside the hashed set: a `.module.css` whose `composes ... from` named a
stylesheet outside the crate built without a refusal (vite records the composed file neither as a

The answers. The build reads no CSS module (`css.modules: false`, the guard's list and the test's

the test refuses a source stylesheet named `.module.` or holding `composes` or `@value`. The second
reading reads every markup tag as a space (the first keeps every letter as written); a sample pins
each spelling. Replayed: the critic's CSS module refused by the build; a `composes` line in the
plain stylesheet, built, refused by the test ("src/style.css is a CSS module"); the four markup
spellings each named by the reader.
