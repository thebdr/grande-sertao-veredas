# C-155: an interpreted program on the engine of a scan

## What it is, 2026-11-25
The second step of `docs/orcl/interpreter.md` ("Built in this order"): `orcl_runtime::Interpreted<I, O>`, a
`TaskProgram` (C-151) over a machine of `orcl-interp` (C-153). It lives in the engine, which now depends on the
interpreter, because the interpreter's own claim is that it depends on nothing, and controlador's programs run
interpreted: the engine without it would be the conformance suite's only.

Its design (the interpreter's design, "Running"):
- four regions, laid out at load: the program's state, the scan, the inputs and the outputs, and a scan entry
  taking a reference to each, `fn scan(&mut self, scan: &Scan, inputs: &I, outputs: &mut O)` as the front end will
  lower it;
- the inputs and outputs are the native program's own `Copy + Default` types, each with an `Image` that writes it
  to and reads it from slots, so the engine's `Io` and the task's process image are unchanged and a native program
  and its interpreted twin run on the same plant: the conformance suite's comparison;
- each scan writes the scan, the inputs and the output image the task holds into their regions, so the outputs
  region holds exactly what the task hands the program, whatever came before; calls the entry to its return; and
  reads the outputs back. Its slots go through a vector reserved when it is made, so nothing is allocated;
- the first state and the safe outputs are handed in when it is made (Q231, taken meanwhile: the front end would
  compute them); nothing of the program runs once it has faulted.

How the tests stand against the clause (`tests/interpreted.rs`): a program lowered by hand as rustc's MIR has it at
opt-level 0, and its native twin, run on two tasks for 2000 scans each on a plant whose reads take up to 20 ms, are
equal scan for scan, in every write and in the statistics; the scan's time, its cycle and the output image reach the
program; a division by zero faults the task by `ScanError::Program`, naming the instruction, with the machine
standing there; an image the machine refuses and outputs that read back as none fault the task by their names;
every refusal when it is made is met by its name; and a thousand scans and a fault, under a counting allocator,
ask nothing of the heap.

Open: a scan that never returns is the host's watchdog's to catch, as a native one's is; an instruction budget per
scan would let the engine stop it itself.

## The implications check (2026-11-25)
The zen-implications check confronted C-155 with C-151, C-153 and C-154. It is a near-duplicate of none: it runs under
C-151's cycle and fault rule unchanged, loads and calls C-153's machine without restating it, and takes a `Program`
in memory where C-154's reader checks a file before any `Program` exists; the clause now carries that sentence. Its
dependency on C-154 runs through the host: format 1 leaves finding the entry to the host, and holds no first state
and no safe outputs, so a controller cannot make an `Interpreted` from a file alone until Q231 is answered (Q231 now
names the format version each answer needs). The clause now also states its limits: the twin agrees while neither
faults; there is no instruction budget (Q232, new); and of a `ScanError`, `Program` is the program's own error (502
once the controller runs interpreted programs) while `Host` and `Outputs` are the adapter's or the host's (507).

`single_element_loop` alone, whose clippy-clean form passed) and passed 15. Two of those 15 are equivalent: the room reserved when the adapter is made, which the make's own writes reach anyway, and a

  the default back, passed. An outputs' default that writes a wrong image was then accepted and faulted the first

  short with its outputs half written and no fault. A loop of half a million instructions now runs to its return;
- **low**: the output image written before each call, which through a task changes nothing, since the region already

- the clause said inputs whose default reads back as none were refused, but the adapter never reads inputs back,
  since a scan never does: the clause now says the inputs' default must be a value of their type, as the code checks.

## Q230's change (2026-11-26): the stack handed in
`Interpreted::new` takes the stack's size in slots after the safe outputs and loads the machine on it (Q230: the
target's settings give it, the host handing it in meanwhile). An entry whose frame the stack cannot hold is refused
when the adapter is made, by the check it already ran (the entry started and aborted): `MakeError::Entry(HostError::
Stack)`. Q231 is ruled as taken (the front end computes the first state and the safe outputs), so its note no longer
says pending. New test: the scan entry's frame counted from its locals, made and run on exactly that stack, refused
on one slot less and on none. The sixth round's kept kill-tests are adopted. The clause returns to pending for its
refute round.
