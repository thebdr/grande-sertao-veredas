# C-155: an interpreted program on the engine of a scan

## What it is, 2026-11-25
The second step of `docs/orcl/interpreter.md` ("Built in this order"): `orcl_runtime::Interpreted<I, O>`, a
`TaskProgram` (C-151) over a machine of `orcl-interp` (C-153). It lives in the engine, which now depends on the
interpreter, because the interpreter's own claim is that it depends on nothing, and controlador's programs run
interpreted: the engine without it would be the conformance suite's only.

Its design (the interpreter's design, "Running"):
- four regions, laid out at load: the program's state, the scan, the inputs and the outputs, and a scan entry
  taking a reference to each, `fn scan(&mut self, scan: &Scan, inputs: &I, outputs: &mut O)` as the front end will
  lower it;
- the inputs and outputs are the native program's own `Copy + Default` types, each with an `Image` that writes it
  to and reads it from slots, so the engine's `Io` and the task's process image are unchanged and a native program
  and its interpreted twin run on the same plant: the conformance suite's comparison;
- each scan writes the scan, the inputs and the output image the task holds into their regions, so the outputs
  region holds exactly what the task hands the program, whatever came before; calls the entry to its return; and
  reads the outputs back. Its slots go through a vector reserved when it is made, so nothing is allocated;
- the first state and the safe outputs are handed in when it is made (Q231, taken meanwhile: the front end would
  compute them); nothing of the program runs once it has faulted.

How the tests stand against the clause (`tests/interpreted.rs`): a program lowered by hand as rustc's MIR has it at
opt-level 0, and its native twin, run on two tasks for 2000 scans each on a plant whose reads take up to 20 ms, are
equal scan for scan, in every write and in the statistics; the scan's time, its cycle and the output image reach the
program; a division by zero faults the task by `ScanError::Program`, naming the instruction, with the machine
standing there; an image the machine refuses and outputs that read back as none fault the task by their names;
every refusal when it is made is met by its name; and a thousand scans and a fault, under a counting allocator,
ask nothing of the heap.

Open: a scan that never returns is the host's watchdog's to catch, as a native one's is; an instruction budget per
scan would let the engine stop it itself.
