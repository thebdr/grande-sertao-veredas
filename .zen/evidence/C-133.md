# C-133 evidence - LLDP

## The port (2026-11-22)

From Veredas 1's `lldp.rs`. Read against Wireshark's LLDP dissector (tshark 4.6.6); what it settled:
- **The MRP port status TLV carries MRRT's port status** (tshark: "MRRT PortStatus", values OFF,
  MRRT_CONFIGURED, MRRT_UP), not whether a ring port is up. Veredas 1 named the values "off",
  "ring-port-up", "ring-port-down", and its topology took status 0 as "not in a ring". The codec
  names them `mrrt` and off, configured, up; the ring is the topology's business (phase 6) and is
  to be read from the domain, not this word.
- the measured delays are port rx local and remote, port tx local and remote, and the cable delay
  local, in that order (named so now; Veredas 1 kept an array of five).

Also changed:
- every TLV not read is kept with its bytes (`unknown`, `unknown_org`), where Veredas 1 kept a type
  and a length only, so nothing heard is lost and a PDU writes back to itself;
- a TLV that repeats one already read (a second chassis id, a second system name, a second chassis
  MAC) is kept unread; Veredas 1 let the last overwrite the first, unseen;
- text that is not UTF-8 is kept as bytes (an id under its subtype, a text TLV unread); Veredas 1
  decoded it lossily;
- the management address keeps its OID; Veredas 1 ignored the OID and its length;
- the time to live is exactly two bytes and the capabilities exactly four;
- the encoder refuses a value past 511 bytes, a type past 127, a management address outside 1 to
  31 bytes and an OID past 255; Veredas 1 masked the length to nine bits and wrote every byte, a
  corrupt TLV, and its 128th type would have overflowed;
- the fixtures name no vendor or product.

Noise: twenty thousand seeded PDUs of plausible TLVs, each cut at every length; every decode that
succeeds writes back to itself exactly.

The "writes back to itself exactly" above overstated: a decoded PDU written again reads back the
same, its TLVs in the standard's order and those it kept after them, so its bytes may be reordered
(the critic of round 1 showed it).

## Refute round 1 (2026-11-22): refuted, six gaps

- **Ids the TLV cannot carry were written.** 802.1AB allows a chassis or port id of 1 to 255 bytes;
  a 256-byte id and an empty one were written, tshark warning and reading nothing after. The
  encoder now refuses them, texts past 255 too, and a management address not of its family's
  length; the decoder keeps such TLVs unread.
- **The dissector claim covered TLVs written back unread**, which tshark does not read (a reserved
  type ends its reading). The claim now covers the TLVs this codec reads.
- **An End TLV holding bytes lost them**, and a kept TLV of type 0 was written. The End is now kept
  as heard (`end`: empty, its bytes, or absent), type 0 refused among the kept.
- **A 1500-byte PDU with no End could not be framed again** (an End added two bytes): an absent End
  is now written absent.
- **"Writes back to itself" was proven structurally**: the clause now says "reads back the same".
- **The MRP domain was sixteen equal bytes**, blind to a byte-order slip: now sixteen distinct.

## Refute round 2 (2026-11-22): refuted, five gaps

- **"Every TLV kept" was proven structurally only**: twelve of fifteen mutants that drop or cut a TLV
  passed. The noise test now also holds every TLV heard to be written back the same bytes (sorted
  by type and value) and the End as it was, and each of the eight TLVs the codec reads has a repeat
  and a one-byte-short and one-byte-long case, besides a management address with a byte past its
  OID and a 7-byte MAC id.
- **Ids of the MAC and network-address kinds were written at any length**, and the dissector then
  read nothing after them. A MAC id is 6 bytes, a network-address id its family's length, refused
  on writing and kept unread on reading.
- **Text**: the dissector reads printable ASCII; it stops at a NUL and shows other UTF-8 as
  replacement characters. The codec writes what it is given; the clause now names the dissector's
  reading, pinned by a NUL and an accented case.
- **An absent End did not survive a frame under 60 bytes** (the pad reads as an End): said, and
  pinned.
- **The OID**: 802.1AB's management address TLV is at most 167 bytes, so an OID is at most 128:
  refused past it on writing, kept unread past it on reading.

## Refute round 3 (2026-11-22): refuted, the code holding, six gaps in what was pinned

- **The OID's value was never compared**: tshark reads it as a BER object identifier (`[2b 06 01]` as
  1.3.6.1; `[ff]` as 0, no complaint). The codec keeps the OID as bytes; the clause names the
  dissector's reading, pinned on both.
- **The bounds were pinned on the writing side only**: seven reading-side mutants survived. Every
  accepted bound is now written and read back the same, and a 256-byte port id and address strings
  of 1 and 33 bytes are read as none or kept unread.
- **The End**: the dissector calls an End holding bytes malformed and reads nothing past a TLV of a
  reserved type, so the clause names those readings and the test pins them.
- **Three id kinds were never read from their bytes** (network and interface-name chassis, alias
  port): read now, with their keys and short names.
- **The replacement characters were asserted loosely**: one U+FFFD per byte now.
- **A lone byte after the last TLV of a PDU with no End was dropped unseen**: kept as `trailing`
  and written back; trailing bytes the writer cannot place are refused.

## Refute round 4 (2026-11-22): refuted, the code holding, one framing defect and ten gaps

The critic fuzzed 180 000 PDUs (13 022 decoded): no panic, every decoded PDU written back and read
back the same with every TLV's bytes. The earlier rounds' attacks are caught. Found, and answered:
- **`frame` of a short PDU with no End wrote a frame the codec could not read back** (the one
  defect in the code): a trailing byte 0x0B joined the pad into a TLV header running past the
  frame (tshark: malformed), 0x0A invented an empty system name, and a 45-byte PDU's one-byte pad
  read as a trailing byte. `frame` now refuses a PDU with no End it would pad
  (`NoEndInPad`); at 46 bytes it needs no pad and the absence survives.
- **"One byte short and long kept unread" proved no length**: each off-size TLV followed a good one
  and was kept as a repeat; eight `== N` to `>= N` mutants passed it. Each TLV now stands alone at
  its size (read), one short and one long (kept unread), and the noise reaches organisation TLVs of
  23 data bytes.
- **No PDU had two good management addresses**; **the decoder's address bounds and a network id
  longer than its family were not pinned** (the bounds tests used family 1, whose length check
  answered first); **RT class 2's port status was dissected only at 0**; **control characters**
  were not pinned against tshark (it reads them as they are: the clause said "printable");
  **the short name's PROFINET guard and nine of eleven capability names** were untested; a count
  said "three bytes" of a one-byte IPv4 address; the End's malformed reading was asserted only as
  "some complaint". All now tested, the clause reworded where it claimed more.
Before this commit the critic's survivors and this round's points, 19 mutants, were run: all
killed.

## Refute round 5 (2026-11-22): refuted, the code holding, the order of the first three, five gaps

The critic fuzzed 150 000 structured PDUs (all decoded ones written back and read back equal, framed
and read back too) and sent every id form the tests never wrote through tshark, finding it reads
them with no complaint but one. Answered:
- **The decoder read the mandatory TLVs in any order**, where 802.1AB has a receiver discard a PDU
  whose first three TLVs are not the chassis id, the port id and the time to live in that order,
  and tshark reads none of it ("Invalid TLV type (0x02), expected ChassisID type (0x01)"): the
  codec "repaired" what a standard receiver drops. It now refuses such a PDU, naming the TLV out
  of place (`LldpError::Order`); a mandatory TLV present but unfit is still missing.
- **No test read a MAC or network id from bytes past ASCII**: four mutants reading them as text
  first passed. A MAC chassis and port id and IPv4 and IPv6 network ids are read now.
- **A port id of the network kind of an 802 family** is read by tshark as text after the family
  byte, warning of what follows a NUL: pinned, and named in the clause; IPv4 and IPv6 network ids,
  chassis and port, are read by tshark as addresses.
- **"For a reader to read as it read the original" claimed too much**: the kept TLVs are written
  organisation TLVs first, so a reader stopping at a malformed one reads less than it did. The
  clause now says what is written and in what order, and the order is pinned (a mutant writing the
  other kept TLVs first passed).
- **The short port name with a dotted station** (`port-001.io.cell-2`) is pinned (a mutant splitting
  at the last dot passed).
Before this commit, seven mutants of these points were run: all killed.
