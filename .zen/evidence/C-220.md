### Where the fork lives: the trap
The plan first put the fork inside the host's folder (`crates/veredas-abaco/ironcalc`, Q340 (a)),
excluded by the root manifest. The laws passed; the component test's membership check failed:
cargo listed `ironcalc` and `ironcalc_base` among `workspace_members`. Cargo's reading of
`exclude` lets a listed member's folder win over an exclusion beneath it (a member path that is a
prefix of the crate's makes it a member). The fork moved to `forks/ironcalc` before anything was
pushed (Q340, option (e) taken meanwhile); the component test now asks cargo itself.

The laws' gap it shows, reported to the orchestrator: L1 judges a crate excluded when an
`exclude` entry covers it, reading the manifest as written; cargo does not exclude a crate beneath
a listed member's folder. A suite with members `["crates/x"]` and exclude `["crates/x/y"]` passes
L1 while cargo makes `crates/x/y`'s crate a member when `crates/x` depends on it.

A fresh-context refuter planted changes in a scratch copy and found:
1. The member check read the prefix `veredas-` only: `orcl-std` added to the fork's `xlsx` reached
   Ábaco's graph and every test passed. Now the members are cargo's own package list
   (`metadata --no-deps`), tools and the language's crates included.
2. The plant stack was a prefix denylist: `inotify` and `http`, added to the fork, passed. Now the
   normal graph on every platform (`cargo tree --target all`) must be within a reviewed list of 85

3. The fork's provenance was not asserted: an unlisted engine change would pass. Now git's history
   is read: the commit that added `forks/ironcalc/base/Cargo.toml` (found by what it added, so a
   rebase does not break it) holds upstream's two trees, the commits touching `base` and `xlsx`
   since are as many as the record's rows, and the working tree changes neither.
4. The fork's suite count was a floor (`>= 3235`) with ignored tests uncounted. Now exactly 3 236
   passed, 0 failed, 8 ignored (upstream's), 0 filtered, and the changes' test files ran.

And one the refuter left as true-as-written: the fork's suite ran on the fork's lock (zip 9.0.5,

of the engine, has no counterpart), and the test now requires every registry crate of Ábaco's graph
at the version the fork's lock holds. The fork's suite passes on it.
