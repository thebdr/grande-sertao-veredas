### Where the fork lives: the trap
The plan first put the fork inside the host's folder (`crates/veredas-abaco/ironcalc`, Q340 (a)),
excluded by the root manifest. The laws passed; the component test's membership check failed:
cargo listed `ironcalc` and `ironcalc_base` among `workspace_members`. Cargo's reading of
`exclude` lets a listed member's folder win over an exclusion beneath it (a member path that is a
prefix of the crate's makes it a member). The fork moved to `forks/ironcalc` before anything was
pushed (Q340, option (e) taken meanwhile); the component test now asks cargo itself.

`exclude` entry covers it, reading the manifest as written; cargo does not exclude a crate beneath
a listed member's folder. A suite with members `["crates/x"]` and exclude `["crates/x/y"]` passes
L1 while cargo makes `crates/x/y`'s crate a member when `crates/x` depends on it.
