# C-042 evidence - the engine pinned

## The design (2026-11-07)

Veredas 1's `veredas-store/tests/capabilities.rs`, as it was, plus the engine's version text,
for the same reason core pins the OPC stack (C-023): the store's assumptions about the engine
are listed where a bump will break them by name. Each probe is one assumption: the appender
and the cloned connection (the ingest and query split), the wire types of a sequence and a
timestamp, the nearest-in-time join, the time bucket, `DESCRIBE` as validation, the catalog
functions, the memory figure, the snapshot by `COPY FROM DATABASE`, the file-backed limits, the
shared connection, and the live CSV view.

The bundled engine compiles once per target directory (about six minutes here; the profile
override keeps its library optimised and without debug info, or every test binary that links it
maps a 2.2 GB library, which Veredas 1 found exhausts the page file). The light build
(`--no-default-features`) does not carry it, as C-034's graph walk proves.

## Refute round 1 (2026-11-09): refuted, three pins weaker than the clause and the read side unpinned

Three pins asserted less than the clause said: `DESCRIBE` was shown "without running the query"
over an empty table, which an engine that ran the query would also pass (now a cast that fails
on the row the table holds describes while the same select run errors, and the binder's exact
words); the temp directory was set and never read back and the memory limit checked by a
substring where the store reads the exact text (now both exact); the widened CSV view was shown
through `DESCRIBE` alone, not in its rows (now the row). And the store relies on read-side
behaviour no pin named, so a bump would fail a store test or change results in silence: the
value variants the cells and the listing match on (a date, a time, a decimal, an interval, a huge
integer, a timestamp), the listing's aggregate over a union skipping null cells and typing the
last value, the positional tie-break sorting nulls last under `DESC`, an empty table copied to a
header alone, `EXPORT DATABASE` with its views in the schema and its sanitised file names, the
CSV reader's options (a decimal comma typed, a ragged file padded), the sniffer's outcomes on a
marked, a header-only, an empty and a missing file, and a copy into a foreign database refused
by the engine and detached after. Eight pins added, one per assumption; the clause names them.
Noted for C-041, outside this clause: a ragged file the engine does not collapse to one column
(`a;b;c` with a short row and a long one) is sniffed to the widest row and the others dropped in
silence; the store's recovery covers the collapsed case alone, as its clause says.

## Refute round 2 (2026-11-09): refuted, two pins incomplete

The listing-aggregate pin's only null-valued row had a null key too, so its distinct count came
out the same with or without the filter the store relies on: a pin that proved nothing of the
filter. A new pin holds a keyed row with a null value and shows the filtered count 2 against the
plain count 3. The padding pin covered a short row alone; the engine meets a long row two ways: a
long row inside the sniff sample widens the schema by a numbered column and keeps every row, a
long row past the sample refuses the whole read with the line named. A new pin holds both, and
the clause says so. Held by the critic: every other new pin exact and engine-specific (the
positional order would differ under nulls-first, the export names deterministic and in name
order, the decimal's scale the engine's, the foreign copy's text), the three round-1 fixes.
Noted for C-041, outside this clause and its rounds: charting a text column that holds no number
or a time column meets the engine's cast error (the clause claims a numeric column alone; a time
charted as its epoch milliseconds, as the narrow surface reads it, is a decision worth taking);
and a live CSV view over a ragged file the engine does not collapse loses rows in silence, or
refuses the read past the sample, against the plan's "read live". Both in the hand-over for the
owner.
