# C-042 evidence - the engine pinned

## The design (2026-11-07)

Veredas 1's `veredas-store/tests/capabilities.rs`, as it was, plus the engine's version text,
for the same reason core pins the OPC stack (C-023): the store's assumptions about the engine
are listed where a bump will break them by name. Each probe is one assumption: the appender
and the cloned connection (the ingest and query split), the wire types of a sequence and a
timestamp, the nearest-in-time join, the time bucket, `DESCRIBE` as validation, the catalog
functions, the memory figure, the snapshot by `COPY FROM DATABASE`, the file-backed limits, the
shared connection, and the live CSV view.

The bundled engine compiles once per target directory (about six minutes here; the profile
override keeps its library optimised and without debug info, or every test binary that links it
maps a 2.2 GB library, which Veredas 1 found exhausts the page file). The light build
(`--no-default-features`) does not carry it, as C-034's graph walk proves.
