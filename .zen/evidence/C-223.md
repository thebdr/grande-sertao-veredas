# C-223 evidence - byte-faithful edits of a workbook Ábaco did not write

## The port (2026-11-22)

From Veredas 1's `crates/veredas-abaco/src/patch/` (`mod`, `package`, `sheet`, `refs`, `cached`,
`styles`, `xml`), its `a1` and the model half of its `workbook` (here `book`), with their tests
(`tests/patch.rs`, `patch_untouched.rs`, `patch_no_styles.rs` and the `no-styles.xlsx` fixture,
upstream IronCalc's `arithmetic.xlsx` without its styles part). Veredas 1 built it on the architect's
ruling AB9 (2026-11-04): a workbook Ábaco did not create is patched, never rewritten. There it was
proven against an older in-house tool's patcher and opened by a real Excel on two real systems with
no repair log; neither the workbooks nor Excel are on this machine.

Changed on the way:
- the model's workspace half (log, macros, preferences, history, the `.abaco` save) is left for
  phase 3; `Workbook::open` reads `.xlsx` and `.xlsm` and keeps the link log on the workbook;
- the source's "moved while patching" check compares the bytes read again with the bytes first read
  (Veredas 1 hashed them with SHA-256; no hash crate joins Ábaco's graph);
- the atomic write moved into `files`, shared by the patcher and `Workbook::export`;
- zip 9's entry names are fallible: an unnamed or undecodable entry is a refusal, not an empty name;
- the edits stay typed and JSON-valued as Veredas 1's tools sent them; an edit file comes with the
  command line, in stamped TOML, once core's header reader can be had without core's network layers
  (asked of core through the orchestrator);
- comments and test data that named the older tool, its files or a customer replaced (one custom
  property's value `PLANT-A`).

## The corpus test, and what it found (2026-11-22)

`tests/patch_corpus.rs` patches every workbook among the fork's test files, Excel's and the others',
twice: with nothing to do (every part must come out equal), and with the first plain number of the
first sheet that has one replaced (only worksheets may differ, and in them only that cell and
formula cells; the calculation chain at most dropped; the patcher's own verification on). It found
four defects of Veredas 1's patcher, each answered in `src/patch`:

1. `missing_r_on_row.xlsx`: a `<row>` without `r` (rows may leave it implicit) was always rewritten,
   so a sheet no edit touched came out with `r="1"` added. Now a row whose only change is that `r`
   gets it only when the part is rewritten anyway (a row inserted before it would shift what it
   implies); alone it is no reason to rewrite the part.
2. `example.xlsx`: a chart sheet (`chartsheet` relationship, no cells) made the patcher refuse the
   whole workbook, `no sheet named "Chart1"`. Sheet entries now carry their kind; only worksheets get
   a job or have their cells read; a chart sheet's part is copied as it is.
3. In the same file: a local defined name's `localSheetId` was written back from the engine's sheet
   order, which skips chart sheets, so a name scoped to a sheet after one would have pointed one
   sheet early. It is now the sheet's position among the file's `<sheet>` entries.
4. `DynamicArrays.xlsx`: `RANDARRAY` spills into cells that hold no formula of their own; the
   volatile measure (two evaluations compared) looked at formula cells only, so the patcher's
   verification failed on them. Spilled cells now count as computed; and since a random draw can
   repeat (one cell of a 0-to-100 array did, about one run in eleven), a cell whose own formula
   calls a volatile function, and every cell it spills into, is unstable by its text, the measure
   over three more evaluations covering what moves with them.

Result: nothing to do, 266 workbooks, every part equal; one number changed, 234 workbooks (32 hold
no plain number), every assertion holding.

`cargo nextest run -p veredas-abaco`: 79 tests, all passing (the crate's 30 unit tests among them).

Owed: Excel's acceptance of a patched file (Veredas 1's exit had it, on the Windows desk); the edit
file.

## Refute round 1 (2026-11-22 to 23): refuted, answered

A critic, given the clause and the code at `88c5432`, probed a scratch copy of the repository with
edits the tests did not make: every structural edit on every corpus workbook, hand-built packages
for the shapes the clause names. Six of its gaps were real; each is answered, and the test that
would have caught it is named.

1. **A self-closing `<definedNames/>` panicked the patcher** (Google Sheets and openpyxl write it:
   three corpus workbooks, on any row or column move or name edit). The element is now read as
   empty, kept as written when nothing joins it. `patch_corpus.rs`'s structural pass (below) runs
   every move and a name edit on every workbook and fails on a panic.
2. **A shared group was kept when only its children read across a move** (`=A10` shared down
   B1:B3, rows inserted at 11; and a summary column shared down over another sheet's rows). The
   group is now expanded when the move reaches the formula of any member as it derives from the
   master's. `patch_shapes.rs`: both cases, the rewritten children's formulas exact, read back.
3. **A column moved inside a table left the table inconsistent** (`ref` grown, its columns not).
   A move that cuts into a table, rows or columns inserted or deleted inside it, is now refused
   before anything is written; a table moved whole moves in the file and in the engine's model
   (fork change 18), so a formula an edit writes after the move reads the table where it is.
   `patch_shapes.rs`: four refusals and a whole move, `ref`, `autoFilter` and the written formula.
4. **A chart on a chart sheet was not re-spelled** (charts were reached through worksheets'
   drawings only). A chart sheet's drawing and its charts are now walked as a worksheet's; the
   chart sheet's own part stays as it is. `patch_shapes.rs`: a chart sheet reading a worksheet,
   rows inserted, the new `<c:f>`, the chart sheet and its drawing byte for byte.
5. **Verification ran after the rename, and failed on deletes over the corpus** (49 workbooks of
   266 with a row deleted, 51 with a column deleted): the destination was already replaced, an
   in-place patch's source overwritten. The new file is now written beside the destination under
   its own name, verified there, the source compared, and only then renamed (`commit`, its unit
   test: a failed check and a moved source leave the destination as it was, nothing left beside
   it). The failures themselves were the engine's, each now a fork change: a range a deletion cuts
   into shrinks as in Excel (17; the engine wrote `A1:#REF!`), an external reference keeps its
   address when its cell moves (19), a moved formula keeps its kind (20). And the patcher's own:
   the cells an array spilled into kept their values when the anchor was deleted, constants to
   Excel; a cell the engine computes without a formula of its own now follows its value as a
   formula's cache does, written as Excel writes a spilled cell (a text as `str`; an inline string
   there blocks the array, which the one-number pass caught on `SORT.xlsx`). `patch_shapes.rs`:
   `MMULT.xlsx` with its anchor row deleted, `link_test.xlsx` with rows inserted and deleted.
6. **A volatile function behind a defined name counted as moved** (`R` = `RAND()`, a cell `=R`).
   Volatility is now read from every formula's and every name's A1 spelling, by whole tokens
   outside string literals and quoted names: a call by name, a name reached through names. The
   old text test read the engine's R1C1 store, where `R[0]C[-2]` is a name `R`, and a substring
   `RAND` matched `GRANDTOTAL(`: a false positive kept a stale cache. `patch_shapes.rs` and the
   unit test of the token reading.

Claims it found untested, now tested: the refusal when the source changed (the `commit` unit
test), a chart sheet counted in `localSheetId` (`example.xlsx` and the hand-built chart sheet), a
clear, deleted columns, a deleted name, a local name set, `fullCalcOnLoad` (`patch.rs`), threaded
comments and drawing anchors on a package (`patch_shapes.rs`). The corpus's one-number check is
stricter: a changed cell other than the edited one must hold the same formula text and the engine
must give it another value (formulas and spilled cells alike).

Verification also compares a formula as the file spells it: the `@` the engine marks where Excel
implies one (an unknown name, a legacy formula) is no difference, an array formula against a plain
one is.

The structural pass (`structural_edits_are_verified_or_refused_and_a_refusal_writes_nothing`):
every workbook, rows and columns inserted and deleted at 2 / B, a global and a local name set,
each verified or refused with nothing written and nothing left beside the destination. 13
refusals, pinned with their reasons: the table workbook's four moves (cut into a table), the
pivot-table workbook's four, the engine's own and Excel's refusals (a column inserted with a cell
in the last column, an array cut in two, three), and `bad_merge_cells.xlsx`'s value hidden under
a merge, which the engine does not show and the patcher keeps as Excel would.
