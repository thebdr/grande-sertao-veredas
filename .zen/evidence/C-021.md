# C-021: The address-space browser: lab notebook

## The port (2026-11-06)

From Veredas 1's `crates/veredas-opc/src/browse.rs` with its inline tests and
`tests/browse_e2e.rs`. They are now `src/opc/browse.rs` and one file, `tests/opc_browse.rs`.

What changed:
- **Failures are `OpcError`, typed with the `Call` they came from.** Each displays Veredas 1's
  text. `result_refusal` takes the call and returns the error. The renderers are public, so the
  test file can reach them.
- **The connection is bounded by `CONNECT_TIMEOUT`.** The browser's thread watches a stop flag:
  dropping the browser abandons a connect, or a browse in progress, within tens of milliseconds.
  Veredas 1's drop sent a request and joined, so it waited out whatever was running, up to 64
  pages of 15 s each, or forever on a peer that accepts TCP and never speaks.
- **A thread that cannot be started is reported** (`OpcError::Thread`). Veredas 1 left a channel
  that never answered.
- **Duplicate children are dropped wherever they fall.** Veredas 1 sorted by display name, then
  dropped adjacent duplicates by node id, which missed a twin with another child between them.
- **The DataType read is chunked like a poll,** and filled in by position.
- **The value brief is one line and cut by characters.** Veredas 1 compared the byte length, so a
  short multi-byte text gained an `…` it did not need, and a newline broke the line.
- **Test names and comments name no vendor or product.**

New tests:
- the silent endpoint, at exactly the 10 s timeout;
- a drop mid-connect;
- a malformed id and a blank id, each followed by a good request;
- the bulk folder's ids in order, every one typed;
- the attribute rows pinned exactly;
- every renderer's text.
