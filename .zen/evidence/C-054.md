# C-054 evidence - writes, gated

## The design (2026-11-09)

Supervisão holds no write path: the binding declares an object's actions (an OPC tag by the node id
text portal's write surface names, and the value), and the page posts them to the session's own
portal route, `/s/<name>/portal/api/opc/write`, where portal's switch and whitelist answer. The
switch is the project's (`writes_armed`) or a shell's in process, never the wire's; the binding
check refuses at load an action on a tag no rule marks writable, so a write the page offers is one
portal would take. The page shows an action in the warn colour, disabled while the session's switch
is off, and asks before posting.

## Verified in the browser (2026-11-09)

Against the demo plant of C-051, writes off: Outlet 3 selected by pointer, its "Release full state"
shown gated and disabled, "Writes go through portal. Its write switch is off." Writes armed by the
project (supervisão restarted): the button enabled, "Its write switch is on."; pressed by pointer
(the browser's confirmation answered in script, the pane having no native dialog), the page read
back "Release full state: written (Good)", and the plant's reaction emptied the outlet (72 % to 0,
filling again from there, the sparkline showing the drop).

Screenshots: `.zen/evidence/supervisao/layout.jpg` (off: disabled) and `write-armed.jpg` (armed:
written, the outlet emptied; taken before the green accent).

## Refute round 3 (2026-11-10, at 105a374): refuted, two holes in the scan and one gap

Round 2's scan was a deny-list, and two routes passed it. Supervisão loads the project itself, and
portal's text loader is public: re-reading the file, turning `armed = false` into `armed = true`
and loading that (behind an environment variable, as round 2's mutant) started the session armed,
a post landing at the plant. And core, a direct dependency, has an ungated telegram link: a GET
route of supervisão's own could dial a device and send it a frame with the switch off, the 405
sweep's GETs carrying no query. The gap: the second action's button was never read with the switch
off (only Release was), so a page gating the first button alone stayed green.

The answers. The scan is now an allow-list: every path of core's and portal's that a source names,
its `use` trees written out, its inline paths, and the items it reaches through the one module it
imports whole (`project`), must be one of the twenty-three supervisão reads and serves with, each
seen at least once; nothing of theirs renamed (`as`) or taken whole (`*`); no socket type but
the host's one listener, no file written, no program run. The reader itself is checked on a sample
that names `project::load` and `telegram`. Both buttons are read disabled with the switch off at
start and after the disarm, and enabled while armed.

## Refute round 4 (2026-11-11, at deb39d5): refuted, one gap

Round 3 turned the reading of core's and portal's paths into an allow-list but left std's surface a
list of banned words, so "no file written, no program run" stayed open: `std::fs::File::options()`
gives an `OpenOptions` without naming it, `std::io::Write::write_all` was not banned, and through them
supervisão copied the project with its switch turned on and loaded the copy through the allowed
`project::load_file`, starting the session armed (a post of 7 then landed on the bench). A renamed
`Command` and a space around `::` passed the word list too.

The answer, in the test: std's and tokio's modules for files, programs, sockets and the process
(`fs`, `io`, `process`, `net`, `os`) are judged as core and portal are, against the same allow-list
(reading files, stdin, the one listener, an address, an error, the process's own exit), every
allowed path seen in today's sources; every `use` tree, inline path and item reached through a
module imported whole is read; nothing renamed; words are matched with no space around `::`. The
reader's self-check plants the escapes (`File::options`, `std::io::Write::write_all`, `use std::fs;`
then `fs::write`, a path spaced across lines, `Command as Run`) and finds each outside. The critic's
three escapes inserted into `config.rs` each turn the test red.

A limit, now stated in the clause: this is a reading of the sources over a closed set of paths, not a
proof in general; a dependency that writes on supervisão's behalf is kept out by C-047's exact list
of dependencies.

## Refute round 5 (2026-11-11, at 8d13c45): refuted, one gap with three escapes

The reading followed paths that start with the literal `std::` or `tokio::`, so three spellings
named a judged path it never read: `std` renamed (`use std as sd;` then `sd::fs::File::options()`),
a comment inside a path (`std::/**/fs::...`, the reading stopping at `/`), and a macro splicing the
rest (`std::$($r)*`). Through each, supervisão wrote a copy of the project with its switch on and
started the session armed (a post of 5 landed on the bench); the test stayed green.

The answer, in the test: a crate root the reading cannot follow is refused rather than passed over
(`std`, `tokio`, core or portal as a word, on code lines, not followed at once by `::` and a name or
a `{`), and the sources may hold no `macro_rules!` and no block comment (today they hold neither).
The reader's self-check plants the three escapes and finds each refused, a doc comment naming the
runtime passing. The critic's three escapes inserted into `config.rs` each turn the test red.

## Refute round 6 (2026-11-11, at 6c6fec9): refuted, two gaps

Two doors the reading never saw, neither naming a judged path. Foreign functions: an `unsafe extern
"C"` block declaring the C runtime's `system`, `fopen` and `fputs` (edition 2024's `safe fn`) ran a
program and wrote a copy of the project with its switch on, the session starting armed (a post of 5
landed). And portal's store, reached through the public `store` of the session's `Live`: its
`save_to` wrote a whole `.duckdb` snapshot (and `export_table_csv`, `export_all_csv` would write CSV),
method calls the reading of paths never meets.

The answers. Both crate roots forbid unsafe code, so the compiler refuses a foreign function, and the
test asserts the attribute on each and names no `unsafe` or `extern "` in the sources; the store's
methods that write a file or rows are refused by name (supervisão calls `query_rows` alone). The
critic's foreign block is refused by the compiler ("usage of an `unsafe extern` block"), the forbid
removed is caught, and the store's `save_to` is named. The root fix, a read-only view of the store
in portal's `Live`, would remove the door rather than watch it; it is portal's surface and not taken
here.
