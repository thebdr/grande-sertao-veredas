# C-135 evidence - the cyclic frame

## The codec (2026-11-22)

New in Veredas 2: Veredas 1's aranha had nothing of the cyclic exchange. Written for core's IO
controller and maquinar's PROFINET device (`docs/aranha-plan.md`, phase 3), to core's rules (no
member, no vendor, typed errors, total on input), checked against tshark 4.6.6's PN-RT dissector.

What the dissector settled while writing it:
- **The frame id ranges**: RT class 3 0x0100 to 0x0FFF; 0x1000 to 0x7FFF reserved; RT class 1
  0x8000 to 0xBFFF; "RTC1 (legacy)" 0xC000 to 0xFBFF; the alarms at 0xFC01 and 0xFE01.
- **"Ignore" is bit 7 of the data status**, not bit 6 as first written from memory; bits 3 and 6
  are reserved. The test that compares each named bit with the dissector's caught it.
- The dissector left the IO data of frame id 0xBBFF undecoded, saying so at warning severity; the
  dissected frames use ids it reads whole. (First written here as "when the data is not valid, and
  for ids at 0xBBxx": the second critic tried 0x8001 under seven statuses, invalid ones among them,
  and 0xBB00, 0xBB01 and 0xBC00, and only 0xBBFF warned. Corrected.) A real exchange is read by the dissector through the
  connection that set it up, which this frame alone does not carry.

## Refute round 1 (2026-11-22): refuted, four test gaps, the code right

- "Another tag" was never written (the fourth frame used the cyclic tag): priority 5, VLAN 100 now,
  to the byte, read back and dissected.
- The status byte's good and extension bits were pinned on two values: each bit alone now, and the
  reserved bits.
- The alarm ids were bounded on one side: 0xFC02, 0xFDFF, 0xFE00, 0xFE02 now.
- The dissector's data status bits were compared with literals over statuses that could not tell
  two swaps apart: six statuses that set each bit apart, each of the dissector's bits held to the
  codec's accessor.

## Refute round 2 (2026-11-22): refuted, the codec agreeing with the dissector everywhere

The critic held the codec to the dissector on all 65 536 frame ids (the cyclic set is exactly the
codec's) and on 20 000 differential frames (every APDU field and status bit equal). What the tests
let through, now pinned:
- **The Ethernet addresses' order was never checked**: `frame` writing them swapped passed. Every
  written frame's destination and source are asserted, by this codec and by tshark.
- **The status byte constants were checked by their good bit only**: 0x80 and 0x00 exactly now.
- **"The messages" covered one refusal**: both now.
- `FrameClass::Other`'s doc names the ids the dissector knows and this codec does not read as
  cyclic (the alarms with security, the remote service interface).
