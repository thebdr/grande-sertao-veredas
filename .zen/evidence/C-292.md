# C-292 — The tester machine — lab notebook

## The first machine (2026-11-22)

Release 2.0.0-alpha.1's OVA (1.09 GB) built in about 12 minutes of provisioning and proven by
`entrega prova`: the release's sums checked at boot, the plant live from the host, the offered
write refused, Chromium on the page (target/entrega/2.0.0-alpha.1/prova/proof-screen.png). Its
first recorded run of the test failed on the test's own listing (`root/root` where `--numeric-owner`
writes `0/0`); the second passed (about 50 minutes: a trial cut, the machine, the proof).

## Refute round 1 (2026-11-23)

Refuted, two findings and a minor one:
- The screen check counted colours (more than 200): with the browser painted flat white the real
  dump still showed 505, the wallpaper alone 217. A machine whose browser never opens the page
  passed.
- `entrega prova`, the proof the clause names, checked less than the test: no card line, and the
  OVA's descriptor and manifest never read, so an OVA VMware would refuse passed it, and the
  first release's machine (built before the card line) passed it too.
- The test wrote `vmx-{}` where the descriptor writes `vmx-{:02}` (only below version 10).

Answered: the proof polls screen dumps until the page's own canvas colour, read from the
release's page at its commit, covers 15 % of the screen (`share_of`, `page_canvas`); `ova_faults`
reads the OVA as VMware reads it, and `proof_faults` holds it, the card line and the page; the
test asserts the same and writes `vmx-{:02}`. Light tests in tests/prova.rs pin each case without
a machine. The first release's OVA, built before `--mode` and the card line, is built again.

## Refute round 2 (2026-11-23)

Refuted, three findings:
- The proof never read the disk: its format and its size were the descriptor's word alone, so an
  OVA holding a sparse VMDK, or a disk of another size, passed (the light test used a 6-byte file).
- The descriptor was checked by substrings: processors and memory swapped, or the hard disk under
  a controller that does not exist, passed the proof and the test alike.
- Without `xmllint` on the host a good OVA was refused as "not well-formed XML".

Answered: `qemu-img info` reads the disk (a stream-optimized VMDK of the stated capacity); the
descriptor is parsed with roxmltree and every value read inside its own element (the processors'
item, the memory's, the SCSI controller's and the disk's `Parent` that names it, the card, the disk
and file references), which also makes `xmllint` unneeded. Tests build OVAs on real empty disks
made by `qemu-img` and name each fault. The proof's PNG is now the rebuilt machine's dump (01:23).

## Refute round 3 (2026-11-23)

Refuted, one real gap and a narrow one:
- The descriptor was read by bare tag names anywhere in the document: the Envelope without its
  namespace or with another, RASD's or VSSD's namespace misspelled, or every Item moved out of
  VirtualHardwareSection all passed, though VMware reads by namespace and section and would see no
  hardware.
- `TAR_OPTIONS` in the shell (`--verbose`) changed `tar -tf`'s output and refused a good OVA; the
  machine test still ran `xmllint`.

Answered: `descriptor_faults` walks Envelope, References, DiskSection, VirtualSystem,
VirtualHardwareSection and its Items, every element checked for its namespace; the OVA's tar calls
run through `vm::run_clean`; the test reads the descriptor through the proof's own `ova_faults`.
Tests: five namespace and placement cases, each named.

## Passed on by C-291's ninth round (2026-11-23)

`maquina::from_release` built a machine from whatever bundle stood in `target/entrega/<release>/`,
and a cut refused after packing (its run together failed) leaves one there, its `release.toml`
already stating the suite and the run. Answered: `maquina::cut_finished` requires the release's
manifest where the cut writes it (`releases/<release>.toml`, or the trial's folder) and that it be
the bundle's own `release.toml` byte for byte; `tests/prova.rs` refuses a bundle without one and
one beside another cut's manifest (a trial's and a real cut's), each by its text, and lets the
cut's own on to the commit's recipe and guide; `tests/maquina.rs` cuts its trial where
`entrega cut --trial` writes it.

## A recorded run lost the boot's check on the console (2026-11-23)

The run recorded after the finished-cut answer (044c9a0, at e6b1df3) failed: the proof boot waited
300 s for `VEREDAS-SUMS-` and never saw it, though the console shows `veredas-verifica.service`
started and finished. Its output, `journal+console`, raced agetty's hang-up of ttyS0 (the plan's
trap): the service finished as `serial-getty@ttyS0` came up, and the lines were lost. Earlier proofs
won the race. Answered: the unit is ordered before `serial-getty@ttyS0.service` (and `getty@tty1`),
so the check is said before any login starts; the clause says so. The failed record was not kept.


## Refute round 4 (2026-11-23)

Refuted by gaps of proof; the 2.0.0-alpha.1 machine does what the clause says (its OVA's first
header `ustar\0 00`, openssh purged, networkd disabled, `/` trimmed, the sums before `login:`).
Words no test pinned, each mutant passing `tests/prova.rs`:
- the provisioning's promises the proof never saw: the SSH server removed, the executables on the
  PATH, cloud-init disabled, the identity blanked, the free space trimmed; and `machine.remove`
  defaulting to nothing, so a recipe without it loaded silently;
- `proof_faults` folding in the OVA's faults (`entrega prova`'s own verdict);
- the recipe read at the commit, not from the working tree;
- the base image refused off its pinned SHA-512;
- the boot check's ordering before the serial login;
- "as ustar" (a GNU-format archive lists the same);
- exotic: a real cut with `--out` elsewhere is refused by `entrega maquina` as unfinished.

Answered: the boot's check also says `VEREDAS-SSH absent`, `VEREDAS-CLOUD-INIT disabled` and
`VEREDAS-ON-PATH ok`, and the proof requires them with systemd's "Initializing machine ID from
random generator" (seen on the first release's proof console); the build requires the
provisioning's `/: ... trimmed on` line (`maquina::provision_faults`); `remove` is a key the recipe
states; `tests/prova.rs` names each missing state, an OVA fault carried into the proof, the
unfinished, failed and untrimmed provisioning, the script's purge, links, cloud-init switch, blanked
identity and trim and the unit's `Before=`, a recipe without `remove`, a base image off its digest
(`cache::base_image_in`, both digests named), a GNU-format OVA (its first header's magic read), and
the recipe read at the commit while the working tree's would not read. The `--out` case is stated
in the clause. The first release's machine predates the new lines: `entrega prova 2.0.0-alpha.1`
now names them missing; the next release's machine carries them.
