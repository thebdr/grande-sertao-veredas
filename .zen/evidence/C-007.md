## Refute round 1 (2026-11-05)

Refuted: `tests/foundation.rs` re-implemented cargo's target rules and missed two of them. With
`edition = "2021"`, `[lib] crate_type = ["rlib", "bin"]` (the underscore spelling cargo still
reads there) makes the library also a binary, and the check read only `crate-type`; and
`autolib = false` leaves no library at all while `src/lib.rs` still exists. The whole suite stayed
green on both, because the other test files still compiled. Also refuted: the clause named
`2.0.0-alpha.1`, which nothing checks (L3 checks SemVer from 2.0.0), and a version in a clause goes
stale at the first bump.

Changed: the test asks cargo (`cargo metadata --no-deps --offline`, which parses and builds
nothing) and requires exactly one library target with `lib`/`rlib` crate types, every other
target a test. The same check runs on planted packages outside the workspace, one per way to an
executable (`[[bin]]`, `[[example]]`, `src/main.rs`, `src/bin/`, `examples/`, `crate-type` and
edition 2021's `crate_type` naming `bin`, a `cdylib`, a bench, a build script, `autolib = false`),
each refused, and a plain library accepted. A package with `autolib = false` and no other target is
refused by cargo itself, so the planted one keeps a test. The clause states the rule as cargo reads
it and the version as L3 does.

Held: every TOML form of `[[bin]]`/`[[example]]`; `autobins`/`autoexamples` (they only switch
discovery off); Windows path spellings; an inner `#![crate_type]` (cargo passes `--crate-type`);
real_tree judging core (L1 membership, L2 name, L3 major, L4 every table, L6 the plan, which here
came a commit before the code).

## Refute round 2 (2026-11-05)

Refuted: the library test `all(lib | rlib)` was true of an empty list, and cargo accepts
`[lib] crate-type = []` without a warning (2021 and 2024), reporting the target as `([], [])`.
`cargo build` then refuses the package, but `cargo test --test foundation` skips the library it
cannot link and stays green: core with no library, the clause's command passing. Fixed: an empty
list is no library; a planted `crate-type = []` is refused.

Held: the package found by its canonical manifest path (a missing one panics, failing closed);
every kind but an exact `["test"]` is a breach (bin, example, bench, custom-build, cdylib, dylib,
staticlib, proc-macro); each planted case parsed by cargo and refused for its own feature; a
`[[test]]` with a crate type stays a test; `#![crate_type]` is overridden by cargo's
`--crate-type`; config-wide rustflags would turn every crate red; a `rustc-wrapper` is a toolchain
override, outside "cargo, asked what it would build".

## Refute round 3 (2026-11-05): holds

`cargo metadata` lists what cargo compiles: `proc-macro = true` beside `crate-type = ["rlib"]`
reports `["rlib"]` and builds one, beside `["bin"]` reports `["bin"]` (refused); both spellings
in edition 2021 report the hyphen's; `[lib] path = "src/main.rs"` with `autobins = false` is a
library. A lib reported `lib`/`rlib` is linked by the recorded command, so a missing or broken
library turns it red. Doctests, the lib's unit-test binary and `harness = false` tests are tests,
which the clause allows.

## The vendor check (2026-11-05)

After the operator's decision (`docs/questions.md` Q8) the clause claims core is content-agnostic;
`tests/foundation.rs` reads every source and test file for the vendor protocol's name and for
vendor-document citations (spelled in pieces so the check does not match itself), and checks the
reader on a planted sample. It cannot enumerate every vendor; it pins the one the telegram layer
came from.
