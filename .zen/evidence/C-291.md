## Refute round 1 (2026-11-22)

Refuted, four findings:
- The cut checked the manifest against the repository only, never against the releases already
  cut, and wrote it first: a cut of today's HEAD as 2.0.0-alpha.2 would have pinned six versions
  2.0.0-alpha.1 already names at other code, which `entrega check` refuses.
- The packed bytes depended on the umask (0002 and 0022 gave two archives, 41 entries apart).
- The clean-tree check ignored untracked files, while the suite runs in the tree.
- The recipe's library limits were any string; `v2.41` read as `[41]` and turned the guard off.

Answered: the manifest is planned before anything is built and checked then against the
repository and every release in `releases/` and where it writes (a release named in either refused
too); the builder's `rustc --version` must be the one the manifest states; packing reads every mode
as 0644 or 0755 (`bundle::pack`); untracked files count; the limits must be dotted digits. A bin
cargo does not build with the default features is now named and refused at the build (round 2 of
C-290 moved that judgement here). Each finding has a test in tests/bundle.rs, the one-tree refusal
in a throwaway repository, before any build.

## Refute round 2 (2026-11-23)

Refuted, five findings:
- The clean-tree check was a bare `git status --porcelain`: `status.showUntrackedFiles=no` hid an
  untracked file, and `--skip-worktree` or `--assume-unchanged` hid an edited one, so the suite
  could run on a tree the manifest's commit is not.
- The tree was checked once, before the suite; a commit or an edit made while it ran was tested
  and the manifest named the earlier commit.
- `--trial` without `--out` wrote its manifest into `releases/`.
- A setgid folder above the work folder made packed folders `drwxr-sr-x`, other bytes.
- The plant's copy changes supervisão's address too, not only ports (wording).

Answered: `cut::differs_from` judges the tree (HEAD, `status --untracked-files=all`, files git is
told not to look at), before the suite and again after it; a trial's manifest goes beside its
bundle and a trial writing into `releases/` is refused; packing clears setuid and setgid
(`ug-s`), the OVA's members likewise; the clause says what the copy changes. Tests pin each.

## Refute round 3 (2026-11-23)

Refuted, three findings:
- The clean-tree check left out ignored files, so a file hidden by a self-ignoring untracked
  `.gitignore` or by `.git/info/exclude` let the suite pass on a tree that is not HEAD's (a
  `build.rs` the commit lacks turned a red test green).
- `NEXTEST_PROFILE=no-browser` or `NEXTEST_RETRIES` in the caller's shell narrowed or softened "the
  whole suite", the manifest saying otherwise.
- `ls-tree` without `-z` quoted names with letters outside ASCII, and the bundle's docs left them
  out (none at d74be94).

Answered: every ignored path must be ignored by a `.gitignore` the commit tracks (`check-ignore -v`
names the rule), else refused by name; `cut::suite_command` runs the default profile with every
variable that steers cargo, rustc or nextest removed; the docs are listed with `-z`. Tests pin each.

## Refute round 4 (2026-11-23)

Refuted, one real gap and one narrow one:
- The toolchain was read by `rustc --version` in the caller's environment, while round three's
  answer ran the suite with `RUSTUP_TOOLCHAIN` removed: under `cargo +other` the manifest would name,
  and the builder build with, a toolchain the suite never ran with.
- `check-ignore -v` quoted a rule's source holding letters outside ASCII (and split on a colon), so
  a tracked `.gitignore` under `docs/design/ábaco/` read as a rule the commit does not hold.

Answered: `cut::suite_rustc` reads the version through `suite_command`, whose child environment is
now the given one alone, the steering variables left out; `check-ignore` gets every ignored path
on its stdin with `-z`, its four fields a path read as they are. Tests: the toolchain the same with
`RUSTUP_TOOLCHAIN=no-such-toolchain` in the given environment (the variable failing rustc when it
reaches it); the accented folder's rule counted as the commit's.

Noted, not a gap of the code today: release 2.0.0-alpha.1's bundle was packed by the cut as it stood
at d74be94, before round one: its folders are 0775 and its plain files 0664 (today's cut packs 0755
and 0644), and its `[tested]` line was written under the tree check of then. Its manifest matches
the bundle byte for byte; the release cannot be cut again under its name. The next release, cut by
today's code, carries every answer.
