## The first real cut (2026-11-22)

`entrega cut 2.0.0-alpha.1` at d74be94: the whole suite green there (898 tests, 512 s, behind the
machine's lock), the four executables built in the Debian 13 builder (glibc 2.38 and GLIBCXX

put a law test's "tree without git" inside the worktree's repository; the cut's suite now takes
its temporary files in the cache.

## Refute round 1 (2026-11-22)

Refuted, four findings:
- The cut checked the manifest against the repository only, never against the releases already
  cut, and wrote it first: a cut of today's HEAD as 2.0.0-alpha.2 would have pinned six versions
  2.0.0-alpha.1 already names at other code, which `entrega check` refuses.
- The packed bytes depended on the umask (0002 and 0022 gave two archives, 41 entries apart).
- The clean-tree check ignored untracked files, while the suite runs in the tree.
- The recipe's library limits were any string; `v2.41` read as `[41]` and turned the guard off.

Answered: the manifest is planned before anything is built and checked then against the
repository and every release in `releases/` and where it writes (a release named in either refused
too); the builder's `rustc --version` must be the one the manifest states; packing reads every mode
as 0644 or 0755 (`bundle::pack`); untracked files count; the limits must be dotted digits. A bin
cargo does not build with the default features is now named and refused at the build (round 2 of
C-290 moved that judgement here). Each finding has a test in tests/bundle.rs, the one-tree refusal
in a throwaway repository, before any build.
