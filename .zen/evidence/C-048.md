# C-048 evidence - the supervisão file and the binding file

## The design (2026-11-09)

The design's first open point (`docs/design/supervisao/README.md`, "the binding file format")
settled as two files, both read by core's header reader: the host file (`veredas-supervisao` v1:
the address, the sessions) and the binding file (`veredas-binding` v1: a session's objects, the
layout, the headline, the dashboards). The reference is `docs/binding-schema.md`; its worked
example is four blocks (the host, the portal project it runs, the binding, the SVG) that the
files test writes under the names they give and loads, and that the live tests of the other
clauses run against the bench (the endpoint, the namespace and the port substituted).

A binding is checked against what its project carries when it loads, never left to light up or
not at run time: every source a binding names is the project's, every series one that source
carries (a capture rule's value groups for a log the rule reads, the key group excluded; an OPC
tag's or bit's series; a catalog message's fields), with the series it does carry named in the
refusal; every write an OPC tag a rule marks writable, named by its node id text, as portal's
write surface names it (the reference first named it by its series, which portal would have
refused: corrected before any code, `docs/binding-schema.md`); every table a capture rule, an OPC
rule, a message or a view. A view's columns are the engine's to judge, so a table panel's columns
are checked when the panel is computed, and a panel that cannot be computed says why in its place
(C-052).

The layout is read as XML (`roxmltree`), never by a pattern over its text (portal's lesson: a
reading of SQL was the wrong tool for five rounds). A layout is a drawing the page places in its
own document, so a script, foreign content or an event handler refuses it at load.

A panel's keys are read per kind from a TOML table (serde with `deny_unknown_fields` per kind), so
a key another kind takes is refused with the keys this kind takes, never swallowed (portal's
untagged-enum trap).

## Refute round 1 (2026-11-10, at d560cee): refuted, seven gaps

Eight mutations of config.rs, binding.rs and svg.rs together kept the test green. The findings,
and what changed:
1. **A panic on a well-formed layout:** an attribute name with a letter past ASCII was cut inside
   that letter (`oé`), and the check panicked instead of refusing or loading. Names compare by
   bytes now.
2. **Types read otherwise than portal reads them:** portal takes a type's word in any case; the
   binding took the lower-case words alone, so a `"TEXT"` tag passed under a level and a `"FLOAT"`
   group refused a valid trend. The universe is now compiled by portal's own readers
   (`opc::compile` and `opc::table_of`, `channel::check`, portal's type parser), and a series
   several rules or messages carry is numeric only where all of them type it so (a channel's
   `item` is a number in two messages and text in the outcome's payload).
3. **Whole paths never driven:** a rule's scope, a tag's bits and a channel's fields are now
   (two logs, bits as ints, a channel from the channel and catalog references).
4. **Boundaries never fed:** a 32-letter name and a 64-character id load, a range of one point and
   an infinite spread are refused.
5. **Layouts no browser lays out, or that run script:** an `svg` root outside the SVG namespace is
   refused, and so is a link whose target runs script (`href`, `xlink:href`); a document type, as
   drawing tools export it, loads.
6. **Panel columns unchecked:** a table panel's columns and sort, and a cells panel's key and value
   (numeric), are checked against the table's columns where the project states them; a view's are
   judged when the panel is computed.
7. **Refusals the reference did not list:** it lists every one now, and the bounds by their keys.

## Refute round 2 (2026-11-10, at 77180a4): refuted, two defects in the layout reader and four gaps

Two defects, both in what a layout may carry into the page. A script link with a tab, a line break
or a carriage return inside its scheme (`java&#9;script:`) was accepted, though a browser's URL
parser drops those characters and runs it; and an element of another namespace (an XHTML `iframe`
with a `srcdoc`, an `h:object`, a `path` of no SVG namespace a marker would follow) was accepted as
long as it was not named `foreignObject`. Now every element outside the SVG namespace is refused
as foreign content, and a script link is recognised as a browser reads a URL (tabs and line breaks
dropped, leading controls and spaces trimmed) in any attribute, an animation's `to` among them.
The reference names both.

Four gaps in the test. Many keys were accepted by name but never read back by value (an object's
key, range and `show`; `above`, `at_most`; the word's and the label's defaults; a dashboard's
columns; a panel's title, minutes, limit, aggregate, table limit and column labels and states):
a binding writing each of them is now loaded and read back whole. No rule over another series was
loaded, so its series and `Rule::ty` were unasserted: an int one and a keyed text one now are.
Seven refusals the reference lists had no case (a marker and bars over text, a cells panel's table
the project lacks, a value panel with no object, a range's high not finite, a bars target and an
`equals` that are not numbers): each is pinned by its text. And the root's own `onload` is pinned.

Argued, not counted: a `key` on a series whose samples carry no key loads (the reference lists no
such refusal); the plan's branches the example never reaches are untested.

## Refute round 3 (2026-11-10, at 5b91c1c): refuted, two defects in the layout reader and four gaps

The defects. A document type declaring attribute defaults loaded: the reader (roxmltree) expands
entities but ignores `<!ATTLIST`, while the page's DOMParser applies it, so the reader checked a
different document from the one the page builds. In headless Edge an `<iframe>` given the XHTML
namespace by a default ran its `srcdoc` script with access to the page, and an `<a>` given a
`javascript:` href ran it on a click. And a script link as a later item of an animation's `values`
list loaded (`#a;javascript:…`), the check reading only the whole value. Now a document type
declaring attribute defaults is refused by name, one using a parameter entity by the XML reader
itself (a general entity, expanded and checked, still loads), and a value is judged item by item at its `;`. The reference lists both.

The gaps: the reference's ranges were pinned on the refusing side only (off-by-one mutations of
places, columns, a table's limit and a span stayed green, and a negative spread loaded under one);
the int-and-float merge was never fed; the accepted side of the name and id shapes was never
loaded; and the reader refused a rule naming `source` or `key` without `series` where the
reference gives each the object's own. Now one binding loads at every accepted edge (places 6 for an
object and a column, 12 columns with a span of all 12, a limit of 1000) with a session named
`2-line` and an id `in_feed.a`, read back; a negative spread is refused; a series typed int by one
rule and float by another reads as a float under a trend; and a rule takes the object's own source,
series and key for any it leaves out, as the reference says (the refusal case pinning the old
reading is gone).

## Refute round 4 (2026-11-11, at 02b43ef): refuted, four gaps in the test, the readers right

The layout reader held (entities expanding to script, a handler, a `javascript:` link or an XHTML
frame refused; `xml:base` refused; what it loads but no browser runs checked in a headless page).
The panel reader had defaults and a boolean no assertion pinned: five default titles (the trend's
and bars' object label, `States`, `Levels`, the cells' table name), the cells panel's 60 minutes, a
levels panel without `ticks` (a reader requiring them stayed green), and `descending`, whose value
was read only as `true` (a reader always sorting descending stayed green); the reference never said
what `descending` defaults to.

The answers. The worked example's eight panel titles are asserted, written or defaulted; the keys
binding writes a title on a trend, a bars and a cells panel and reads each back, adds a levels panel
without ticks or title (none, "Levels"), a cells panel leaving its windows to their defaults (60
and 5 minutes) and a table sorting without `descending` (false). The reference now states
`descending` false unless written, and the test's copy of it moved with it. Seven mutants each turn
the test red.

Outside the clause, for the operator (`docs/questions.md` Q23): a layout's `<style>` may
`@import` a stylesheet from another host; nothing refuses it meanwhile.

## Refute round 5 (2026-11-11, at ab97319): refuted, four gaps in the test, the readers right

Written values the test never read back: a rule over another series on a keyed object (dropping
the object's key stayed green), a panel's `minutes` written other than 60 and a `bucket_minutes`
other than 5 (a reader ignoring the window a file sets stayed green on value, bars, timeline and
cells), a fraction compared by `equals` (truncated, green), and the disabled state (refused by its
reader, green under this clause's run). Also pinned only by C-049's run: a bind other than the
default and two sessions in the file's order.

The answers, in the test: the keys binding gives object `a` (keyed A1) a rule over `fill2` read
back with the key, adds object `c` with `equals = 0.5` and a disabled state, and four panels
writing their windows (value 15, bars 120 and 10, timeline 120, cells 90 and 15); the host file is
loaded with a written bind and a second session named to sort first, read back in the file's
order. The reference now states the consequence the critic found: a rule takes the object's key,
so on a keyed object a rule over a text series (which carries no key) is refused; the test's copy
of the reference moved with it. Nine mutants each turn the test red.

## Refute round 6 (2026-11-11, at a5bb689): refuted, eight gaps in the test, the readers right

The round-5 answers held. Beside them, values and refusals the test never reached: a rule's own
`key` (the object's overriding it stayed green), a trend's `minutes` other than its default,
written titles on a timeline, a grid, levels and a table, a value, trend or bars panel naming no
object (binding the first object stayed green), a bind beyond the loopback (served on the loopback
instead, green), the lower accepted edges of a dashboard's columns and a table's limit, `minutes = 0`
on every kind but the trend, and a grid over a text series (refusing it stayed green). The layout
reader held against every bypass tried; Q23 stays open.

The answers, in the test: object `a` gains a rule over `fill2` writing `key = "B2"`, read back with
it; the keys binding gains an object over the text series `mode`, a trend of 45 minutes, a timeline,
a grid of `m` and levels with written titles beside a grid of `a` and `m` defaulting to "States", a
table titled "Tab" with `limit = 1`, and a second dashboard of one column with a panel of span 1, all
read back; the host file's written bind is `0.0.0.0:9123`; seven refusals by text join the rest
(`minutes = 0` on value, bars, timeline and cells; `sped` on value, trend and bars, each with its
place). The critic's eight mutants each turn the test red.

## The keys' class (2026-11-11, after the sixth refute round)

Rounds 5 and 6 each found keys the reader takes that the test never wrote, so never read back. The
class is now driven from the reader's own list: for the supervisão file's two tables, every binding
table, the bound series, each panel kind, a column, a sort and a limit, the keys the reader names in
its refusal of a misspelled key must all be written in the worked example or the keys binding, whose
tests read them back. The panels' `span` was written only on the trend (and at its default on one
value panel), so a span of 2 is now written on a panel of every kind and read back; with it the
check passed on its first run.
