# C-149 evidence - the executable

## First version (2026-11-26)

Phase 7. Veredas 1's `main.rs` served the engine over HTTP (axum, JSON, server-sent events) to its
`aranha/` page; Q280 (ruled 2026-11-25) leaves the surfaces to Oficina, so the executable is a
command line on the library, and nothing it prints is a format of its own: the scan is the file
(C-146), the diff the library's (C-147), the lines for an engineer reading them and a script
grepping them.
- **Three commands, the plan's**: `listen` (and write the scan), `identify`, `diff`. Its arguments
  are read by hand: the crate stays light (C-130), and three commands need no parser crate.
- **The capture beside the scan** is the scan's name with `.pcap`, every frame the listener kept
  from the snapshot the scan is written from (its first frame and count in the scan, so every
  witness is checked against a record of it, C-146), the frames sent among them. A capture of
  several interfaces is one file: classic pcap has no interface per record, and the scan's
  witnesses name each frame's interface.
- **Its order is the rules'**: listening first, the Identify a second in (the wire's own traffic
  heard first), the ports read while the listener still hears (the read's answer is a frame it
  keeps, C-148), the topology from the last snapshot before the listener stops (a device leaving as
  the bench ends says its port is no one's cable, C-145).
- **The diff's exit status is diff(1)'s** (0 the same, 1 changed, 2 trouble), so a script can ask
  whether a plant changed since its baseline. A link's line gives its ends and confidence and not
  its witnesses, which differ between two scans of one cable.
- **Refused, never guessed**: a usage it cannot follow, a file it cannot read, an interface it
  cannot open, each status 2 with its reason, nothing written. On Windows raw frames wait for Q281;
  `diff` runs anywhere.

The test starts the executable before the bench (a Hello sent before a listener opens is gone,
"Traps"), the second device saying no Hello so that its name comes from the Identify alone, and
reads the diff outside the private network: the two files are all it needs.

Before the first commit, 22 mutants of `src/main.rs` (a resumable script under
`~/.cache/veredas/aranha/mutants/c149/`): the help's or a refusal's status, the diff's status for a
change, `no change` unsaid, a vanished device unsaid, a rename unquoted, a removed link or a
cleared conflict said as added or new, `--for` unbounded either way, an interface named twice
taken, a scan file of another extension taken, the Identify or the reads not done, the capture's
count off by one or its name another, the identify's name filter ignored, the refusal's prefix
dropped, the stderr counts dropped, the summary's count off, kinds unspelled: 21 killed (the
filter's only once an Identify by a name no device holds was added); one equivalent within the
test's reach, the capture's first frame taken as 0 (nothing is let go in a scan of seconds, so the
listener's first kept frame is 0; the witnesses are checked against the capture's records by that
number).

## What C-033's rounds already knew (2026-11-26)

The stop hook paired the clause with C-033 (the bench's executable), and the implications check
found the first version repeating three faults C-033's refute rounds had found in that executable,
each of which broke this clause's own words ("refused with status 2", the diff's status diff(1)'s
for a script reading it): an argument not UTF-8 panicked (`std::env::args`, exit 101); a stdout
closed (`diff a b | head -1`) or a stderr closed panicked at the first line written (`println!`,
`eprintln!`), and `listen` wrote its Identify counts to stderr before its scan, so a closed stderr
lost the scan; an option given twice took the second in silence. Fixed as the bench's executable
fixed them: arguments read with `args_os` (a path kept as the system gives it, anything else that
is not UTF-8 refused by name), every line written with its failure ignored, an option given twice
refused. `--version` added, as alforge's plan asks of every executable. Each fault, put back as a
mutant, fails the test (a closed stdout and a closed stderr are a pipe whose reader is gone before
the executable writes). Usage errors keep status 2 (C-033's are 1; no suite rule sets one, and
diff(1) takes 1 for a change).

## The first refute round, answered (2026-11-26)

The critic (its own copy; probes on the bench in a private network; scan files edited by hand; 22
mutants of its own) refuted on four defects and what the test never asserted (18 survivors):
- **Texts printed raw.** A link's ends were printed bare, and a port or a chassis is a device's
  own text: one holding a space and `=` made a line that cannot be split back into its ends, one
  holding a line break printed a bare `no change` inside a diff of status 1. Every text is quoted
  now, a node and its port among them, so a line is one change; identify's label too.
- **The capture written before the scan.** A scan that could not be written (a folder in its
  place, a read-only file) was refused after its capture had replaced the one beside the
  baseline, leaving the baseline's witnesses pointing at another listening's frames. Both are
  checked before anything is opened (a folder there, a file that may not be written, a file name
  not UTF-8), then written under names of their own and put in place, the capture first: a
  failure before that replaces nothing.
- **A scan file's name not UTF-8** wrote a scan naming a capture that is not there
  (`to_string_lossy`): such a name is refused, as the scan names its capture by it.
- **The Identify one interface after another**, each waiting its window, so a listening ran past
  `--for` by a second an interface: it is asked on every interface at once.
- **The ports read before a failure dropped** (`read::ports` gave the subslot and the error
  alone): the walk now gives what it read with the failure (C-148), and the executable draws it.
- **Unasserted**: the timing (`--for`, its default, its bound, the Identify a second in), the
  port-failure line, identify's alias, wait, ids, the mirror diff's lines, every kind of line,
  a device on two interfaces, an unaddressed device not read. Each has a case now; identify's frame
  number is gone from its line (the listener that kept it is gone when the line is read).

Of 28 mutants of the answer (the critic's 18 survivors and M01 written against the new code, and
the new paths: ends and the label unquoted, the capture or the scan written in place, a temporary
file left, a name not UTF-8, a folder or a read-only file taken, the Identify one interface after
another, the cut's ports dropped by the executable or by the walk), all are killed (a resumable
script under `~/.cache/veredas/aranha/mutants/c149r1/`).

## The second refute round, answered (2026-11-26)

The critic (its own copy; probes in a private network with a scripted device and on the host
before anything is opened; 10 mutants) found the quoting of labels, the paths in the current
folder and with several dots, a link as the scan path and the Identify on one interface holding,
and refuted on:
- **A failure between the two renames** put the new capture in place and left the old scan: a
  trailing separator on `--out` did it (`with_extension` drops it, the scan's rename does not), as
  did a folder made where the scan goes while it listens. A path ending in a separator is refused
  before anything is opened; the capture there is kept aside until the scan is in place and put
  back if the scan's rename fails.
- **The temporary names were fixed**, opened truncating and through links, and removed
  afterwards: a user's file under such a name was consumed or deleted, a link's target
  overwritten. Every file of the run is now made new under a name of its own (the process and a
  count), never through a link, and only what the run made is removed.
- **The folder was never checked**: a folder not there, or one that may not be written in, was
  found only after the listening. A file of the run's own is made there and removed before
  anything is opened.
- **The diff's interface lines were unquoted** (an interface's name holding a line break printed
  a bare `no change`): quoted.
- **One interface's failed Identify dropped the whole scan** (a `?` on each interface's answer);
  it is said on stderr and the listening goes on, as it does when an interface ends without one.
- **Closed streams for listen's and identify's stdout and the port-failure line** were never
  tested: each is a case now.

The critic's R07 (identify's counts of others and of frames lost swapped) stays equivalent within
the clause's words ("a count"), and its R10 (a capture's temporary file left on a failed capture
rename) is answered by the run's own names, removed on every path.
The answer's own probe found one more hole: a folder made at the capture's place while it listened
would have been moved aside under the run's name; both places are checked again just before the
renames, and something other than a file there is never moved or replaced.

Of 15 mutants of the answer (the critic's R01 to R06 against the new code, and the new paths: the
rollback, the names of the run's own, the separator, the folder check and its file, the interface
lines, the temporaries and the capture kept aside left behind, the check again before the renames),
13 are killed (two only once a case was added: a device line written with stdout closed, a
successful run over a capture already there). Two survive, equivalent within a test's reach: the
two renames in the other order (every failure a test can make from outside, the scan's place made
a folder or the capture's, gives the same files either way; only a capture rename failing after
the capture was kept aside would tell them apart) and the run's files opened truncating rather than
made new (its names hold its process id and a count, which no file can be given before the run).
