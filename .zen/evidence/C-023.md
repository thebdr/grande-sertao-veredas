  - `BadDecodingError` is the decoder limit: what the field's 3,048-tag source met.

## Refute round 2 (2026-11-06): refuted, one unpinned limit

All five round-1 findings are closed. The browser's page (1 000) sits exactly at the client's
array limit, and nothing related them. On a server serving 5 000 per page, asking for 1 001
references killed the connection (`BadConnectionClosed`). So `BROWSE_PAGE = 2_000` would have
passed every test, and broken against any server that honours the page asked for.

Now pinned:
- `BROWSE_PAGE <= ARRAY_LIMIT`, asserted at compile time;
- a full 1 000-reference page decoded;
- 1 001 closing the connection.

Also pinned:
- four good codes with info bits (limit, overflow) still good;
- UserAccessLevel as a Byte;
- MinimumSamplingInterval as a Double. The demo variables now state one.

## Refute round 3 (2026-11-06): refuted, one unpinned assumption

All round-2 findings are closed; the 1 001-reference pin really measures the client's own limit.

Unpinned: the worker and the browser close sessions "so the server frees the slot", and nothing
showed the slot coming back. A stack bump that skipped CloseSession, or took longer than 100 ms,
would pass every test, and a controller with few slots would then refuse new sessions.

The demo plant now takes a session limit (`DemoConfig { max_sessions }`). On a server holding
one session:
- three sessions in turn, each closed within 100 ms, all connect;
- one dropped unclosed leaves the next refused, `BadTooManySessions`.

## Refute round 4 (2026-11-06): holds

The slot pin catches both changes it guards against:
- **A skipped CloseSession.** The server frees a session only on CloseSession or on expiry,
  never on a closed channel.
- **A close slower than 100 ms.**

A fresh search found every place the layer calls the stack pinned here. The node id's text round
trip is pinned in `opc_spec.rs`.
