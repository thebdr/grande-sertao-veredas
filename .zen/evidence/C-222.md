## What parity is measured on (2026-11-22)

P-007's exit asks for "parity with Veredas 1's oracle numbers". Those numbers (Veredas 1's
`docs/abaco-oracle.md`, "Phase B1b": five real workbooks of one plant, 1 217 533 formula cells, all
equal to Excel's cache under the cached and the linked resolution) were taken on files copied from a
cloud folder of the Windows desk. They were never committed (Veredas 1's history holds only
IronCalc's test workbooks and one derived fixture) and are not on this machine: not on its disk
(`find / -xdev` by name), not in Veredas 1's checkout, not in the Google Drive mount (searched by
name to depth 10). They hold a customer's data and never enter this public repository.

So, as taken meanwhile in Q344: the corpus is every workbook Microsoft Excel saved among the fork's
own test files, the baseline Veredas 1's oracle and fork run here over it.

### The corpus rule
A first rule (`docProps/app.xml` naming an application that starts with "Microsoft" and holds
"Excel") let in `openpyxl_example.xlsx`, whose application is "Microsoft Excel Compatible /
Openpyxl 3.1.5" and which caches no value: the corpus test listed the applications and caught it.
Every genuine Excel file of the folder says `AppVersion` 16.0300 and carries
`<fileVersion appName="xl" lastEdited="7" ...>` in its workbook; XlsxWriter writes "Microsoft
Excel" with version 12 and its own constant file version. The rule now requires the exact name (one
of four, Excel on Android counted after the refute round), a version from 14 and Excel's file
version edited by version 5 or later. 257 workbooks: Excel on Windows, on the Mac, online, on
Android. The folder's nine others are named in the test with what each says of itself (no
application, LibreOffice, openpyxl, IronCalc). The rule reads what a package says of itself; a writer
that forged all three would pass (a limit, stated in the code).

### The baseline
Veredas 1's `abaco-oracle`, built from Veredas 1 at `671cdc43` in release
(`CARGO_TARGET_DIR=<scratch> cargo build --release --locked -p abaco-oracle`, its tree untouched),
run once per workbook under `--links cached` and `--links linked`; each report's summary row and
table of classes read into `tools/abaco-oracle/baseline/veredas-1.toml` (the classes by the
oracle's ids, each file's classes summing to its formula cells and its matches equal to the
summary's, checked as it was written). One workbook,
`calc_tests/LOOKUP_AND_REFERENCE/INDIRECT.xlsx`, aborted Veredas 1's oracle before the engine ran:
its calamine cross-check built a sheet's whole declared range and asked for 549 755 813 888
bytes. It is recorded as unmeasured.

Veredas 1 on the 256 files it measured, under either resolution: 75 743 of 76 245 formula cells
equal to Excel's cache (99.34 %). 32 files fall short of 100 %: volatile dates (NOW, TODAY and the
templates built on them), numerical tails (Bessel functions, IRR, XIRR, trigonometry), dynamic
arrays the engine spills differently, and a few text, date and information functions; the oracle's
report lists every mismatch by class with examples.

### Veredas 2's oracle

by the rule above. The comparison and its classes are Veredas 1's, line for line.
