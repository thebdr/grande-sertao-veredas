# C-037 evidence - backfill

## The design (2026-11-07)

Veredas 1's `tail/backfill.rs` as it was: the plan (files, first offset, encoding, skipped
members), the peek over buffered reads, the raw line table per encoding. Its unit tests moved
into the clause's test file through two doc-hidden functions (`plan_for`, `line_table`) that
expose the plan and the table without making the internals public API.

Added over Veredas 1's tests: an unstamped continuation line before the start skipped (it belongs
to the earlier stamp), the refusal's text when a backfill is asked without a timestamp rule, the
first replayed line's stamp and index at the seam, and a backfill into an empty folder falling
through to a live attach that reads what is born whole.

## Found by the suite (2026-11-08): the locate through a rotation

The fixed-name seam test failed one run in six, on its own as under the whole suite, with no line
at all: the backfill located its start while the writer retired `current.log` into the pattern,
the peek of the listed active hit a file no longer there, and the worker ended in an I/O error
the test could not see. The locate now lists again on a not-found peek, within a patience of
500 ms (the fixed-name mode retires its active under a new name at every rotation; the indexed
mode never renames). Pinned by a hook before the peek that performs the rotation; the plan comes
out with the same start in the same file and the retired generation under its new name.

## Refute round 1 (2026-11-08): refuted, four gaps and two judgement calls

The critic found: a start equal to a stamp shared across a seam chose the later file (the newest
file whose first stamp was at or before the start), skipping the earlier file's lines on that
stamp, common with second stamps and size rotation; a peek of an empty file reported UTF-8 as if
detected, so a plan taken while the active was still empty (the state right after a rotation)
forced UTF-8 on the UTF-16 the writer then put there, every line garbage; a fixed-name rotation
that had already recreated the active when the retired one was peeked read a file the listing did
not name, the retired generation absent from the plan and from the skipped, so the attach read it
whole as a fresh retiree; a family whose only member held no lines refused ("no line timestamps
parse and the file names carry no dates") instead of falling through to live. The judgement
calls: a start between two files took the next file's top even when it opened on unstamped
continuation lines the clause itself assigns to the earlier stamp; and a file whose first 400
lines carried no stamp had no first stamp, so it was never chosen and the whole family replayed.
Fixes: the newest file whose first stamp is strictly before the start (a file opening on the
start's stamp is reached through its predecessor's scan); the peek's encoding is `None` for a file
with no bytes, the live tail detecting from the head; the listing is taken again after the peeks
and the scan, and a plan stands only when the members are the ones it was computed for (every
rotation adds a name), a family that never holds still running the patience out by text; a family
with no line anywhere plans nothing and falls through; the next file's first stamped line (a next
file with no stamp at all from its top); a head without a stamp within the cap under a tail with
one is scanned forward to its first stamp. Six tests pin them, two end to end. Checked and held
by the critic: a start on a stamp mid-file and among equal stamps inside one file, CRLF and
UTF-16 offsets with the mark counted and the torn unit left off, the prefilter's safety, the
fallback reached only with no stamp anywhere, the refusal before any worker, the skipped names
seeded as consumed, a start in the active file.
