# C-131 evidence - the envelope and the MAC address

## The port (2026-11-22)

From Veredas 1's `ether.rs` and `mac.rs`. Changed on the way:
- the 802.1Q tag keeps its priority and drop-eligible bit (Veredas 1 kept the VLAN id only):
  PROFINET's cyclic frames ride at priority 6 with VLAN 0, and the IO controller writes them;
- `build` refuses a payload past 1500 bytes, a priority past 7 and a VLAN id past 4095. Veredas 1
  wrote any length;
- the MAC reader takes exactly three spellings. Veredas 1 deleted every `:`, `-` and `.` and read
  what was left, so it took mixed separators, a group of one digit beside one of three, the dotted
  form with six groups, and a leading `+` (`u8::from_str_radix` accepts a sign: `+1:0e:cf:12:34:56`
  read as `01:0e:cf:12:34:56`);
- `is_local`, the locally administered bit, for the fixtures' range.

## The second reading

`tshark` 4.6.6, extracted from Ubuntu's archive into `~/.local/opt/wireshark` (the packages:
tshark, wireshark-common, libwireshark19, libwireshark-data, libwiretap16, libwsutil17,
libsmi2t64, liblua5.4-0, libnghttp3-9, libopencore-amrnb0, libbcg729-0, libjsoncpp26, libhwloc15,
libtbb12, libtbbmalloc2, libtbbbind-2-5, libfalcosecurity0t64), run by a wrapper that sets its
library, data and plugin folders. `tests/common/mod.rs` writes the frames as a classic pcap and
reads tshark's `-T ek` output (numbers in decimal); a packet tshark calls malformed, or expert
information at warning or error severity anywhere in it, is a complaint the tests require absent.
Where tshark is not found the test fails naming what it tried.

## Refute round 1 (2026-11-22): refuted, three gaps

- **The drop bit was never read back alone.** Every parsed tag had the drop bit equal to the
  priority's low bit; a mutant reading bit 13 passed. The drop bit alone and the priority's low bit
  alone are now parsed back.
- **The 1500-byte limit was tested untagged only.** Tagged 1500 is now taken (1518 bytes, read by
  tshark) and 1501 refused.
- **A type field below 0x0600 is an 802.3 length.** `build` wrote one, and 0x8100 untagged, which
  its own `parse` then read as a tag. `build` now refuses both (`NotEtherType`), `parse` keeps the
  field as it travels and `is_length` tells a length (a spanning-tree frame's) from an EtherType;
  the clause's dissector claim names the EtherTypes it covers.

## Refute round 2 (2026-11-22): refuted, five test gaps, the code right on every edge probed

Every answer of round 1 held against its mutants. What the tests still let through, now pinned:
- `is_length` was asserted at two points; mutants reading IPv4 as a length, 0x0600 as a length, or
  a tagged LLC frame never as one passed. Six type fields either side of 0x0600, tagged and not.
- `is_local` was asserted at one positive and one negative; seven first octets and two group
  addresses now.
- The non-ASCII MAC texts were refused by the byte width before the digit check; a mutant dropping
  the digit check passed (and panicked on `aéb.ccdd.eeff`). Three texts of exactly a group's width.
- No PROFINET frame was dissected under C-131's own test; PROFINET's type, tagged and untagged, and
  LLDP's tagged now are.
- The Hello group address was pinned only by C-132's test; C-131's now too.

## Refute round 3 (2026-11-22): refuted, the code right, three test gaps

- **A tagged frame was never compared whole**: a mutant padding tagged frames with 0x55 passed (a
  pad holding leftover data is a known bug class). A tagged frame is now compared to the byte, pad
  included, and parsed back whole.
- **The dissector's fields were asserted on some frames only** (the drop bit read once, as true): each
  field is now asserted on every frame where it applies, against what the frame was built with; the
  frame length, the pcap's own, is no longer counted as the dissector's reading.
- **Serde was tried with one refused text**: all twenty-three now, refused untrimmed.
- Pinned on the way: mixed case accepted (the clause's "either case" read as case-insensitive), and
  the local bit on first octets with only high bits set.

## Refute round 4 (2026-11-22): refuted, the code right on every edge, two parse gaps, three readings

The critic ran 65 mutants (the earlier rounds' fixes holding) and probed tshark with edge frames.
Answered:
- **Parse was never checked past a 100-byte payload**: a mutant cutting the payload at 100 bytes,
  and one refusing what build refuses (past 1500), passed; the second would refuse a two-tag
  frame, or the 65 536-byte frames the raw link hears whole. The 1514- and 1518-byte frames are now
  read back whole, and a 1522-byte two-tag frame and a 9000-byte one too.
- **An 802.3 frame's payload was checked on three bytes**: mutants cutting it to the length field
  passed. The whole payload, pad included, is asserted now.
- **"Below 0x0600 is an 802.3 length" went further than IEEE**: 802.3 makes 0x05DC the highest
  length, and Wireshark warns "Invalid length/type" for 0x05DD. `is_length` now reads up to 0x05DC;
  0x05DD to 0x05FF are neither (and still no EtherType to write).
- **VLAN id 4095 was written**: 802.1Q reserves it and says it shall not be transmitted. It is now
  refused on writing and still read.
- **0x88A8 and 0x9100 were written as a frame's type**: Wireshark (and this crate's raw link) read
  them as tags, the "written, then misread" pattern the first round closed for 0x8100. Refused now.
Before this commit, nine mutants of this round's points were run: all killed.

## Refute round 5 (2026-11-22): refuted, a group source written, seven mutants

The critic found the earlier rounds' fixes holding and the MAC parser agreeing with an exact oracle
on 202 345 near-valid texts. Answered:
- **`build` wrote a frame whose source is a group address** (broadcast, a DCP group, any address
  with the group bit), which IEEE 802.3 forbids and Wireshark warns of ("Source MAC must not be a
  group address"): refused now, tagged and untagged (`EtherError::GroupSource`); heard, such a frame
  is still read as it is.
- **Seven mutants passed**: serde read only from a borrowed string (from a value, a reader and an
  escape now); a tag of nothing written or read as no tag (pinned both ways); 0x88A8 and 0x9100
  read either way (pinned as the frame's type, and the clause says so, where Wireshark reads a
  tag); the priority refusal's message; a trailing line break and a leading tab accepted; upper-case
  A, B and D refused (every hex letter is now read in both cases).
- **"Neither" could not be told from an EtherType**: `is_ethertype` added, the three readings
  asserted; Wireshark's "invalid" is an untagged frame's only, as the clause now says.
- **Wording**: a second tag's type is read as the frame's type and its tag field as the payload's
  first two bytes, not "the payload's first bytes".
Before this commit, nine mutants of these points were run: all killed.

## Refute round 6 (2026-11-23): refuted, the code right, five tag types written and bounds tried at one value

The critic swept every type field tagged and untagged, every tag word, payloads of 0 to 1600 bytes,
704 address bit patterns and 123 374 MAC spellings through `build`, `parse` and tshark: every
reading agreed but in one place. Found, and answered:
- **Five more types read as tags** (the clause's own rule): tshark 4.6.6 registers eight
  EtherTypes as tags, not three (`tshark -G decodes`): besides 0x8100, 0x88A8 and 0x9100,
  802.1ah's I-TAG (0x88E7), 802.1BR's E-TAG (0x893F), 802.1CB's R-TAG (0xF1C1), the VN-Tag
  (0x8926) and Broadcom's tag (0x8874), each reading the payload's first bytes as its own. The
  writer wrote them, as round 4 had found of 0x9100; it now refuses all eight, and a test shows
  each of the five to tshark, which reads its protocol's tag. No frame of the suite uses them.
- **Bounds tried at the first value past them only**: the tag's control word masks the priority
  and the VLAN id, so a check that missed a higher value wrote a cut tag silently (priority 200 as
  priority 0, VLAN 0xFFFF as the reserved 4095). Every priority from 8 to 255 and every VLAN id
  from 4095 to 65535 are now refused by their exact errors, payloads far past 1500 too.
- **Seven types tried as accepted**: every type from 0 to 0xFFFF is now built tagged and untagged,
  refused exactly below 0x0600 and for the eight, and read back as itself otherwise.
- **Tagged frames of 14 and 15 bytes** never parsed: every length from 14 to 17 named.
Before this commit, the critic's mutants and one dropping a tag type, eight, were run: all killed.
