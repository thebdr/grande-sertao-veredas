# C-200 evidence - veredas-comissionador, the component

## The design (2026-11-22)

The plan (`docs/comissionador-plan.md`) and the grammar (`docs/test-schema.md`) came first
(b2ed0d1), with the questions Q310 to Q317 and the option taken meanwhile for each. The crate
followed on the orchestrator's word of the same day: phase 1, the reading and the check.

A library and one executable, like portal and supervisão: the executable is a shell over the
library (`veredas-comissionador check <file>` today; `run` and `replay` with the engine, C-205).
No build script, no feature.

Its members: core alone for now (the header reader, `veredas_core::schema`). Portal joins the
manifest with the engine (phase 2), when the engine reads a session; the test admits core and
portal, L5's row, and requires core.

## Never arming the switch (Q314)

Q314 is taken as (a): comissionador never arms portal's write switch; a live run of a test that
writes will be refused while the switch is off. The guard reads every Rust file of `src/` as
`proc-macro2` tokens, the pattern of supervisão's writes test, smaller: the only ways to arm a
session's switch from outside portal are `Session::set_writes_armed` (the gate itself is
crate-private in portal) and a gate of one's own (`WriteGate`, core's type), and a method or a
type can only be reached by naming it, so a name absent from the tokens is a call absent from the
code. `include!`, `include_str!` and `include_bytes!` are refused too: they would bring tokens
from a file the reading does not walk. A raw identifier (`r#set_writes_armed`) is read as its
name; a comment and a string are not tokens of code.

Limits written into the clause: a dependency's macro could expand to such a call without the
name in this crate's tokens (the crate has no such dependency); the tests are not read, since a
test of the engine will hold a session and arm it, as portal's and supervisão's tests do.

## Refute round 1 (2026-11-22): refuted, three findings, all closed

1. **Code the reading never opened.** The test read the `.rs` files under `src/`; a
   `#[path = "gate.txt"] mod gate;` brought in a file it skipped, and `[lib] path = "outside/lib.rs"`
   in the manifest built the library from outside `src/` while `src/` stayed clean. Both armed a
   gate with every test green. Closed: every non-test target's `src_path` (cargo metadata) under
   `src/`, every file under `src/` Rust, and `path` refused inside any attribute (`#[...]`,
   `#![...]`, `cfg_attr` within them).
2. **A gate without its name.** Core's `WriteGate` derives `Default`, so `Default::default()`
   handed to `veredas_core::opc::spawn` arms a worker of comissionador's own with no `WriteGate` in
   the text. The clause's rule is wider than the switch: comissionador drives machinery only
   through portal. Closed by refusing what reaches past the session: `spawn` (every worker that
   writes takes a gate, so a gate by `Default` serves nothing), the protocol layers' paths (`opc`,
   `telegram`, `fieldbus`), std's sockets (`net`) and processes (`Command`); the normal
   dependencies held to a reviewed list with no OPC UA, socket or HTTP crate. Asking core to drop
   `Default` was the other way; it is not needed.
3. **A project's text in a literal.** Once portal is a dependency, a `[session]` text with
   `writes_armed = true` loaded by `project::load` would start an armed session. Closed: a
   literal holding `writes_armed` is refused. The guard is stated as Q26's: against accidents,
   not deliberate hiding (an encoded or computed text is outside it).

The critic found sound: the rule of targets (a missing or second binary, other library types,
examples, benches, a build script), the member edges with L5 alongside, raw identifiers, macro
bodies, comments and the `include` macros.

## Refute round 2 (2026-11-22): refuted, three findings, all closed

1. **The switch armed through a struct field.** A `[session]` table serialized from a struct with a
   field `writes_armed: true`, then loaded by `project::load`, starts an armed session: no literal
   holds the name. `writes_armed` is now refused everywhere but the read of the switch's position,
   `.writes_armed()` (a `.` before it, an empty call after it): a field, a struct literal's key, an
   assignment and a call given a value are each refused.
2. **Portal's other spelling of the switch.** `project::from_v1` reads a Veredas 1 folder whose
   `commands.json` says `allow_writes` (or `allow_dashboard_writes`) and yields an armed project.
   `from_v1` is refused, and a literal holding either key with `writes_armed`.
3. **A socket by the system's own calls.** An `unsafe extern "C"` block calling `socket`,
   `connect` and `write` sent a frame with every test green; plainly written, not concealment.
   `unsafe` is refused: comissionador has none and needs none.

Also from the round: a doc comment is a `doc` attribute to the lexer, so `/// writes_armed` was
refused as a literal; a doc attribute's text is now a comment's. The reviewed dependencies are
trimmed to what the engine uses (no `toml`, no `serde`). The critic found the engine's own gated
path (an OPC handle's `write_tags`, a channel handle's `send`, `serve::coerce`, `store_now_ms`)
untouched by the reading, the `opc` path's refusal costing only that the engine reaches a rule's
table through the compiled spec's fields rather than `opc::table_of`.

## Refute round 3 (2026-11-22): refuted on a missing assertion, the guard holding

The critic found no ordinary way to arm or bypass the switch through what portal or core export,
nor through the reviewed dependencies: the switch's fields and the gate are crate-private in
portal, a session built by hand starts disarmed, every function that takes a gate is named
`spawn`, core's ungated channel is reached only by a `telegram` path, the workspace's tokio has no
`process` or `fs` feature, and no plant of the suite reads a file live. The one gap: `include_bytes`
was refused but no assertion held it, so dropping it from the list stayed green. Closed: its
assertion, and the list of refused names held equal to the names asserted one by one. The clause's
"starts no worker of its own" said more than the reading enforces (`spawn_blocking`, a
multi-thread runtime pass): it now says what is held, nothing named `spawn`, every worker that
writes being started by one. The engine's cost noted: the OPC UA types cannot be named in its own
signatures (their paths hold `opc`), and a run record cannot use the key `writes_armed`.

## Refute round 4 (2026-11-23): refuted, one finding (low), closed; two corrections

What held: the executable starts a session from the project file alone, the switch set only by
the file's `[session] writes_armed` (Q314 (a)); the record reaches the store only through the
`Plant` door and writes only under its runs folder; only `opc::worker::spawn` and
`channel::spawn` take a gate; the reading of raw identifiers, aliases, globs, `cfg_attr`, inner
and doc attributes; the manifest's dependencies against the reviewed list and the lock file.

1. **Portal's log layer read the plant past the session**: `FileTailSource`, `FamilyTailSource`
   and `SourceSet`, re-exported at portal's root, start a log's reader through `Source::start`,
   named nothing the guard refused; a probe read a log's first line outside any session and every
   guard test passed. `tail`, the three types and the `Source` trait are refused, each asserted.
   `std::fs` is the engine's own (the test and its function files, the runs folder): `fs` is now
   named in `check.rs`, `main.rs` and `record.rs` alone, asserted, and found elsewhere as
   `std::fs`, `tokio::fs` and an alias; a plant's file read in those three is outside what the
   reading can tell, as the clause now says.

Corrections: round 3 said the workspace's tokio has no `process` or `fs` feature. Core's
`async-opcua-client` asks tokio for `full`, so it has both; the guard holds by the names
(`Command`, `net`, now `fs`), not by the features. The clause said every function of core or
portal that starts a writing worker takes a gate: core's telegram channel and fieldbus masters do
not; they are behind the refused `telegram` and `fieldbus` paths, as the clause now says.
