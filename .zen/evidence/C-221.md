## Refute round 1 (2026-11-22): refuted, six gaps closed
A fresh-context refuter ran probes and mutants against a copy of the crate:
1. **An engine bug.** "Always recalculate" did not open a linked workbook whose target is written
   as Excel writes it: a relationship's target is a URI, `sub%20dir/Zone%20list.xlsx` for
   `sub dir/Zone list.xlsx`, and the resolver decoded only http(s) and `file:///`; a Linux
   `file:///tmp/x.xlsx` lost its leading slash. Fixed in the fork as change 12
   (`forks/ironcalc/VEREDAS-FORK.md`), pinned by the fork's unit tests and here by a real file
   linked both ways.
2. "Spelled as Excel shows them" was false: `1e21`, `1e-7`, `-0` and Rust's escaping of text. Now a
   number is spelled by the engine's `number_to_text` (Excel's text form: `1E+21`, `0.0000001`, `0`)
   and a text between double quotes with a quote doubled, line breaks and control characters
   escaped, every other character as it is.
3. Two mutants survived (no evaluation for a file without links; none under the cache): the stored
   values equalled the computed ones. A file whose stored values differ (a host's 555 against a
   cache of 999; a stale product) now shows the computed ones.
4. An unavailable book's reason was never checked, and a corrupt linked book never tried: both
   pinned (`<path> not found`; `<path>: <the reader's error>`, its cache answering, no log line).
5. The log compared numbers exactly while spelling them at 15 digits (`cached 0.3 → live 0.3`).
   Numbers now compare at Excel's 15 significant digits; text exactly, its case included (the
   engine's own comparison folds case, which would hide a renamed signal).
6. An empty text was tested on the live side only: both sides now.
