# C-134 evidence - the raw link and the private network for tests

## Why, and the measurement (2026-11-22)

Raw frames need `CAP_NET_RAW`; no session has sudo. Measured on this machine (the shared notes,
`raw-frames-without-sudo.md`): `unshare -Urn` gives a user and network namespace where a veth
pair comes up and an `AF_PACKET` socket on each end carries a DCP frame whole. Ubuntu 26.10 sets
`kernel.apparmor_restrict_unprivileged_userns = 1`, which moves an *unconfined* process that makes
a user namespace to the `unprivileged_userns` profile, denying every capability inside; the
desktop app runs under `/etc/apparmor.d/claude-desktop` (`flags=(unconfined)`, `userns,`), and every
process it starts carries that label, so the sessions' test runs keep their capabilities in the
namespace. A plain terminal (`ptyxis`, label `unconfined`) does not.

Three members need the step (aranha, maquinar's PROFINET and EtherCAT devices, core's masters
through `tools/mestres`). The proposal, left in the shared notes before the code, put both the
link and the fixture here, within L4 and L5 (maquinar may use aranha; a tool may use anything;
core's own tests cannot, and need not while its masters are tested from `tools/mestres`), to move
into core with the codecs (P-018). No objection was written.

## What the measurements while building settled

- **`unshare(CLONE_NEWUSER)` refuses a multi-threaded process** (EINVAL), and a libtest binary is
  one. The fixture runs the test binary again for one test (`--exact <name> --nocapture
  --test-threads 1`), unsharing in `pre_exec` between `fork` and `exec`, and writes
  `/proc/self/setgroups` (`deny`), `uid_map` and `gid_map` there, so the child is root inside and
  keeps its capabilities across `exec`. Nothing in `pre_exec` allocates: the paths and contents are
  made before the fork.
- **A name that matches no test exits 0 with no test run.** The parent therefore requires a line
  the child prints once the body has run; without it the test fails as "never ran".
- **The child must not go on past the body.** At first the code after `isolated` ran in the child
  too, and a check meant for the host's interfaces read the namespace's. The child now exits once
  the body has run.
- **libtest writes "test <name> ... " with no line break**, so the child's line starts with one.
- **A socket does not hear its own sent frame** (the kernel skips the sending socket when it hands
  an outgoing frame to the packet taps); another socket on the same interface sees it, marked
  `PACKET_OUTGOING`. The test pins both.
- **A packet socket's group and promiscuous memberships do not show among `ip link`'s flags**
  (those are the flags a person sets); the kernel's counts do, in `ip -d link`'s `promiscuity` and
  `allmulti`. The test reads the counts.
- **sysfs shows the namespace that mounted it**, not the caller's: the interface's MAC is asked of
  the kernel (`SIOCGIFHWADDR`) on the link's own socket.
- **A veth pair has no hardware filter**, so it delivers a frame to another host's MAC whether or not
  the link is promiscuous; promiscuity is shown by the kernel's count, not by a frame that only it
  lets through. A real card's filter is outside what a veth pair can show.

`libc` joins `[workspace.dependencies]` (already in the lock through tokio and others): the raw
link's socket, its options and the fixture's `unshare` are the system's C interface.

## While adding maquinar's asks (2026-11-22, evening)

maquinar asked (shared notes) for an EtherType filter of any value and for a link that never reads
back its own frames. Measured on the way:
- **The kernel takes a VLAN tag out of a frame before a packet socket reads it**, on a veth pair as
  on most cards (62 bytes sent, 58 read, the priority gone). The link asks for the tag
  (`PACKET_AUXDATA`) and puts it back where it was, as libpcap does.
- **A socket bound to one EtherType is handed a priority-tagged frame with its tag dropped for
  good** (no aux data either). The filter is therefore a classic BPF program on a socket bound to
  every type, matching the type at byte 12 (tag taken out) or behind a tag still in the frame; the
  socket is created with protocol 0 and bound after the filter, so nothing unfiltered is queued.
- **A frame sent the moment a veth end is set up can be lost** while its carrier comes up (one run
  in three, before). The fixture, and `netns::wait_up`, wait for `LOWER_UP`; twelve runs in a row
  green after.
- The sending socket never hears its own frames (already pinned); `Options { outgoing: false }`
  leaves out every frame this host sends on the interface.

## Refute round 1 (2026-11-22): refuted, six gaps

- **A test whose body never ran passed**: another test's name copied, or a second call in one test,
  ran a body that was not this one, or none. The fixture now requires the calling test's own name
  (libtest names the test's thread after it) and makes one private network per test; both pinned.
- **The filter did not look behind a tag still in the frame**, as on the sending end, nor behind
  802.1ad: it now matches the type behind up to two tags, 802.1Q or 802.1ad, pinned on both ends;
  and it keeps a frame whole (it trimmed one to 65 536 bytes; the link now refuses a frame past its
  buffer as too long, filtered or not, pinned with a 65 549-byte frame at MTU 65 535).
- **The timeout was cut short by a signal and rounded down under a millisecond**, and the outgoing
  skip had no upper bound: the wait is one deadline (`ppoll` to the nanosecond, a signal or a frame
  passed over waiting on for what is left), pinned with a signal at 50 ms, a stream of this host's
  frames, and 900 µs.
- **"Without waiting" was asserted nowhere**: under a full queue (a tbf qdisc at 8 kbit/s) each send
  returns at once and the full queue is refused by name (`QueueFull`).
- **The words claimed more than the code**: loopback hands a host's own frames back as heard, so the
  link opens on an Ethernet interface only; the kernel counts an 802.1ad tag in the 1514; a name the
  kernel would not give an interface is refused as one (`.`, `..`, `/`, `:`, white space).
- **IPv6 off and "the failure says why" were unasserted**: both pinned (the latter by forbidding
  user namespaces inside a private network and asking for one).

## Refute round 2 (2026-11-22): refuted, eight gaps

- **A send that waits passed**: the shallow queue (tbf, 1 ms) drops, so the send got ENOBUFS and
  never reached the socket's own buffer, the one place a packet socket's send waits. A deep queue
  (tbf, 1000 s) is added: every send returns at once and the full queue is `QueueFull` (EAGAIN).
- **The filter's two-tag orders were proven for one**: 802.1ad then 802.1Q, 802.1Q then 802.1ad,
  802.1ad twice and 802.1Q twice, on the sending end and the far end, now.
- **`recv(Duration::MAX)` panicked** (the deadline overflowed the clock): a timeout past what the
  clock counts is no deadline now.
- **The fixture's carrier wait was untested** (every test waited itself): the body now first finds
  every end `LOWER_UP`.
- **The buffer did not count a tag it put back**: a 65 540-byte tagged frame was handed back, and a
  refusal named the length without the tag, in the send's words. The limit counts the tag, the
  refusal names the whole length in its own words (`TooLongHeard`), and frames of 65 536 bytes are
  heard whole, tagged and not.
- **The name rule was Unicode's white space, not the kernel's**: the kernel names interfaces with
  U+2003 and U+0085 and refuses a byte 0xA0 (`à0`). The rule is now the kernel's, byte by byte.
- **A filter on a tag's own type kept another type on the sending end only**: refused now.
- **"Whether this host sent it" meant "left by this interface"**: the words say so.
- Also: a frame handed back holds its own length, not the buffer's 65 536 bytes of capacity.

## Refute round 3 (2026-11-22): refuted, two defects and five gaps

The critic retried the earlier rounds' attacks (all holding) and found, now answered:
- **A link that leaves out this host's frames failed on an over-long one** (a defect): the length
  was judged before the frame was known to be outgoing, so another socket's 65 537-byte send ended
  the wait with `TooLongHeard`. An outgoing frame is now passed over before its length is read.
- **The filter looked one tag deeper on the far end** (a defect): the kernel takes the outer tag
  out there, not on the sending end, so a three-tag frame of the filter's type was kept on the far
  end and dropped on the sending one. The filter now loads the kernel's "tag taken out" mark and
  allows one tag fewer in the frame when it is set: both ends drop it.
- **The fixture's carrier wait could not fail, and did not prove what it was for**: a veth end
  shows `LOWER_UP` at once, yet a frame sent at once from the end raised first was lost 6 and 4
  times in 60 without the wait (0 in 60 with it, by the time `ip` takes to start). Measured here:
  `ip` shows the end up, its queue `noqueue`, from the first look. The fixture now proves each pair
  carries a numbered probe each way (`netns::wait_pairs`), a test runs the fixture twenty times with
  the first frame sent at once, and a pair whose queue drops everything fails the wait by name.
  One part is not proven: that the fixture stops only at the latest probe sent (a mutant stopping
  at any probe survives); it matters only for a probe more than 50 ms late, which a user namespace
  cannot stage (no delaying queue loads there).
- **Gaps**: another type behind two tags was never sent (a mutant keeping any two-tag frame
  passed); bytes 10 to 13 were untested in names and the count said twelve of eleven (fifteen
  now); a late signal's wait had no upper bound held (a mutant restarting the full timeout after a
  signal passed); the read time was checked on a frame sent before the wait (a mutant stamping the
  wait's start passed).
Before this commit, ten mutants of this round's points were run under the suite lock: nine killed,
the one named above surviving.

## Refute round 4 (2026-11-22): refuted, one defect and seven gaps

The critic found the earlier rounds' attacks holding (530 signals through a 300 ms wait ending at
300.07 ms among the new ones) and answered here:
- **A link leaving out this host's frames lost a frame from the wire behind a burst of them** (a
  defect): the frames were left out in this process, after the kernel had queued every one into the
  socket's buffer; three thousand of them filled it, and the next frame from the wire found no
  room. The kernel now leaves them out (`PACKET_IGNORE_OUTGOING`, set before the bind), and a test
  sends the burst unread, then one frame that must be heard.
- **The fixture's "each way" was proven one way**: a pair dead from b0 to a0 passed with the second
  probe removed. A test drops everything on b0 and expects the failure naming that way; both
  failures are now bounded, after 5 s and before 8 (a 20 s mutant passed).
- **Nothing pinned that a link opened while traffic flows hears only its interface and its type**
  (a socket created on every type, or bound before its filter, is handed frames of other types and
  of other interfaces before the bind): links are opened over and over while two interfaces flood,
  none handed a frame it should not be.
- **Frames between 14 and 59 bytes, tags of a zero TCI, and a tag the kernel holds on the sending
  end** (a bridge tagging on its way out) were never sent: each now crosses whole, the last two put
  back by a plain and a filtered link.
- **"To the microsecond" was bounded at 50 ms**: the shortest of three 900 µs waits is now held
  under 5 ms (a wait rounded up to a 10 ms tick passed).
- Wording: the two names the kernel gives are opened in a private network, not on the host.
Before this commit, eight mutants of these points were run under the suite lock: all killed.
