# C-013 — Message bodies captured into named fields — lab notebook

## The port (2026-11-05)

From Veredas 1's `crates/veredas-telegram/src/capture.rs` and its inline tests, now
`src/telegram/capture.rs` and `tests/telegram_capture.rs`, unchanged but for paths.

## Refute round 1 (2026-11-05)

The code held on every input the critic tried; the tests did not prove it. Refuted on eight
points, each now pinned with exact values: a big-endian read checked only as "different"; U16,
I32 and Hex never read; no field starting inside the body and running past it (a check on the
start alone would slice past the end); a repeat cap equal to the default; a bad-pattern test in
which every pattern was bad; a collision tested against the payload regex only; a barcode cap that
changed nothing on its input and no barcode at exactly the minimum length; the infeed fallback to
the operator id and a big-endian scanner request never asserted; one read status of four checked.

Held: unmeasured dimensions field by field, the status byte skipped, barcodes stopping at the NUL
padding and capped at 16, Ascii stopping at NUL, huge offsets refused for every type, repeats
numbered from 1 in match order, a short ISPC block zero-filled. Left: `FieldType::Ascii` is
documented as trimmed text but `asciiz` trims only the end.

## Refute round 2 (2026-11-05)

All eight round-1 gaps closed. Refuted on one more: no repeat pattern without a capture group was
ever run, so the "else the whole match" half of the rule was unproven (a mutant reading group 1
only gave blanks, which the sort plan reads as a no-read; one indexing `caps[1]` panicked). Pinned
with `\d{6}` over two barcodes. Left: `Other(b)` checked for 0 only; `min_len` counts bytes of the
decoded text.

## Reshaped (2026-11-05): the rules engine alone

After the operator's decision (`docs/questions.md` Q8) the GENIBELT scanner path
(`scanner_parcel`, `BarcodeFormat`, the read statuses) left core with its tests; what remains is
the configuration-driven `CaptureSpec`, and the clause states only that.

## Refute round 3 (2026-11-05)

Every reading rule held. Refuted on the clause's new words: "configuration rather than code" had
no test reading a spec from configuration (removing `Deserialize`, or a `max` default of 0, would
have passed). A spec is now read from TOML with its optional keys left out, equal to the literal
one and extracting the same map; a misspelled key or type name is refused (`deny_unknown_fields`
on the three tables).
