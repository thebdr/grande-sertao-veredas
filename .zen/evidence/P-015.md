The spike's plan, its seven points and how each is judged are in `docs/oficina-plan.md` ("The

## The toolchain, measured on the Linux machine (2026-11-22)

Checked against the upstream servers by their metadata and by HEAD requests; no Qt downloaded.

- The machine had no Qt, no CMake, no Xvfb, no clang. It has gcc/g++ 15.3, ninja, Rust 1.100,
  whose default linker on `x86_64-unknown-linux-gnu` is `rust-lld` (cxx-qt's cargo-only build

- aqtinstall 3.3.0 cannot read Qt 6.12's Windows repository: `aqt list-qt windows desktop --arch

  headers KDDockWidgets' Qt Quick side needs on Qt 6.10 and later cannot be installed on this

- Upstream versions: cxx-qt 0.10.0 (2026-08-24, MIT OR Apache-2.0); KDDockWidgets 2.5.1

- Hypervisors here: QEMU/KVM through libvirt only. No Hyper-V, VMware or VirtualBox.
- Installed in the home folder for the survey: `uv` 0.13.9 (Astral's release, SHA-256 checked),
  to run aqtinstall, since the system Python has no pip.

## What the TOML editing library does (toml_edit 0.25.20, probed 2026-11-22)

- An LF text parses and renders back byte for byte.
- A text with CR LF endings renders with LF: the line endings are not kept.
- A leading byte-order mark is accepted and dropped from the rendering.
- A value's trailing comment and the spaces around it live in the value's decoration: replacing
  the value with `doc[key] = value(x)` loses them (`port = 504`); replacing it with the old
  decoration carried over keeps them (`port = 503  # the port`).
- Spans are kept by `toml_edit::Document::parse` and dropped by `into_mut`, so the document is
  edited as a `DocumentMut` and parsed again for the form's lines.
- A parse error carries a byte span; the library's own text gives the column in characters
  (`a = "😀" x` fails at column 9), where both views count UTF-16 units (column 10).

The document (`spikes/oficina/model/src/document.rs`) answers each: it works on LF text without
the mark and writes both back as read (a file with both endings is written with the one more
lines use, LF on a tie), carries the old decoration onto every edited value, and reports columns in
UTF-16.
