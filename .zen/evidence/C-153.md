# C-153: orcl-interp, the machine

## What it is, 2026-11-25
The first step of `docs/orcl/interpreter.md` ("Built in this order"): the program as the front end will lower it,
and the machine that loads and runs it, tested on stable with programs built by hand in Rust (fixture first). No
program file, no front end and no engine integration yet; each is a clause of its own.

How the tests stand against the clause:
- **Operations** (`tests/ops.rs`): each run in the machine and compared with Rust's own operation on the native
  type. The reference is written with the native type's methods (`wrapping_add`, `checked_div`,
  `overflowing_mul`, `wrapping_shl`, `as`), never with the machine's own `Int::wrap`, so a mistake in that helper
  shows. MIR's shift takes its amount modulo the width (`rustc`'s `BinOp::Shl` documentation); `wrapping_shl` on
  the amount's low 32 bits is the same for widths that are powers of two, which is what the reference uses.
- **The machine** (`tests/machine.rs`): a loop counted instruction by instruction (nine a round, seven around it),
  so a step that skipped or doubled an instruction shows; a run stopped after budgets from 1 to 333 and a clone of
  the machine taken inside the callee, both finishing with the original's result, memory and count.
- **The blocks** (`tests/blocks.rs`): `Ton::scan` and `RTrig::scan` lowered by hand, the way rustc lowers them at
  opt-level 0 (`&&` as a switch, `get_or_insert` returning a reference that is then read), run beside
  `orcl-std`'s native blocks over 60 traces of 400 scans with steps back in time and changing presets, and over
  every 10-scan trace of the edge.
- **No allocation** (`tests/alloc.rs`): a global allocator counts this thread's allocations while entries run,
  fail three calls down and stop midway. Planting one `vec![0u8; 1]` in `Machine::step` made the test fail with
  37 600 counted, so the count is live.
- **The root** (`tests/root.rs`): the crate root line by line, and every file of `src/` read (their list compared
  with the folder's) for an attribute that allows a lint back, `cfg_attr`, `#[path]`, `include!` or `unsafe`.

Not claimed: that the loader refuses every ill-typed program (it refuses those the clause lists, each tested);
that a float operation's NaN carries the same payload as native (NaN is compared as NaN).

## Refute round 1 (2026-11-25): refuted, high weight; answered
At 68376f68. The critic found a defect in the code, not a mutant: `State` derived `Clone`, and a cloned `Vec`'s
capacity is its length, while a call checked the stack's depth against the vector's capacity. So a copy of a
machine failed at its first call deeper than it was copied at (`Internal("a stack deeper than laid out")`), and its
first run allocated. The test copied only inside `sum`, which makes no call. Answered: the machine's `Clone` is
written by hand, giving every buffer of the copy the room the layout fixed at load, and the depth is checked
against that room, never a vector's capacity. Now a copy is taken at every instruction of a run, at every depth, and
of an idle and a just-started machine through a chain five deep, each finished alike; and the allocation test runs
a copy. Undoing the room in the copy fails the allocation tests.

Mutants that survived, each answered by a test (the critic's kill-tests, adopted): an index local read from the
entry's frame instead of the running one (high: `a[i]` in a callee); `f32` negation dropping its minus (high);
`f32 as f64` forgotten; the stack sized by the first callee only; `Busy` only after a failure; a region of another
type taken by reference; an allocation planted in a switch or an aggregate (the allocation test now runs every kind
of instruction and every core operation); a call's argument or result type unchecked; a call to no such function,
too few arguments, an unchecked next block of a call, a switch or an assertion; a duration's nanoseconds unchecked
in a region; an entry's unwritten local caught on the first run only; integer to `f32` rounded twice; `f32`'s
default as `-0.0` (the test compared with `==`, under which `-0.0 == 0.0`, and now compares bits); a checked shift's
`None` keeping an earlier payload.

Sentences that a test claimed and did not hold: "every refusal of the loader above" (20 of the loader's 37 reasons
were never asserted; now every reason is met by a test and a scan of the loader's source fails for one that is not,
five being out of any program's reach and named); "every budget from 1 to 333" (six budgets were run; now all 333);
"a reference writing its caller's place" (the test wrote a host region; now a caller's own local too). `run(0)`
returned `Idle` while an entry ran; it now says the entry stands, or gives a failed one's error.

The allocation counter also counted across test threads; it now counts each thread's own allocations.

  reading `layout.rs` alone (now also every `reason:` of `machine.rs`); a reference to the type one past the last
  (the test pointed further); an operation's own integer type and a checked shift's option payload unchecked

  panic in `Duration::new`; now a duration read through another variant is the internal error it should be); an

belongs to the target's settings (`docs/orcl/interpreter.md`, "Memory").

## Refute round 3 (2026-11-25): refuted, moderate weight; answered
At f79d1309. All 64 earlier mutants that should be killed are killed; round 2's `g03` (a reader reserving its
count) passes, contrived, as round 2 left it. New survivors, each with a test now (the critic's kill-tests):
- **moderate**: the stack's frames counted along the callee deepest in slots instead of on their own (every test's
  call graph had its slot-deepest callee also deepest in frames; now `main` calls a large callee and a chain three
  frames deep, in the machine and its copy); and an enum variant's fields placed at one slot each (every variant of
  several fields had fields of one slot; now `B(Duration, u8)`'s second field is read where it was written).
- **low**: an array aggregate's parts counted but not typed; a region's enum with a discriminant of another integer
  type accepted.
- **contrived, answered all the same**: an integer switch's target values unchecked (only the bool case was tested).

A defect of the code, not a mutant, on a file a sender damaged or built: the nesting limit was met only when a
program listed its types outermost first, since the sizer remembers what it has sized; listed innermost first, as
an interner does, 100 000 types nested loaded, and then the check of a constant of that type recursed as deep and
overflowed the thread's stack, aborting the process. The sizer now records every type's depth and refuses one past
256 whatever the order, which bounds every walk of a type's parts. Also: a constant of `[[(); u32::MAX];
u32::MAX]` (a file of 130 bytes) made loading run for hours, its elements of no slot checked one by one; they are
now checked once. Found while answering: two variants with one discriminant were found by comparing every pair,
so an enum of many variants could stall loading; they are now found by sorting.
