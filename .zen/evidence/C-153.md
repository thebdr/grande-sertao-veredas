# C-153: orcl-interp, the machine

## What it is, 2026-11-25
The first step of `docs/orcl/interpreter.md` ("Built in this order"): the program as the front end will lower it,
and the machine that loads and runs it, tested on stable with programs built by hand in Rust (fixture first). No
program file, no front end and no engine integration yet; each is a clause of its own.

How the tests stand against the clause:
- **Operations** (`tests/ops.rs`): each run in the machine and compared with Rust's own operation on the native
  type. The reference is written with the native type's methods (`wrapping_add`, `checked_div`,
  `overflowing_mul`, `wrapping_shl`, `as`), never with the machine's own `Int::wrap`, so a mistake in that helper
  shows. MIR's shift takes its amount modulo the width (`rustc`'s `BinOp::Shl` documentation); `wrapping_shl` on
  the amount's low 32 bits is the same for widths that are powers of two, which is what the reference uses.
- **The machine** (`tests/machine.rs`): a loop counted instruction by instruction (nine a round, seven around it),
  so a step that skipped or doubled an instruction shows; a run stopped after budgets from 1 to 333 and a clone of
  the machine taken inside the callee, both finishing with the original's result, memory and count.
- **The blocks** (`tests/blocks.rs`): `Ton::scan` and `RTrig::scan` lowered by hand, the way rustc lowers them at
  opt-level 0 (`&&` as a switch, `get_or_insert` returning a reference that is then read), run beside
  `orcl-std`'s native blocks over 60 traces of 400 scans with steps back in time and changing presets, and over
  every 10-scan trace of the edge.
- **No allocation** (`tests/alloc.rs`): a global allocator counts this thread's allocations while entries run,
  fail three calls down and stop midway. Planting one `vec![0u8; 1]` in `Machine::step` made the test fail with
  37 600 counted, so the count is live.
- **The root** (`tests/root.rs`): the crate root line by line, and every file of `src/` read (their list compared
  with the folder's) for an attribute that allows a lint back, `cfg_attr`, `#[path]`, `include!` or `unsafe`.

Not claimed: that the loader refuses every ill-typed program (it refuses those the clause lists, each tested);
that a float operation's NaN carries the same payload as native (NaN is compared as NaN).

## Q230's change (2026-11-26): the stack is the host's
The architect ruled Q230 against what was taken (a function reaching itself refused at load): a program runs on a
stack of a size the target's settings give, laid out at load, and a call past it is the fault 502. The load no longer
walks the call graph, so `LoadError::Recursion` and the deepest-path sizing are gone, with the walk's one reason
("too many functions", which no program could meet). `Machine::load` takes the stack's size in slots and lays it out
after the regions, the memory being the regions and the stack whole; a call whose callee's frame would end past the
stack, or that would hold more frames than the stack has slots (a frame of no slot counting one, so the frames'
buffer is sized at load too), is `ErrorKind::Stack` at the call, the machine standing there with nothing written; an
entry whose frame the stack cannot hold is `HostError::Stack` at its start. Slots, not bytes, so a program reaches
the same depth wherever it runs whatever a slot's size there.
