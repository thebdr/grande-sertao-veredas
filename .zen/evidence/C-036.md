# C-036 evidence - log families

## The design (2026-11-07)

Veredas 1's `family.rs` and `tail/family.rs` as they were, with their three invariants (a family
born after attach is all new content; never read an adopted active while older retirees are
unconsumed; a sweep skips the files a live cursor reads, by identity). The unit tests of the
family spec moved from the module into the clause's test file, so the clause links one file.

The plant's writer is two things here. The bench's emitter (C-025) writes the files a plant
writes, rotating cleanly on a line count, and its `family_shape` gives the spec that reads them:
the test attaches before the first file, lets the emitter rotate several times in UTF-8 and in
UTF-16, and requires the received lines to equal every line of every file on disk in family
order, read back independently of the tail. The rotation races a plant logger shows (a straggler
landing late in the retired file, a torn write, a fixed-name rename) the emitter never produces
on purpose (C-025: never append to an existing file), so a writer in `tests/common/mod.rs` plays
them, as Veredas 1's test kit did. That writer is the plant, not a stand-in for the tail: what
is under test reads real files on a real disk either way.

## Refute round 1 (2026-11-08): refuted

Two gaps. A keyless family (no `date`, no `idx` group) was listed by modification time but
followed by name: the tail ranked members without the time, so a newer file with a smaller name
was never the newest, history leaked and lines were lost. No rank holds for a keyless family
against a straggler (a late line into a retired file moves its time), so following is refused by
text and the listing keeps its time order, now asserted exactly. And the emitter accepts an hour
in a file name; the reader read the date back without the minutes it had no format for, so every
hour of a day shared one key and the next hour was never followed: an hour without minutes is
now the start of the hour, and a pattern whose date specifiers are split by other text (which
the reader could never read back whole) has no shape. Both pinned. The same round brought the
attach guarantee of C-035 to families: the start returns once the folder is listed or the backfill
located.

## Refute round 2 (2026-11-08): refuted

Four gaps. The tests shared module pulled the plant helper, which needs the session, so the
linked test no longer built without the store feature: the helper is gated to it. A fixed-name
family whose active file was absent at the start waited the whole attach bound and then opened
the active at its end, losing the first line: a listing with no active signals the attach, and
the active, when it comes, is new content read from its start. The keyed check was syntactic: a
date token that parses on no member left every key empty and the tail followed by name while the
listing ordered by time; a pre-existing family on which no key parses is refused by text, and the
clause now states the tie rule (followed by name, the lower name history: the keys must separate
generations). A twelve-hour hour got no minutes filled: it does now.
