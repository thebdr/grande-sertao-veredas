# C-027 evidence - message bodies written from named fields

## The design (2026-11-06, for the bench, kept for portal)

New in Veredas 2: Veredas 1's bench rendered a telegram body either as a text template (the
log emitters' engine, `{ts}` and drawn values) or as typed-in hex, and its typed catalog encoded
each message in code. With the catalog out of the suite (Q8), a body is written by rules:
`telegram::compose`, the inverse of `telegram::capture`, sharing its `BinaryField` and
`FieldType` so one field list serves both directions. A text template with `{name}` placeholders
(`{{` and `}}` literal), binary fields at offsets, a pad byte, a fixed length.

Choices, each pinned by the test:
- the template is parsed when the spec compiles (an unclosed brace, a stray `}`, an empty
  placeholder refused by character), not met on the first message;
- an integer is read from decimal text alone (no hex, no fraction), held to its type's range;
- text is padded with NUL to its length and refused when longer, never truncated; at length 0
  it is written as given, which is how an open-ended trailing text field is declared;
- hex is parsed as `framing::parse_hex` does and held to its length; at 0, as spelled;
- the body never grows past `MAX_BODY` (the framing's 16 MiB ceiling): an offset there is
  refused before any arithmetic grows the body, so a field at `usize::MAX` cannot wrap;
- `names` says what a body needs, so a rules engine can check a message's sources against it
  when a file loads rather than when the first message fails.

## Refute round 1 (2026-11-06): refuted

The round trip broke for what the clause itself endorsed: a text or hex field at length 0 was
written open-ended, and capture (which reads its length) read it back empty; an embedded NUL
and trailing spaces came back shortened; two overlapping fields read back as something else;
and the test took `+7` on a U8 while the clause said a sign only where the type takes one. Now:
a text or hex field declares its length (0 refused where the spec compiles), fields may not
overlap, a NUL inside text is refused, an unsigned type refuses `+` and `-`, a placeholder's
name is read trimmed and a `{` inside one refused, a `len` over the ceiling and a template or
field that cannot fit `len` are refused at compile (a body would have been padded to
`usize::MAX`: the test found that allocation). Trailing whitespace is the one stated exception:
capture trims it. Held: the range edges in big-endian, `1_0` and `1e1` refused, the exact
ceiling, `names` order, `pad = -1`, `{{{a}`.

## Refute round 2 (2026-11-06): refuted

The compile-time checks ran only with a fixed length, so a spec with a field at the ceiling and
no `len` loaded and could never write; and a field written over a placeholder's value wiped it
silently. The literal-text and field-end checks now run against the length, else the ceiling,
with `checked_add` (two fields at the top of the address space no longer read as apart by a
wrapped sum); a field over a placeholder's value is refused when rendered, over literal text it
overwrites, as stated. Held: names trimmed and listed once, UTF-8 at exact length, the ceiling
with a placeholder-only template, a Unicode minus refused, no render without `Compose::new`.

## Refute round 3 (2026-11-06): holds

Both round-2 gaps closed and held under probing: a field across the literal/value boundary, one
spanning two adjacent placeholders (the first found reported), one ending exactly where a value
starts (literal text only, written), an empty value under a field (nothing lost, written), a
placeholder-only template over `len` refused at render, `{a }{a}` one name, `check_fields`
reached by the catalog through `Compose::new` alone. Outside the clause, fixed anyway: the
placeholder overlap named the field's start, not the first shared byte (`AB{a}` with a U16 at 1
said byte 1, the literal `B`; it says 2 now, pinned).

## Reconcile (2026-11-07): the inverse named

The near-duplicate check against C-013 found the two engines distinct layers sharing one field
list; the clause now cites C-013 and states the round trip in capture's spelling (an integer in
plain decimal, hex as uppercase pairs, text without its trailing whitespace) rather than "field
for field"; C-013 names its inverse. The code's doc comments on the shared field type say it
is written as well as read.
