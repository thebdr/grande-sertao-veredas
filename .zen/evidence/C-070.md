# C-070 evidence - the controller's state text

## The design (2026-11-22)

Read before deciding: `docs/controlador-plan.md` "The state" (the model, the table, the order,
the seven examples, health); the deliverables' B5 and K1 to K6 (`docs/briefing/deliverables.md`);
the review's entries 17 to 21 (`docs/briefing/review.md`), none ruled (Q31); Q45's readings.

The structure makes a wrong state impossible to build rather than refused at writing: layer 1 is
an enum (`State`) whose variants carry only their own state's reasons (`StopReason`,
`StartupReason` with the `StartupPhase`, `HoldReason`, `FaultReason`), and a maintenance
request's fixed urgency is no field (`MaintenanceRequest::DeviceMissing` is urgent by its
variant). So the writer is total, and the reader's job is to refuse every text no state writes.

The reader is held to be the writer's inverse in both directions. Every spelling has one form:
the reader refuses a second space, a missing `()`, `+1`, `01`, `0x1`, `1_0`, `-0`, a lowercase
hexadecimal escape, a printable character escaped, a raw control character, an absent condition
written with a zero count, terms out of order, a reason of another state, an `id` that is not its
row's. Without that, two texts would mean one state and a screen comparing texts would disagree
with one comparing states.

Reality here is the plan's text and TOML: the test copies the plan's table and examples (each
example read to the state it means and written back byte for byte), and `toml` (the crate core
already reads its files with) reads every value the writer writes, and every term's arguments as
an inline table, as the state holds them. The string escapes were run over every Unicode scalar
value, chunk by chunk through `toml`, then one by one against the list's exact spelling.

The readings taken are Q100's, each marked `DECISION PENDING` where the code leans on it.

## What the test does not cover

The text's meaning to a controller (which state follows which, when a condition is raised) is
controlador's; the register block a Modbus client reads (the review's entry 20, b) is not built;
nothing yet stores or publishes the text.
