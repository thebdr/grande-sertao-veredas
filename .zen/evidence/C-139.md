# C-139 evidence - the wire seam

## The seam, the capture file and the hub (2026-11-23)

Phase 4's first piece (`docs/aranha-plan.md`): the one seam the listener, fusion and asking will
sit on, with its three kinds. Absorbed from Veredas 1's `wire.rs` and `pcap.rs`
(`/home/thebdr/code/Veredas`, branch `supervisao-plan`), changed on the way:
- **Stamps in nanoseconds**, not milliseconds: a raw link's clock and a nanosecond capture keep
  their precision, and the writer writes nanosecond pcap (Veredas 1 wrote microseconds).
- **A frame keeps its length on the wire**, so a capture cut by its snapshot length says so
  (`Frame::is_cut`), and writing it back keeps it.
- **A capture cut short keeps the frames before the damage**, named, where Veredas 1 refused the
  whole file: a capture still being written is read up to where it stops, as tshark reads it.
- **The memory hub waits** up to its timeout (Veredas 1's returned at once, which a listener's
  loop would spin on), bounds each port's queue and counts what it lets go, and a dropped port
  leaves the segment.
- **The seam never hands back a frame this host sent**: the raw link behind it passes them over
  within the same wait, so a listener's own sends stay apart from what it heard.
- Typed errors with messages, the pcapng refusal named apart from another magic number.

Spiked against tshark 4.6.6 before the tests were written (seventeen hand-made files, and
tshark's own rewrites with `-F pcap`, `nsecpcap` and `pcapng`):
- It reads major version 2 and 3, refuses 1 ("major version 1 unsupported"); ignores the
  snapshot length (a 60-byte frame under a snapshot length of 0 or 20 read whole); reads a
  fraction past a second ("Fractional second 1500000000 is invalid") and a length on the wire
  under the bytes kept ("Frame length is less than captured length") with a complaint each; reads
  the frames before a record cut in its header or its bytes and says the file "appears to have
  been cut short in the middle of a packet"; refuses another link type's frames as Ethernet;
  takes a link type with the check sequence's bits set as Ethernet, the frames as recorded.
- **Its writer counts seconds as signed**: a stamp past 2038 (2 147 483 648 s) fails its rewrite
  ("An error occurred while writing to the file ... Success.") though its reader reads stamps to
  2106 (4 294 967 295.999999999 read). The conversion test keeps its stamps inside 2038; the read
  test holds the last second a capture counts.

Before the first commit, 35 mutants of `pcap.rs`, `hub.rs` and `mod.rs` (each bound, each
byte-order and resolution choice, each header field's place, each refusal, the replay's end,
the hub's own-frame rule, queue bound, stamp, wake-up and leaving, the raw link's pass over its
host's frames and the seam's length check before the socket) were run against the tests: all
35 killed, one only after a test was added (a last record keeping no bytes, read by tshark too).

The clause shares the word "capture" with portal's capture rules (C-038, named regex groups read
from text lines): a different capability, cross-referenced in the clause.
