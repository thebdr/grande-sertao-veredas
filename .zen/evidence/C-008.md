# C-008 evidence - the shared types

Ported from Veredas 1's `veredas-core` (`lib.rs`: `SourceId`, `now_unix_ms`; `sample.rs`:
`Value`, `SeriesRef`, `Sample`; `store.rs`: `SeriesType`). Bodies unchanged; added `PartialEq` on
`Sample`, `Hash` on `SeriesType`, and `Quality` (new). `C-007.md` has the port's reasoning.

## Refute round 1 (2026-11-05)

Refuted: "ordered by source then series" was not proven. The only fixture,
`[("b","a"),("a","z"),("a","b")]`, sorts the same by the shown `source/series` text, so an `Ord`
comparing `to_string()` would have passed. The two orders differ when one source id extends
another with a character below `/` (`plc` vs `plc-2`, `a` vs `a.b`). The derived order was right;
the test now pins `plc/temp` before `plc-2/temp`, `a/z` before `a.b/c`, and that the shown strings
sort the other way.

Pinned on the way (held, not refutations): a sub-millisecond stamp rounds down in both the
numeric view and the index (`00:00:00.0009` is 0, `23:59:59.9995` before the epoch is -1), now in
the clause; an int wider than 32 bits keeps its value.

Held: times at chrono's extremes (both under 2^53, exact as f64), ints beyond f64 precision
(rounding is inherent to an f64 view, the clause promises no more), a leap second (`23:59:60.500`
indexes as the next second's `.500`, as unix ms do), ties (derived `Ord` agrees with `Eq`), special
floats on display (identical to Veredas 1), empty names, two tags with one shown form
(`("a/b","c")` and `("a","b/c")`: unequal, the clause claims no unique shown form), formatter
flags ignored, the exact UTC literals (a local-time reading would fail on any non-UTC host; the run
was recorded at UTC+1), `now_unix_ms` bracketed by the system clock.

Open for a later clause: if portal addresses tags by their shown `source/series` (its write
whitelist, its REST paths), it needs an escaping rule or a ban on `/` in source ids.

## Refute round 2 (2026-11-05): holds

Each new claim tried against a wrong implementation: sorting by shown text, by series first or by
source alone each fail; truncation, round-to-nearest, rounding up and fractional milliseconds each
fail the sub-millisecond pins; the index and the value view are pinned on the same stamp.
Wording: "on the same millisecond axis" read as "a stamped and an arrival-indexed sample of one
moment line up" would hold only for a UTC source clock; the clause now says the value's axis.
Left: `now_unix_ms` on a clock before 1970 rounds toward zero while stamps round down (at most
1 ms, on a host clock nobody runs).
