# C-202 evidence - the engine, live

## The design (2026-11-22)

`docs/comissionador-plan.md`, "How a run meets the plant", carried out:

- **One door to portal** (`plant::Plant`), its one implementation over a session's `Live` in this
  process (Q313 taken): the catalog from `DuckStore::list_tables` (a table with portal's time
  column, its value columns typed from the engine's own type names), rows of a window from
  `query_rows` (newest first, paged by the store's cap, turned oldest first), the latest value of a
  column from the newest rows back past holes, a write through `Live::opc_handle(..).write_tags`
  (the tag found by its rule's name and its series in the compiled spec, the value coerced by
  `serve::coerce`, a refusal read as "may have reached the plant" by `serve::refused_code` 504),
  a send through `Live::channel_handle(..).send`, the switch read by `Live::writes_armed`. Nothing
  of the OPC UA stack is named in the crate (C-200 refuses the `opc` path): its types are reached
  through the spec's fields.
- **The clock is the store's axis.** A wait gathers every row of the tables its condition reads,
  from the clock on, in stamp order, applies each to the values it holds (initialised from the
  latest at the clock) and evaluates at that row's stamp; the first stamp at which it holds is the
  step's end. An await takes the first row stamped after the clock whose `where` holds, the row
  bound to its name while the condition is judged. Live, the rows are read up to 250 ms before
  the machine's now (the pump flushes every 50 ms), polled every 50 ms; a write moves the clock to
  the moment the plant answered. A replay reads the same way over the window, the window's end
  its horizon (C-203).
- **Outcomes and routes** as the reference says; a retry counted per route (the step and the
  route's place in the file) per run, never reset (Q316); spent, the step fails with the reason,
  routed once more by its `on fail` unless that line was the retry spent.
- **Bounds:** the run's `timeout` bounds every wait without its own; a step the run stops inside
  (the tester's stop, the bound, a replay's window) is recorded with no outcome; a run of more
  than 100 000 steps, or a script or a call of more than ten million statements, ends, so no file
  hangs the engine.
- **Shown values** are the suite's (core's `Value` displays a float by Rust's shortest round trip):
  the worked example's `margin` is `0.050000000000000044`.

## What the build met

- **The worked example's function follows destination 4.** A fixture whose replies name another
  destination makes `ItemRoute` wait out its 60 s bound: no outcome for 4 ever comes. The test of
  the failing path calls it with the destination the replies name.
- **A name nothing assigns is the check's, not the run's.** `report ghost` is refused before any
  run; a report's "no value yet" is for a name the path taken never reached.
- **`/` gives a number.** A function whose output is `int` and computes `x / 2` ends in error at
  the output's type; `x - 4` stays whole.
