# C-094 evidence - search over logs at rest

## What it absorbs and what it leaves (2026-11-22)

Veredas 1's `veredas-core::grep` (the grep tab's engine, 1 182 lines on ripgrep's crates) carried
as portal's `grep` module, on the briefing's word that the grep engine is on Oficina's first-release
list (Oficina embeds a portal and shows it; Q14 keeps portal free of a desktop UI). Carried: the
query of several patterns combined per line with NOT, AND, OR and XOR, the literal, case and
whole-word options, the tree, file-list and family scopes, the context lines and breaks, the size
guard, the binary skip, the per-file and total caps, the cancel and the live totals, the events
streamed over a channel. Left:
- **`fancy-regex`**: portal's rule is one syntax across the suite's rules, `regex`; a pattern with
  lookaround or a backreference is refused by the engine's own words.
- **ripgrep's crates** (`ignore`, `grep-searcher`, `grep-regex`, `globset`): a file is decoded
  whole by portal's own decoder (C-035's detection, so a plant whose tails read right greps right,
  where Veredas 1 transcoded only some files) and searched line by line with `regex`; the tree is
  walked in name order (Veredas 1 walked in parallel, its order the scheduler's); masks are plain
  globs with `*` and `?`. No new dependency, and the light build keeps the grep.
- **The highlight engine** (`highlight`): the spans carry each match's pattern for a highlighter;
  drawing is the workbench's.
- **Not carried on purpose**: replace. Read-only by design, as Veredas 1 had it.

## Choices

- A break only when context is asked (grep prints `--` only then); a first version broke between
  two matches with no context, which the test caught.
- A binary file is one with a NUL in its first 8 KiB unless the head reads as UTF-16 (its zeros are
  text): skipped quietly and counted, searched when asked.
- A cancel is checked before each file and every 4 096 lines inside one.
- The whole file is read into memory before it is searched; the size guard bounds that.

Thirteen mutants each turn the test red (xor as or, the negation ignored, a break without context,
the binary guard off, UTF-16 taken for binary, either cap off, the cancel unheard inside a file
(first surviving, killed once the test cancelled inside one large file), the whole word off, an
overlap kept, the masks ignored, the tree unsorted, the context before dropped).

## Refute round 1 (2026-11-23, at 713e3ed): refuted, six gaps

1. **Decoded otherwise than the tail**: the grep fed a whole file to the decoder at once, the tail
   feeds it in 64 KiB slices, and the decoder settles UTF-8 or CP1252 on the slice holding the
   first byte past ASCII. A file opening in UTF-8 with one CP1252 byte 71 KB later read as UTF-8
   in the tail and as CP1252 in the grep, `Produção` found by neither the eye nor the query. The
   grep feeds the tail's own slices now (`tail::READ_CHUNK`), and the test compares its lines with
   the live tail's for the same file.
2. **Whole word inverted at a pattern's non-word ends**: `\b(?:p)\b` matched `-5` glued in `a-5 b`
   and missed it alone. Built on the engine's half word boundaries now (`\b{start-half}`,
   `\b{end-half}`): standing apart from word characters on both sides, as Veredas 1's `word(true)`.
3. **`?` matched a byte**: an accented letter is two. Masks are matched by character now.
4. **Links followed**: a `loop -> .` searched one file 41 times, a `latest ->` folder would be
   searched twice. The walk follows no link, to a folder or a file, as Veredas 1's
   (`follow_links(false)`, files only).
5. **The refusals' words unasserted**: the engine's own words are asserted now (an unclosed group,
   look-around not supported).
6. **"Opened for reading alone" unasserted**: a read-only file is in the tree test now, searched
   with no error.

Seven mutants, each red now: the engine's words dropped from a refusal, every file opened for
writing too, the whole file decoded at once, the whole word by `\b`, masks by byte, links to
folders followed, links to files read.

## Refute round 2 (2026-11-23, at 3d95ac24): refuted, four gaps

1. **"As the live tail decodes it" holds for one tail only**: a tail reading the file whole from
   its start. A live tail that followed the file as it was written settles UTF-8 or CP1252 on its
   first poll, and one attached at the end on a 4 KiB head; on a file mixing the two (UTF-8, then
   one stray CP1252 byte within the first 64 KiB) they read otherwise than the grep. Taken: the
   clause narrowed, the limit stated. A file at rest decodes as a tail reading it whole from its
   start; the decoder's rule (C-035) is not moved for files that mix encodings, which every reader
   can only guess at.
2. **Whole word wrapped the pattern's text**: `a)|(?:b`, refused bare, was accepted wrapped (the
   whole-word test on one side of each branch only); `(?x)run # word`, valid, was refused wrapped
   (the comment swallowing the wrapper's close) in words quoting text the operator never wrote.
   The pattern is compiled bare first now, and a comment of the extended mode is closed by a line
   end before the wrapper's.
3. **A cancel was not heard while a file was read**: the file was read whole, then decoded whole,
   before the first check (400 MB: the cancel heard after 5 s). The file is read and decoded in the
   tail's slices now, the cancel asked at each.
4. **Two guards' edges unasserted**: a file of exactly the size limit is searched, and a NUL past
   the 8 KiB head makes no binary file (a log padded with NULs after a power cut).

Five mutants, each red: no cancel while reading, no bare compile, no comment fallback, the binary
guard over the whole first slice, the size limit inclusive.

## Refute round 5 (2026-11-23, at 791a1e9a): refuted, four gaps
