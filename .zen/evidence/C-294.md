# C-294: a release's licences

Q35's ruling (2026-11-25: every crate but Oficina `MIT OR Apache-2.0`, Oficina `GPL-3.0-or-later`)
held at every cut, with Q446's (2026-11-26: Qt's and KDDockWidgets' texts and where their sources
are).

## What the list holds at HEAD (2026-11-27)

Every member states its licence (Oficina's `GPL-3.0-or-later`, the rest `MIT OR Apache-2.0`), and
every package cargo resolves for the components states one: 380 crates and the IronCalc fork's two
packages, with no entry missing one. KDDockWidgets states `GPL-2.0-only OR GPL-3.0-only` in its own
`LICENSE.txt` (Q446's text had LGPLv3); Oficina's GPL-3.0-or-later takes it. The copy of Qt on the
development machine carries no licence text: the bundle ships Debian's own LGPL-3, GPL-2 and GPL-3
texts, Qt's open-source terms being `LGPL-3.0-only OR GPL-2.0-only OR GPL-3.0-only`.

## Refute round 1 (2026-11-27): refuted, at ec40f6f7

Real forms, all on this repository's own list. The probe vendored HEAD with `cargo vendor` as the
cut does, then ran `keep_vendored` and `assemble`:
- **Crates' licence files below their top folder were dropped**, and their rows said "none
  shipped": tokio-modbus's and crc-catalog's `LICENSES/`, ring's `src/polyfill/once_cell/LICENSE-*`
  (which ring's own `LICENSE` points to), regex-syntax's `LICENSE-UNICODE`, chrono-tz's `tz/LICENSE`.
- **IronCalc's `THIRD-PARTY-NOTICES.md`** (the Unicode terms of the CLDR data compiled into
  `ironcalc_base`, which "must accompany any redistribution") matched no name of the rule.
- **Two of KDDockWidgets' five texts** (`MIT.txt`, `BSD-3-Clause.txt`) were dropped. The library
  compiles in nlohmann json, MIT.
- **Qt's bundled third-party code** (ICU 73, PCRE2, double-conversion, libpng, libjpeg, HarfBuzz,
  md4c) was named nowhere in `licenses/qt/`.

Answered (this commit):
- **Depth:** licence files are taken at any depth, and every file of a `LICENSES/` folder, for
  crates and packages by path alike.
- **Names:** the name rule takes notices (`*NOTICE*`, `THIRD-PARTY*`, `3RDPARTY*`); a Rust source
  is never one.
- **KDDockWidgets:** its every `LICENSES/` file and its `3RDPARTY.md` when present.
- **Qt:** its own SPDX documents (`sbom/*.spdx.json`) of the modules whose files `lib/qt/` holds,
  matched by file name, which name the bundled code and its licences, the custom licences' texts
  inside.
- **Q450 (raised):** the texts of the standard licences those documents name, and ICU 73's terms,
  are not on this machine. Q450 asks whether to fetch them from Qt's source archives (recommended)
  or carry the documents alone (taken meanwhile).

## Refute round 2 (2026-11-27): refuted, at 6108991d

Real forms, each with a probe on a repository of its own:
- **`license = ""` passed the refusal:** the list wrote it as an empty expression, which states
  nothing.
- **A licence stated by `license-file` shipped no text** when its name was none the rule knows
  (`LICENCA`, `legal/terms.txt`), and when the file lay outside the package (`../../LICENSE`, the
  repository's own, as `cargo package` allows). The same for a vendored crate whose manifest names
  `legal/terms.txt`.
- **A package nested in another's folder** had its licence files carried under the outer package
  as well (`git ls-tree -r` lists the whole subtree).
- **Fonts' licences** of a vendored crate's documentation (deltae's `docs/doc/FiraSans-LICENSE.txt`,
  `SourceSerif4-LICENSE.md`) were dropped: the names did not start with a licence word.

Answered (this commit):
- An empty or blank `license` or `license-file` states none, and the cut refuses it.
- The file a `license-file` names is carried whatever its name: a package by path's from git at
  the commit, inside its folder at its own path, outside it by its name at the folder's top (under
  `license-file/` when a file of the folder has that name); a crate's from its vendored manifest.
  A package by path's that the commit does not hold as a file, or that lies outside the
  repository, is refused before the build, naming it.
- A folder of a package's that holds a manifest with `[package]` is that package's: its files are
  not the outer one's. A folder whose manifest is a workspace alone stays the outer package's.
- Any name holding `LICENSE`, `LICENCE`, `COPYING` or `NOTICE` is a licence file; a Rust source is
  never one. Submodule entries are no files of a package.

## Refute round 3 (2026-11-27): refuted, at 32d9aafd

The critic ran the cut's own steps on HEAD (`components::list`, `builder::prepare`'s `cargo vendor`,
`keep_vendored`, `assemble`, Qt's `lib/qt/` staged from the builder's script) and read every one of
the 350 vendored crates for licence files kept or missed. Two real forms:
- **glam's `ATTRIBUTION.md` was dropped** (HEAD's own list): it holds the MIT texts and copyright
  lines of DirectXMath, Realtime Math and GLM, whose code glam compiles on x86_64 (`src/sse2.rs`),
  each asking to be included in all copies; glam names it in its manifest's `include`, and
  veredas-maquinar reaches it through rapier3d-f64 and nalgebra. No other notice was missed.
- **A package at the repository's root stating `license-file = "LICENSE"`** (used by path by a
  member, as signal-hook-mio uses signal-hook) was refused as naming `/LICENSE`, outside the
  repository: the list joined its empty folder and the file with a `/`. This repository's L1 keeps
  a root package out of HEAD.

Holding: no entry of HEAD's list states no licence; Qt's documents match the staged layout (qtbase
and qtdeclarative, ICU 73 Q450's); KDDockWidgets' five texts; an inherited `license-file`; versions
with build metadata.

Answered (this commit):
- A name holding `ATTRIBUTION`, or starting `ACKNOWLEDG` (pyo3-ffi's `ACKNOWLEDGEMENTS` in this
  machine's registry), is a licence file. A test vendors glam 0.33.12 with the machine's own
  `cargo vendor` and finds its `ATTRIBUTION.md` kept.
- The root's own package names its licence file from the root as it is; its row's source is "this
  repository, its root", and its folder's packages are left to them.

## Refute round 4 (2026-11-27): refuted, at f7cf62b2

The critic ran the cut's own steps on HEAD and read the contents of all 999 crates of this
machine's registry for notices under names the rule misses. Three real forms:
- **half 2.7.1's only copyright notice** (HEAD's list, through portal → duckdb → arrow →
  arrow-array): REUSE's `.reuse/dep5` names "2021 Kathryn Long", and its `LICENSE-MIT` holds no
  copyright line; MIT asks for the notice in all copies. Dropped.
- **A component's font licence `OFL.txt`**, Google Fonts' own name (Veredas 1's desktop compiles
  Geist in by `include_bytes!` beside `assets/fonts/geist/OFL.txt`; IronCalc's web app does the
  same): dropped, while `assets/fonts/LICENSE` beside it was kept.
- **`AUTHORS` named by a licence as its holders:** sha1_smol 1.0.1 ("as shown by the AUTHORS file",
  BSD-3-Clause) and fancy-regex 0.11.0 ("The Fancy Regex Authors"). Dropped.

Holding: no entry of HEAD's list states no licence; every crate has its vendored folder; nothing
kept at HEAD is no licence or notice; the packages by path, KDDockWidgets' five files and Qt's
documents (qtbase and qtdeclarative, every QML module Oficina imports) are carried.

Not counted: a package by path stating both `license` and `license-file` (no instance), r-efi's
and winapi's (other platforms), code files whose names hold NOTICE in no package a list reaches,
two constructed forms (`missing/../LICENSE`, two packages by path of one name at two versions).

Answered (this commit): `AUTHORS…`, `OFL…` and `UFL…` (the word alone or before `.`, `-`, `_`),
`REUSE.toml` and `.reuse/dep5` are licence files. The vendored test now takes half 2.7.1 and
sha1_smol 1.0.1 beside glam with the machine's own `cargo vendor`, and the bundle's test carries a
component's `assets/fonts/geist/OFL.txt`.
