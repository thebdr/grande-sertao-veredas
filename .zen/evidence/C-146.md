# C-146 evidence - the scan file

## `veredas-scan`, version 1 (2026-11-25)

Phase 6's second piece. Absorbed from Veredas 1's `snapshot.rs` (a JSON snapshot of the engine's
knowledge: its counts, devices, topology, conflicts, the sources' names, a millisecond stamp; what
its API served and its `aranha/baseline.json` stored), changed on the way:
- **TOML with a stamp** (law L7), its header read by the suite's one reader (core's `schema`, core
  taken without its plant-facing layers: serde, toml and thiserror alone, so aranha stays light, as
  C-130 holds), a later version migrated or refused, never guessed at.
- **Read back whole**: every key taken or the file refused, naming each (`serde_ignored`, as
  ábaco's reader does); Veredas 1's JSON read ignored what it did not know.
- **Witnesses kept, and the capture beside**: every value with its first and last witness by frame
  number, and the capture's first record number, so a value reads again from its frame; Veredas 1
  kept millisecond stamps and the sources' names, not the frames.
- **The expected list is not carried**: comparing what the wire shows with what a configuration
  expects is controlador's hardware configuration, fed by the scan (the plan's absorb table). The
  diff comes next (its own clause).
- **A number past TOML's integers is refused when written**: the `toml` crate writes and reads a
  `u64` past `i64` (measured: a stamp of `u64::MAX` written and read back equal), which TOML's spec
  and other readers refuse; the writer goes through TOML's own value model first, which refuses it.
  A first version read its own text back to check, and could not be made to fail.
- A field serialises as the list of its values (`#[serde(transparent)]` on `fusion::Field`), the
  rest as its type holds it, so the schema document names what each key holds rather than
  repeating the types; its example is the sample scan's file, held to the character by the test.

Before the first commit, 11 mutants of the scan file and of the field's serialisation (unread keys
taken, the header unchecked, the integers' range unchecked, the capture never written, the
conflicts left out, the devices reversed, the fusion not given back, the tool unversioned, another
version, a field not written as its list, another format): all killed.

C-130's test of the proc macros aranha's builds use read the workspace's own resolve, which gives
core the features every member asks of it together (its OPC UA, tokio and Modbus layers), so core
taken without them showed fifteen proc macros it does not compile. The walk reads aranha's split
instead (the split's manifest is aranha's, held so by the split test), where core is resolved as
aranha takes it: the same six as before.

## The first refute round, answered (2026-11-26)

The critic (its own copy, 632 fully populated scans and 82 odd strings round-tripped, every one
of the 258 number slots raised past TOML's integers, a key added after each of 269 table headers,
917 single-key removals, 32 mutants) found the round trip, the writer's range, the unread keys and
the header holding, and refuted on:
- **The body was not read whole**: the toml crate (1.2) reads a struct written as a list, drops a
  list's elements past what a tuple or a struct takes, takes a one-key table for a word, and a set
  keeps a repeat once; `serde_ignored` sees none of it, so each read back equal to what was meant.
  What was read is now written back as TOML's own values and compared with the file as parsed,
  the first place they differ named; a number past TOML's integers is refused by that parse.
- **A device twice, and frames outside the capture**: a third `[[devices]]` with the first one's
  MAC was read; witnesses past the capture's last record were never checked. A scan read whole
  must be a scan (devices by MAC, each once; no frame past its capture's last), refused when
  written too. A witness before the capture's first is a frame the listener let go, as a bounded
  listening shows, and the clause and the schema say so.
- **The test's "in a witness" key** matched `first_frame = 0` in the capture, never a witness: it
  is placed in a witness now, and in the maps by name; two keys at once are both named.
- **The schema did not say what every key holds** (the PROFINET port status's and the delays'
  fields, the chassis key's other kinds): it does, held by a test that requires every key a fully
  populated scan's file holds to be named there.
- **Where the code was right and the test was thin** (numbers past the integers in other slots,
  fields written under another name in a scan whose fields were mostly empty, the header's other
  texts): each is asserted.

Of 14 mutants of the answer and the types the file holds, 13 are killed; one is equivalent (a key
one side alone holds is either named unread before the comparison runs, or of another form, which
its last arm refuses).
