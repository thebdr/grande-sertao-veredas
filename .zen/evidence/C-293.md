# C-293: the tester machine's update command

The architect ruled Q437 on 2026-11-25, "Update command": a command in the machine fetches a newer
release bundle, checks its sums and its manifest, installs it beside the old one and switches to
it, the plant's files left alone. Q436's place was ruled "Nowhere yet" the same day, so the
command fetches nothing: it takes a bundle by path, as the architect hands bundles over, and says
its SHA-256 to compare. A URL can be added once a place is named; no question was needed meanwhile.

## What it is

`tools/alforge/src/veredas-atualizar.py`, Python 3 (the standard library alone: `tomllib`,
`tarfile` with its `data` filter, `fcntl`), installed by the provisioning at
`/usr/local/sbin/veredas-atualizar` (`maquina::ATUALIZAR`, written byte for byte); `python3` is a
package of the recipe's, so the boot's check names it. `VEREDAS_ROOT` roots every path, which is
how the host's tests run the very text the machine runs.

## How it is proven

- Without a machine (`tests/atualizar.rs`): the shipped text run by the host's `python3` against a
  machine's folders of the test's own, bundles packed by the cut's own code; every refusal leaves
  every file, mode and link as it was (a snapshot of the whole root compared).
- In the machine (`tests/maquina.rs`, feature `maquina`): after C-292's proof, the shipped disk is
  booted again copy-on-write with a newer bundle on a data disk; QEMU's serial console is a socket
  it waits on (`vm::Spec::serial_in`), the test logs in as the recipe's user and types the commands
  a tester types. Each marker is typed split by quotes (`"ALFORGE-""UPDATE-EXIT $?"`), so the
  console's echo of a command never reads as its output; the kernel's messages are turned off the
  console first (`dmesg -n 1`).

## Found while building it

- A lock file beside the releases is itself a change to the machine: the command locks the
  `/opt/veredas` folder itself.
- `flock <file> sleep` as a test's lock holder: killing flock leaves its child holding the lock;
  `flock --close` keeps the lock with flock alone.
- A unix socket's path holds at most 107 bytes: the serial socket goes under the cache's `tmp/`.

## The implications check (2026-11-25), answered

Answered:
- A trial's bundle is refused, and so is a manifest missing a key or naming one executable twice.
- The disk's room is checked first.
- An I/O error once the release is moved puts back `current`, the links and the folder.
- The services are watched after the restart: a release that refuses the kept plant gives exit 3
  with the way back.
- Python 3 is installed by the provisioning itself.
- The guide says how to update.
- The proof boots an overlay of the shipped disk, reboots it and checks the boot again.
- Both digests are printed: the archive's, and its `SHA256SUMS`'.

Stated as limits:
- the manifest is read by Python's reader;
- a hostile bundle and signatures (P-014's);
- what only a new OVA brings;
- the old releases kept;
- how a bundle reaches a VMware machine.

C-293's proof inside the machine rides on C-292's machine (tests/maquina.rs) rather than building a
second, so that file re-stales both clauses.

## The first run inside the machine (2026-11-25, at d2447af7)

The machine was built and C-292's proof passed; the update installed and the machine rebooted on
it. Seven markers did not read: bash's bracketed-paste mode writes `ESC[?2004l` before a command's
first line of output, so every first line missed a marker read from the line's start, and the
reboot's check lines were compared whole. Markers are now found anywhere in their line, the
reboot's lines by their end, and the host's test console holds the escape as the machine prints it.
