# C-006 evidence - a plan before the code

## Refute round 1 (2026-11-05)

Attacked: a plan holding only a byte-order mark (on disk through the reader, and synthetic), zero-width
characters, a wrongly-cased plan on Windows (refused: git is case-sensitive, the law fails closed), a
folder where the plan should be (the reader errors, the suite goes red), `docs/orcl/README.md` blank,
a one-character plan, `docs/veredas-plan.md` taken as a component's plan, a `veredas-*` crate under
`tools/`, and the "before its code" claim.

Refuted, fixed: `is_blank` counts byte-order marks and zero-width characters as nothing, as an editor
does (`l6_a_plan_holding_only_a_byte_order_mark_is_empty`); the reader leaves the suite's plan out
(`l6_the_reader_leaves_the_suite_plan_to_nobody`); the `tools/` escape is L2's to name
(`l2_a_veredas_crate_under_tools_is_named`, `l6_a_veredas_crate_under_tools_is_caught_by_the_laws_together`);
the clause is reworded to what presence at every commit proves: no component's code lands without its
plan, and what the plan must say is the review's.

Held: a one-character plan passes, and the clause says why.

## Refute round 2 (2026-11-05)

The four round-1 fixes held. Refuted on two:
- a component excluded from the workspace (`exclude = ["crates/veredas-abaco"]`, or `["crates"]`)
  was never a member, so no law saw it: closed in L1, a suite crate is never excluded
  (`.zen/evidence/C-001.md`, round 2);
- "from the first commit" rested on the suite being run at every commit, which nothing in the repo
  performed. Now a law over history: `leis::history` asks git for the commit that first added each
  component's manifest and reads the plan out of that commit (`git show <sha>:docs/<nome>-plan.md`),
  naming the commit when the plan is missing or blank; proven on throwaway repositories (the plan
  one commit late, together, blank then filled, uncommitted, no repository at all), and run on the
  real tree's history by `real_tree.rs`. `.github/workflows/leis.yml` runs the suite on every push,
  with full history, so the law is not a habit.

Noted: other invisible code points (NUL, U+00AD, U+2061–U+2064, U+FFFE) still count as text; no
editor leaves them, and the clause now names exactly the set `is_blank` knows. A UTF-16 plan makes
the reader error (fails closed); a symlinked copy of the suite plan passes, consistent with leaving
what a plan says to the review.

## Refute round 3 (2026-11-05)

Refuted on the history law's formulation: it judged one commit per component, the first that a
plain `git log` reported as adding the manifest, on simplified history. Three shapes landed code
without a plan and passed: a branch whose code-without-plan commit a merge hid (git followed the
parent whose result matched), a component first appearing in the merge commit itself (a merge shows
no diff, so no "A" entry, and the `continue` was fail-open), a crate removed and re-added without
its plan (judged by its first life). A shallow clone's grafted root also read as the adding commit.

The law is now what the clause says: every commit reachable from HEAD (`git rev-list`) that holds
the component's manifest must hold its plan, not blank, checked in one `git cat-file --batch-check`
over every (commit, path) pair with each distinct plan blob read once, the earliest offending commit
named ("commit <sha> holds the code and no <plan>" / "… and <plan> blank"); a shallow clone is an
error. Four tests build the shapes in throwaway repositories: late, together and blank; the merge
that hides and the merge that lands; the re-added crate and the plan deleted then restored;
uncommitted, no repository, a shallow clone refused where the full clone names the commit. Held:
a `git mv` rename demands the new nome's plan at the rename commit; a wrong-case plan fails closed.

## Refute round 4 (2026-11-05)

Refuted on three. The serious one: the git helper wrote the whole `--batch-check` input before
reading any output, so past about a thousand commits per component git's stdout pipe filled, git
stopped reading, and the law hung forever (the critic timed it: 801 commits in 2.4 s, 1 201 never).
The input is now fed from its own thread while the output is read, and a test builds three
thousand commits with `git fast-import` and asserts an answer within a bound. The two others: a
folder or a symlink standing where the plan should be passed in an old commit (the object type
was thrown away, a symlink is a blob), and only the components present at HEAD, at their current
folder, were judged, so a renamed component's old folder or a deleted component's landing was never
looked at. The law is reformulated over git's trees: for every commit, the `crates`, `docs` and
`docs/orcl` trees are asked in one `--batch-check`, the distinct trees' raw entries read in one
`--batch` and parsed (`<mode> <name>\0<id>`), and every `veredas-*` / `orcl-*` folder of every
commit's `crates` tree must find its plan as a regular file (mode 100644 or 100755) in that
commit's `docs` tree, not blank (each distinct blob read once); the earliest offending commit is
named once per folder (`l6_history_judges_components_no_longer_at_head`,
`l6_history_wants_the_plan_as_a_regular_file`, `l6_history_answers_on_a_long_history`). Noted, not
counted: "earliest" by `rev-list --reverse` is by date across merges; a folder named for a
component counts as its presence even without a manifest (strict); orphan branches are out by the
clause's "reachable from HEAD".

## Refute round 5 (2026-11-05)

The round-4 fixes held (the 3 000 commits in 17 s on this box). Refuted on three, each a commit the
history law accepted while the tree law refused the same tree: the suite's own `docs/veredas-plan.md`
counted as `veredas-veredas`'s plan in history (the tree law leaves it out; history does now too,
`l6_history_leaves_the_suite_plan_to_nobody`); a UTF-16 plan holding only its byte-order mark, or
only whitespace, read as text through a lossy decode (the blobs are read as bytes in one batch now,
and bytes that are not UTF-8 are blank, `l6_history_wants_text`); a component added as a submodule
(mode 160000) was skipped as not a folder (a gitlink or a symlink named for a component is its
presence now, staged with `update-index --cacheinfo` in `l6_history_judges_a_submodule_or_a_link_named_for_a_component`).
The clause said "three git conversations"; it is a fixed number (the plan blobs are one batch now),
and the clause says so. Noted: a nested `crates/grupo/veredas-x` is L1's business, history looks at
the top of `crates/` as the clause says; a malformed `cat-file` answer would read as no components
(fail-open on git's own corruption, not reachable).
