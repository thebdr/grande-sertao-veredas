# C-092 evidence - the controller a portal is embedded in, as a source

## The ruling and the interface (2026-11-22)

`docs/controlador-plan.md`, "The engineering link": controlador owns the real-time communication,
its embedded portal reads its memory (the variables list, the CPU's states) asynchronously, and
"state changes and faults are stored like any other data, and the history view reads them". The
reading of memory has no transport to build: the embedded portal runs in controlador's process.
Built here: the portal's side, a source fed in process.

- **A feed, not a poll.** `Session::controller_feed()` hands the embedding a `ControllerFeed`
  (cloneable, `Send`) with `push_state(&ControllerState)` and `push_fault(&FaultRecord)`; the
  pump drains it like any other source's channel. The state is core's structured
  `ControllerState` (C-070), so the text stored is core's one writer's and its parts (word, reason
  number and word, health) come from core's table, never from parsing text.
- **A fault record** is what `docs/controlador-plan.md` "Faults" lists that the state does not
  already carry: its FAULT state (the cause with its task, location, code, event, kind or download;
  the debug conditions active), the download that was running, the handler's outcome. The rest of
  the plan's record (the snapshot of all data, the last seconds before it) is the window's copy
  (C-093). If controlador's record carries more, the table grows a column: the interface is
  proposed to controlador's member through the orchestrator.
- **Two fixed tables**, `controller_states` and `controller_faults`, claimed like any rule's so a
  rule of the same name is refused: a history view finds them by name. One controller source per
  session (`SessionConfig::controller` is an option): an embedded portal sits in one controller.
- **Health.** A state stands until it changes, so the source never reads idle: waiting until the
  first state, then live, ended at the stop.
- **Names.** `push_state`, `push_fault`, `fault_state`, `CONTROLLER_STATES`: supervisão's sources
  name `state` and `fault`, and its policy test refuses a public name of portal it also holds.
- **The bench.** No bench device plays a controller's memory: the producer is controlador, a
  component, not the plant. The test plays the embedding through the public feed with core's
  types, beside the bench's plant read by the same session; controlador's own tests prove its side
  once it embeds portal.

## Refute round 1 (2026-11-22, at b3380d9): refuted, two gaps

1. **A push racing the stop was accepted and lost**: the feed stayed open after the session's last
   drain, so a push during the stop's tail returned Ok and left no row (24 rounds in 30 of the
   critic's probe); a fault lost so had no copy either. The feed now sends under a gate the pump
   closes before its last drain: a push lands before that drain or is refused. A test races a pusher
   against the stop over ten rounds: every accepted push a row.
2. **The stamps unasserted**: a feed stamping the index on UTC instead of the controller's local
   clock passed (an hour off on this machine). The test now checks every row's index against the
   local clock and its arrival against the unix clock at the push.
