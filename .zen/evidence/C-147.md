# C-147 evidence - the diff of a scan against a baseline

## First version (2026-11-26)

Phase 6's third piece. Absorbed from Veredas 1's `snapshot.rs` `diff` (devices appeared and
vanished by MAC, renamed by their label, readdressed by their DCP address else their ARP one, links
added and removed by a key, conflicts new and cleared by kind, value and devices), changed on the
way:
- **A value is compared only where both scans state it.** Veredas 1 compared a label that falls
  back to the LLDP system name and then to the MAC, and an address that falls back to the ARP one
  and then to an empty text: a device heard only by its LLDP in a later listening was "renamed"
  from its station name to its system name, and "readdressed" to nothing. Here each value is its
  own field (station name, system name, IP suite, ARP address, management addresses), what the
  device states now (the value heard last, as `Field::current`), and a value one scan states and
  the other does not is **one-sided**: a scan that did not ask says nothing of what it was not
  told, neither a change nor silence.
- **An empty name and 0.0.0.0 are values** a device states (a device reset to its factory state
  names itself empty and has no address): renamed from a name to an empty one, readdressed to
  0.0.0.0, never one-sided.
- **A link is its two ends** (node id and port): its confidence and its witnesses are evidence,
  not wiring, so a link heard then confirmed, or heard more often, is no change. An end is its
  node's id, so a chassis node in one scan and a device announcing that chassis in the other are
  two ends: the diff does not resolve one into the other (that would be identity by a chassis key
  across time, which the topology itself grants only within one scan and only when one device
  announces it).
- **The interfaces each scan listened on** are compared: a device vanished with the interface it
  was heard on reads for what it is.
- **Two scans, or a refusal**: a baseline or a scan that is no scan (a device twice or out of order
  by MAC, a frame past its capture's last: C-146's `check`) is refused naming which, rather than a
  diff of whatever its lists hold.
- **The expected list is not carried** (the plan's absorb table): comparing the wire with a
  configuration is controlador's.

What the diff does not compare, on purpose: the PROFINET ids, vendor text, role and instance (a
MAC is one device; a device whose ids change under one MAC is fusion's to show as a conflict when
both are heard in one scan), the alias (a neighbour's port, said by the topology), rings (a ring
broken shows as its link removed), the topology's notes (each scan's own evidence) and the stats'
counts.

The bench proof scans as an engineer does: listening on both interfaces before the bench starts,
an Identify of every device on each, the topology built from the listener's last snapshot while the
devices still run (a device's LLDP on leaving says its port is no one's cable, C-145), the scan
written to its file and read back before the diff. The bench's devices state no LLDP system name
and no management address and send no ARP unasked: the test says so, so their fields' absence is
measured, not assumed.

Before the first commit, 22 mutants of `src/diff.rs` (kept as a resumable script under
`~/.cache/veredas/aranha/mutants/c147/`): a device appeared dropped, a vanished one unlabelled,
renamed and readdressed swapped, an equal value a change, the one-sided values dropped, a value
neither scan states one-sided, the station name taken from the label, the IP suite without its
gateway, the management addresses joined otherwise, the first name heard taken for the current
one, a link keyed by its confidence and witnesses too, added and removed swapped, a conflict's
devices left in their order, a conflict keyed by its kind and value alone, the interfaces swapped,
the baseline unchecked, the scan unchecked, the ARP address or the system name not compared, the
two refusals' names swapped, cleared taken for new, the vanished devices in reverse order: all
killed (the system name's only by the sweep).
