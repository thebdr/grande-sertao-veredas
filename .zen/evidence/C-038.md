# C-038 evidence - capture rules

## The design (2026-11-07)

Veredas 1's `extract.rs` (`ExtractRule`, `GroupType`) and `timestamp.rs`, with two changes. The
group type is core's `SeriesType` (the same four cases; Veredas 1 kept two enums and a mapping
function between them). The regex engine is `regex` alone: Veredas 1 fell back to `fancy-regex`
for lookaround and back-references, so a pattern could mean one thing in a log rule and another
in a telegram capture rule (core's `CaptureSpec` is `regex` alone); one engine, one syntax, across
every rule of the suite, and a lookaround pattern is refused as a bad pattern with the engine's
text. The plan records the decision.

The grep tab's ad-hoc table (Veredas 1's `capture.rs`: cells typed by inference, CSV and Markdown
export) is not here: it is operator tooling over logs at rest, and goes where the shell goes
(`docs/questions.md` Q14).
