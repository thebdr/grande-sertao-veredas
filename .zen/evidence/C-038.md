# C-038 evidence - capture rules

## The design (2026-11-07)

Veredas 1's `extract.rs` (`ExtractRule`, `GroupType`) and `timestamp.rs`, with two changes. The
group type is core's `SeriesType` (the same four cases; Veredas 1 kept two enums and a mapping
function between them). The regex engine is `regex` alone: Veredas 1 fell back to `fancy-regex`
for lookaround and back-references, so a pattern could mean one thing in a log rule and another
in a telegram capture rule (core's `CaptureSpec` is `regex` alone); one engine, one syntax, across
every rule of the suite, and a lookaround pattern is refused as a bad pattern with the engine's
text. The plan records the decision.

The grep tab's ad-hoc table (Veredas 1's `capture.rs`: cells typed by inference, CSV and Markdown
export) is not here: it is operator tooling over logs at rest, and goes where the shell goes
(`docs/questions.md` Q14).

## Refute round 1 (2026-11-09): refuted, one gap

The capture-rule half held every probe (the number parsers' edges, empty and absent groups, the
key by exact name and untyped, the first match of a line, the error texts, the scope by exact
id, the time type with no formats, the fills of C-036). The extractor did not: when its preferred
format missed, it went on from the preference and wrapped around instead of returning to the
configured order, so with three formats a format that had never succeeded (month.day) could beat
the first configured one (day.month) and then stay preferred, while the stateless spec, which the
backfill's locate uses, read the same stamp the other way: one line, two stamps a month apart.
The test had two formats, where a rotation and the configured order are the same sequence. The
preferred format is tried first and, on a miss, the configured order with it skipped; the clause
says so and a three-format test pins it (failing at ac62e83). Noted outside the claim: a
timezone in a format is parsed and dropped, and a bare carriage return the tail keeps (C-035)
defeats a `$`-anchored rule, both now in the plan's traps.
