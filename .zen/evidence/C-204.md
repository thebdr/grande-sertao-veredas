# C-204 evidence - the run record and the acceptance report

## The design (2026-11-22)

Q312 is taken as (a) and (d): the record is a TOML file per run, `veredas-report` version 1, with
the evidence as CSV beside it, the PDF Oficina's drawing of it; anyone signs by a name typed (no
accounts, Q20), and a signed report is frozen. The orchestrator's word on (d): nothing that freezes
a signed report in a way a later answer could not undo, so the freeze is the engine's refusal to
change the file, not a seal in it.

- **A run's folder is taken by creating it**: the next number after the highest folder of four
  digits, a folder already there (another keeper's, or one left by a run cut short) passed over;
  `report.toml` is written beside its place and moved there last, so a folder that holds a report
  holds a whole run, and the listing passes over one that does not.
- **The exact text that ran** is copied (`test.test`, `functions/<n>.fn`): a report names its test,
  and the file on disk may have moved on since.
- **The evidence** is the rows of every table the test reads (the binding's set, C-202), stamped in
  the run's window, oldest first, as the suite shows each value. The rows before the window that
  gave a wait its first values are not kept; a replay from the kept evidence alone would need them
  (later, with a replay over a window the session no longer holds).
- The key `writes_armed` appears nowhere in the record (C-200 refuses it in the crate's sources).

## Found by its own test (2026-11-23)

The record test compared each table's evidence with the store read again after it, and once found
90 rows where the evidence held 89: a live run's window ends at the moment the last send was
answered, and a row stamped just before it may reach the store a little after. `keep` now reads a
live run's evidence only once the window's end is 250 ms past, the settle every live read takes.

## Refute round 1 (2026-11-23): refuted, five findings, all closed

1. **Two changes of one report at once crossed**: `note` and `sign` each read, judged and wrote
   with nothing held between, every writer through the same temporary name; two signatures at
   once were both taken in 186 trials of 300 (one kept), a sign beside a note lost its signature in
   297, and one trial tore the report. A change now reads, judges and writes under an operating
   system's lock (`File::lock`) on the folder's `report.lock`, released when the process ends, so
   a crash leaves no stale lock. `list` stopped at the first report it could not read; it now
   lists each run with its report or the reason.
2. **The evidence's `arrival` was on the Unix clock beside a `time` on the store's axis** (an
   hour apart on a machine at UTC+1, equal at UTC, where GitHub's runners are). It is put on the
   store's axis, the plant's local wall clock at that moment, as portal stamps its rows. The test
   runs the executable under a zone five hours east of UTC, so the check holds on any machine.
3. **Runs from 10000 on were kept but never listed**: the numbers read four-digit names alone.
   A name is read as the number it writes, four digits at least.
4. **`read` and `sign` held no value set**: a mode `banana`, a role `janitor`, a moment
   `yesterday`, an attempt 0, a test file `../../etc/passwd` all read. Every value the reference
   gives a set or a form is judged on reading, and a signature takes `tester` or `witness` by a
   name holding a letter or a digit.
5. **Keys the test did not assert** (the `use` path, the criterion's text and measured value, the
   sends' answers, the steps' moments, the evidence's cells after the first stamp, the signature's
   time): each asserted, every evidence cell against the store's row.

What held: TOML round trips of a note with control characters, quotes, line ends, a byte-order
mark and non-ASCII text; folder numbering when runs are kept at once; the evidence window as
stated; the worked example key for key against the engine's output.


## Refute round 2 (2026-11-24): refuted, four findings, all closed

What held: the lock (60 threaded pairs; across processes, a note waited 1.6 s while `flock(1)`
held `report.lock`; a lock file that is a folder or read-only refused, the report unchanged); a
change failing midway leaves the old report whole; 18 hard strings (DEL, NUL, CR, a byte-order
mark, U+10FFFF, `'''`, `"""`) through a note and a read; the arrival across both of CET's
daylight-saving changes; 9999, 10000 and past listed in order.

1. **An evidence file could leave the run's folder through its table's name.** `read` built the
   expected file from the `table` it judged (`evidence/{table}.csv`) and took any
   `evidence/table-<digits>.csv` for any table, so `table = "../../0001/evidence/outcome"` with
   its matching file read, as did `/abs` and `../../../../../../etc/passwd`, a plain table at
   `table-1`, and two entries at one file. Each entry's file is now exactly the one `keep` writes:
   `evidence/<table>.csv` for a plain name (letters, digits, `_`, `-`), `evidence/table-<n>.csv`
   by its place from 1 otherwise; a table given twice is refused. The reference states both; the
   test's old assertion that a plain table at `table-1` reads is reversed.
2. **Moments in other forms read.** chrono's parser takes any whitespace for the format's space,
   skips blanks before a number and takes a signed year; the length check closed none of it. A
   moment is now judged byte by byte (digits, and the separators in their places), its seconds
   under 60, then as a day the calendar has: eleven such forms are refused.
3. **`list` hid every run when the test's folder could not be read** (no read permission, a file
   where the folder is): any error was "no runs". A missing folder is still none; any other error
   is now named. A `0000` folder is no run.
4. **`keep` panicked on a folder `4294967295` already there** (and wrapped to `0000` in a release
   build): the next number is a checked sum, refused by name past the last.

The old `record.rs` fails both changed tests. Trivial, left: a note on a folder with no report
leaves an empty `report.lock`; an empty text and a hole are both an empty cell, as the reference
says of a hole; a report's number is not compared with its folder's name, which the clause does
not state.

## Refute round 3 (2026-11-25): refuted, three findings, all closed

What held: moments at every edge tried (months 00 and 13, day 00, the 31st of April and
November, the 29th of February in 2026, 1900, 2024 and 2000, hour 24, minute and second 60,
digits past ASCII, a `T`, short milliseconds, the years 0000 and 9999); `keep` at the last
numbers (4294967295 kept and read back, the next refused); a folder made meanwhile passed over; a
name that is not Unicode, and `0000`, no run. Trivial, left: a link to a run elsewhere listed with
that report's number (the number against the folder's name, left in round 2); an empty or
non-ASCII table name reads at its place, which `keep` never writes; the reference now says
"ASCII letters".

1. **`list` passed over a run's folder it could not look into** (mode 000, or every run's folder
   at 600 giving a list of no run): `exists()` is false on any error. `try_exists()` now tells a
   folder with no report (passed over) from one that cannot be looked into (listed with why).
2. **Two evidence entries could name one file**: the naming is not one to one (a plain table
   named `table-1` takes the file of a table placed first), and `outcome` and `Outcome` are one
   table in the store and one file on some systems. A file or a table given twice, in any case,
   is refused.
3. **`keep` wrote a window its own `read` refused** (a replay from the year 10000, which the
   executable's parser took): every moment the report will hold is judged before any folder is
   made, and C-205's parser takes a four-digit year alone.

The old `record.rs` and `main.rs` fail the three tests that hold them.

## The architect's Q312 (e) (2026-11-25): the roles a test names sign its report

Asked who signs an acceptance report, the architect answered "Roles named by the test": anyone
signs by a typed name and a signed report is frozen; besides, a test may name the roles that must
sign (`sign tester, witness`), and the report reads "awaiting witness" until they have. Built so:
the test's `sign` setting (C-201) names `tester`, `witness` or both, each once; the report keeps
them as `test.sign` (C-204), each of them signs once, a role not named is refused, and
`Report::standing` reads `awaiting <roles>` until all have signed, then `signed`; a note is refused
from the first signature; a test naming no role is signed, and frozen, by its first signature, as
before.

## Refute round 4 (2026-11-26): refuted, two findings, both closed

What held: the named roles' signatures at once (80 trials by threads, 25 by two processes under
the lock), the same role twice at once taken once; `standing` in every state tried; a role in
another case or with a dotless i refused, blanks trimmed; `note` and `sign` refused on a report
`read` refuses, the file unchanged; `list` naming every kind of unreadable run; moments before
1970 kept, the years -1 and 10000 refused before any folder.

1. **`keep` wrote two tables' evidence into one file** (round 3's fix was `read`'s alone): a
   table named `a.b`, placed first, and a plain `table-1` both took `evidence/table-1.csv`, the
   first's rows lost and the report refused by its own `read`. A place is now `table.<n>`, which no
   plain name can take (a plain name holds no `.`), `n` its place among the evidence written (a
   table gone from the session no longer shifts the others), and `keep` judges the whole report as
   `read` does before it makes the run's folder. The old "file named twice" check, now
   unreachable, is gone.
2. **`read` folded case wider than the store** (`Ärger` and `ärger`, two tables of the store, read
   as one): it folds ASCII alone, as portal does.

The old `record.rs` fails both tests; the critic's tables, through `keep` over a plant of them,
are kept in four files, each with its own header, and read back.
