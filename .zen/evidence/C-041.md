# C-041 evidence - the session store

## The design (2026-11-07)

Veredas 1's `veredas-store` (`DuckStore`, its schema types, its errors, its CSV helpers) as it
was, in one module behind the `store` feature, with two changes. The `SeriesStore` trait is
gone: it was the seam for a second store that never came, and a trait with one implementation
is a surface to keep for nothing; the narrow methods are the store's own. The column type is
core's `SeriesType`, which core gives every protocol's rule, so a base table is shaped by any
rule without a mapping (Veredas 1 kept `GroupType` beside it and mapped at the session).

"Every protocol's data stored alike" is what the test's third case pins: a capture rule's
series, an OPC rule's columns (through the gateway's own `opc::compile` and `table_of`) and a
telegram message's table (through `MessageTable::of`) make three `BaseTableSpec`s the store
opens together, and their rows read back through one surface, listed, windowed, paged and
charted the same way. The session (phase 5) will feed the store exactly this way, from the
bench.

The CSV helpers stay: a reference table the operator keeps beside the plant (sensor labels,
limits) is read live through a view, which is the store's business, not a shell's; a shell's
concern (Veredas 1's SQL builder, templates, recents) is Q14's.
