# C-041 evidence - the session store

## The design (2026-11-07)

Veredas 1's `veredas-store` (`DuckStore`, its schema types, its errors, its CSV helpers) as it
was, in one module behind the `store` feature, with two changes. The `SeriesStore` trait is
gone: it was the seam for a second store that never came, and a trait with one implementation
is a surface to keep for nothing; the narrow methods are the store's own. The column type is
core's `SeriesType`, which core gives every protocol's rule, so a base table is shaped by any
rule without a mapping (Veredas 1 kept `GroupType` beside it and mapped at the session).

"Every protocol's data stored alike" is what the test's third case pins: a capture rule's
series, an OPC rule's columns (through the gateway's own `opc::compile` and `table_of`) and a
telegram message's table (through `MessageTable::of`) make three `BaseTableSpec`s the store
opens together, and their rows read back through one surface, listed, windowed, paged and
charted the same way. The session (phase 5) will feed the store exactly this way, from the
bench.

The CSV helpers stay: a reference table the operator keeps beside the plant (sensor labels,
limits) is read live through a view, which is the store's business, not a shell's; a shell's
concern (Veredas 1's SQL builder, templates, recents) is Q14's.

## Refute round 1 (2026-11-09): refuted, eight gaps

The critic found: a base-table column's last value shown as the engine prints it ("26.0",
"1e+20") against the suite's display the narrow samples already used, the two assertions in the
test contradicting each other; a snapshot attaching an existing database and copying the session
into it, and a refused snapshot leaving the target attached so every later snapshot failed; one
linked CSV missing between a removal and its replacement breaking the whole table surface, base

repeating and skipping rows that share a time (36 distinct of 50 over two stamps); dates,
decimals and intervals paged as Rust debug text; a column two tables of one source share listed
from whichever table came last while the window merged both; a disk store reopening at an

dropped on a table with no key column. Fixes: the last value read typed and displayed by the
suite's own type; the snapshot refused by name before anything is attached, the detach run
whatever the copy did and a half-written file removed; a view that cannot be described listed
with no columns, hiding nothing; the sequence breaking the time tie; a date and a time of day as
milliseconds, a decimal a number, an interval an ISO 8601 duration, a blob hex, a nested value
alone left as debug text and the clause saying so; one series per (source, column) across tables
through one union, the later value winning; a database already at the path refused by name
(Q16: a session store is fresh); a key on a keyless table refused as a name the catalog lacks.
Eight tests pin them, one assertion corrected to the clause's side ("26"). Held by the critic:
every name and value quoted or bound (a column named to drop the samples table, a view with a
quote, a key with an apostrophe, paths with one), the export's file names sanitised inside the
folder, the engine's and the store's case rules agreeing, the window's edges and ties, an offset
past the end, a snapshot onto a folder or a missing parent refused, the CSV edge files, no read
path taking the ingest lock.

## Q17 decided (2026-11-09): the padded reader for any ragged file

The architect decided the padded reader takes any linked CSV the sniffer reads ragged, the
sniffer staying the first reader of a regular file. Raggedness is read off the file itself: the
first 2 048 lines counted in the sniffer's own delimiter (`sniff_csv`), quotes honoured, a blank
last line no row; unequal widths force `read_csv` with that delimiter and `null_padding`, where
only a file collapsed to one column was forced before. The engine's behaviour on the padded path
is C-042's to pin (a long row widens within the window, refuses by its line past it); the store's
choice is this clause's. The test reads a short row and a long row the sniffer would keep or
drop on its own terms with every row kept, leaves a regular file with a quoted delimiter and a
blank last line to the sniffer, and keeps a ragged row past the window out of the count. The run
was re-recorded after the change.

## A definition is one SELECT (2026-11-11, from C-054's seventh refute round)

C-054's critic found that `validate_definition` ran a definition's text: the pinned crate's
`prepare` runs every statement but the last, so `SELECT 1); COPY ... TO '<file>'; SELECT (1` wrote
a file through a validation documented as not running anything, and `CREATE VIEW ... AS (sql)` in
`execute_batch` did the same when the store opened. Every definition is now handed to the engine's
`query()` table function as a string, which parses it and refuses anything but one SELECT
("Expected a single SELECT statement"), at validation and when the views are applied; a sound
definition yields the same columns and types. The store test refuses four spellings of a second
statement (closing the parenthesis, after a `;`, inside dollar quotes, a COPY alone) at validation
and at open, checks the COPY's file was never written, and validates a `;` inside one SELECT's
string. The project reference and its test's copy now say a view's `sql` is one SELECT.

## A 128-bit integer never wrapped (2026-11-15, from C-052's twelfth round)

C-052's twelfth round read a HUGEINT past 64 bits (and a whole DECIMAL of 38 digits, which the
driver hands over as one) through `duck_to_json` as `*i as i64`: 2^64 + 1 written as 1, two keys
merged. The conversion now writes a 128-bit integer as a JSON number where 64 bits hold it and as its
own digits otherwise; C-052's test drives both through a dashboard's table and cells. The series
listing's own conversion (`duck_to_value`, a series' last value) cast one the same way; it now gives
no value where 64 bits do not hold it. That path is not reached today: the listing reads the suite's
base tables alone, where an `int` series is a BIGINT column, so no test drives it. A DECIMAL with
places is still read as the double nearest it and a UHUGEINT arrives from the driver as a double:
C-052 states both limits.

## Refute round 4 (2026-11-22, at 713742f): refuted, six gaps in the linked CSV

The round C-041 never had after the shared changes of 2026-11-09 to 2026-11-15 (Q17's padded
reader, a definition as one SELECT, the 128-bit integers). The critic found the one-SELECT rule,
the view fixpoint and the 128-bit conversions holding, and six gaps in the linked CSV, two of them
mutants the test let live:
1. **Q17 itself was never tested.** The test's short and long files were both ones the sniffer
   collapses, which the older branch already forced; with the Q17 block switched off all 24 tests
   passed. A long last row the sniffer does not collapse (it keeps that row alone, two rows lost)
   is the case.
2. **The 2 048-line edge was never tested**: the test's long rows sat on lines 102 and 2 102, so a
   window of 2 047 passed.
3. **A file the sniffer refuses was refused whole**: a long row inside the window with a row after
   it (the sniffer "could not detect the parsing types", C-042 pins it) and a short row past the
   window, both of which the padded reader reads with every row.
4. **A long row past the window read as a total of nothing**: the preview's and the page's
   `count(*)` swallowed the engine's "CSV Error on Line: 2104" as 0, and the LIMIT read stopped
   before the line; the clause's refusal by the line was asserted nowhere.
5. **The padded reader refused a quoted line break** ("the parallel scanner does not support
   null_padding in conjunction with quoted new lines"), and the raggedness count knew only `"`: a
   regular file quoted with `'`, a line break in a quote, was counted ragged, forced onto the
   padded reader and refused, where the sniffer read it right (a regression of 90da9ba).
6. **A bare carriage return ended no line**: a file from an old Mac export with a long last row
   was not seen ragged, and two rows of three were lost.

The answers. The padded reader runs on one thread (`parallel=false`), which reads a quoted line
break whole (C-042 pins it, and that the window and the refusal by line are the same). The
raggedness count reads the file in the sniffer's own dialect (its delimiter, quote and escape, from
`sniff_csv`), a line ending at LF, CRLF or a bare CR; a ragged file is forced onto the padded
reader with that quote and escape (`CsvOptions` carries both, the scan writes them). A file the
sniffer collapses or refuses is read in the dialect the sniffer finds when asked to pad
(`sniff_csv(..., null_padding=true)`, which names `,` and `'` for a ragged file quoted with `'` that
it otherwise collapses on `|`), else in the delimiter that splits it widest; where none splits it
(a missing file) the sniffer's refusal stands. The preview's and the page's counts pass their error
on, so a long row past the window refuses both by its line. Four tests hold the gaps, the edges
beside each (lines 2 047, 2 048 and 2 049 in LF and CRLF files; a regular file in each dialect not
ragged; a missing file refused). Twelve mutants each turn the test red: the window at 2 047, the
Q17 block off, the refusal kept, each count back to 0, one thread dropped, the quote and the escape
each ignored in the count, the padded sniff off, the quote not written, a bare CR no line end, a
CRLF counted twice (the last two first survived a weaker file each, now a CRLF edge and an escaped
quote that ignoring the escape leaves open).

The same day the memory figure moved to the ingest's connection (C-043's finding); the clause says
so where it names the three connections.

## Refute round 5 (2026-11-22, at 4865e61): refuted, three edges of round 4's answers

The critic held the new branch for a refused file (a binary file, a UTF-16 one and an empty one
keep the sniffer's word), the tab, `|` and `;` long rows, a quote inside a `'`-quoted cell, the
decimal comma with a quote written, and the counts' errors (a removed linked CSV still lists, a
page of a refused view is refused). It found three edges, none a regression (each read the same
before round 4):
1. **A blank line moved the window.** The count advanced on every line end, the engine's window on
   rows: with one blank line, a long row on physical line 2 049 (the 2 048th row) was counted past
   the window and two thousand rows were lost to the sniffer's keep-alone.
2. **The forced reader chose its own quote.** The sniffer's `"` was dropped as "the reader's own",
   so the scan wrote no quote; a forced reader with no quote detects one and, on a file with a
   quoted line break near the window's end, picked none and refused it on line 2 049.
3. **A file with no quoting was counted as if `"` quoted it.** A stray `"` inside a field (12"
   long) toggled the count's quote, so a long row after it went unseen, where the engine opens a
   quote only at a field's start.
The answers: the count advances on rows (a blank line moves the window by none); the forced reader
always gets the sniffer's quote and escape written out, empty for one it did not see (`quote=''`,
which the engine takes); the count opens a quote only at a field's start, takes a doubled quote and
an escaped character as text inside one, and none at all when the sniffer saw none. The fields are
`quote_char` and `escape_char`: as `quote` and `escape` they were names supervisão's own sources
use, and its policy test refuses a public name of portal it also holds (the reachable suite caught
it). C-042 pins the engine's part. Nineteen mutants, round 4's twelve re-run among them: seventeen
turn the test red; two live. A CRLF counted as two line ends now changes nothing (blank lines no
longer advance the window, so the second end is a blank line); the widest-delimiter fallback's
quote left unset changes no outcome the tests reach (every file the fallback takes reads the same
either way, and the padded sniff finds the dialect first). Both are equivalent here, and said so.

## Refute round 6 (2026-11-22, at 24f8d17): refuted, two regressions of round 5 and two older gaps

The critic held CRLF inside quotes, `"ab"cd`, an escape as the last byte, doubled quotes with
their escape, a quoted comma or line break before a long row, a BOM before a quoted header, and a
regular file with ` "x,y"`. It found:
1. **A ragged quoted file read with no quote** (a regression of round 5): the sniffer reading the
   file as it is saw no quote (`(empty)`), round 5 wrote `quote=''`, and a quoted line break and a
   quoted comma were split; round 4 had left the quote to the reader, which found `"`. Neither
   sniff alone decides: asked to pad, the sniffer sees `"` on that file and none on round 5's
   late file, which it reads as it is with `"`. The quote is now the one either saw, the file as
   it is first.
2. **A quote after leading spaces** (a regression of round 5): the engine opens a quote after
   them (`1, "x,y",3` is three cells), round 5's count did not, and a long row after such fields
   went unseen. Leading spaces now keep a field's start; a space inside a field does not.
3. **The decimal comma refused on the padded path** (older): the comparison went by column name,
   and the padded reader took the header for a row in the all-text reading and not in the comma
   reading. By position now.
4. **A ragged `;` file with decimal commas read on `,`** (older; the clause's own rule): the
   padded sniff named `,`, which also split it widest, into nonsense. A collapsed or refused file
   now keeps the padded sniff's dialect unless another delimiter types strictly more columns as
   numbers, with or without the decimal comma; with no sniffed dialect, the most numbers, then the
   widest. (A first version scored every candidate alike and let `,` under `"` beat the sniffer's
   own `'`, wider by the quote it got wrong; the existing test caught it.)
The store test's assertion that a doubled quote with no escape counts three fields went: the engine
refuses such a file rather than read it so (C-042 pins it), and the sniffer reports a doubled quote
with its escape. Mutants: round 6's seven each turn the test red (the union of quotes off, leading
spaces clearing the start, a space setting it mid-field, the comma by name, the candidates scored
without the comma, the sniffed dialect always kept, the widest always kept); round 5's re-aimed at
the restructured code are killed but two equivalents (a CRLF counted twice, the fallback's quote
unset: no file the tests reach is read differently).
