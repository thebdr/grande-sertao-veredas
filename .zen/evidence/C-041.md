# C-041 evidence - the session store

## The design (2026-11-07)

Veredas 1's `veredas-store` (`DuckStore`, its schema types, its errors, its CSV helpers) as it
was, in one module behind the `store` feature, with two changes. The `SeriesStore` trait is
gone: it was the seam for a second store that never came, and a trait with one implementation
is a surface to keep for nothing; the narrow methods are the store's own. The column type is
core's `SeriesType`, which core gives every protocol's rule, so a base table is shaped by any
rule without a mapping (Veredas 1 kept `GroupType` beside it and mapped at the session).

"Every protocol's data stored alike" is what the test's third case pins: a capture rule's
series, an OPC rule's columns (through the gateway's own `opc::compile` and `table_of`) and a
telegram message's table (through `MessageTable::of`) make three `BaseTableSpec`s the store
opens together, and their rows read back through one surface, listed, windowed, paged and
charted the same way. The session (phase 5) will feed the store exactly this way, from the
bench.

The CSV helpers stay: a reference table the operator keeps beside the plant (sensor labels,
limits) is read live through a view, which is the store's business, not a shell's; a shell's
concern (Veredas 1's SQL builder, templates, recents) is Q14's.

## Refute round 1 (2026-11-09): refuted, eight gaps

The critic found: a base-table column's last value shown as the engine prints it ("26.0",
"1e+20") against the suite's display the narrow samples already used, the two assertions in the
test contradicting each other; a snapshot attaching an existing database and copying the session
into it, and a refused snapshot leaving the target attached so every later snapshot failed; one
linked CSV missing between a removal and its replacement breaking the whole table surface, base
tables included, because the listing described every view before answering; newest-first pages
repeating and skipping rows that share a time (36 distinct of 50 over two stamps); dates,
decimals and intervals paged as Rust debug text; a column two tables of one source share listed
from whichever table came last while the window merged both; a disk store reopening at an
existing path failing on the engine's table collision, by accident; a chart's key silently
dropped on a table with no key column. Fixes: the last value read typed and displayed by the
suite's own type; the snapshot refused by name before anything is attached, the detach run
whatever the copy did and a half-written file removed; a view that cannot be described listed
with no columns, hiding nothing; the sequence breaking the time tie; a date and a time of day as
milliseconds, a decimal a number, an interval an ISO 8601 duration, a blob hex, a nested value
alone left as debug text and the clause saying so; one series per (source, column) across tables
through one union, the later value winning; a database already at the path refused by name
(Q16: a session store is fresh); a key on a keyless table refused as a name the catalog lacks.
Eight tests pin them, one assertion corrected to the clause's side ("26"). Held by the critic:
every name and value quoted or bound (a column named to drop the samples table, a view with a
quote, a key with an apostrophe, paths with one), the export's file names sanitised inside the
folder, the engine's and the store's case rules agreeing, the window's edges and ties, an offset
past the end, a snapshot onto a folder or a missing parent refused, the CSV edge files, no read
path taking the ingest lock.

## Refute round 2 (2026-11-09): refuted, four of the first round's fixes incomplete

The tie-breaker was the sequence, which is counted per source: two sources sharing a table, or a
view with a time column and no sequence, still repeated and skipped rows across pages (34 and 36
distinct of 50). Every other column now breaks the tie, positionally, so a page walk sees a row
once (two rows identical in every cell aside); the clause says so. A time column's last value
was built from milliseconds where the engine holds microseconds and the suite displays them: the
same instant listed two ways through the two surfaces; it is built from microseconds. A negative
interval was formatted with a floored second and a positive fraction (-1.5 s read as -2.5 s); the
sign now rides the seconds. Three tests pin them. Held by the critic: the snapshot refusal and
the one after it, the missing linked CSV's view erring with the engine's text while the tables
read, the time of day and the decimal typed, the chart's empty key, the disk refusal for a
directory and a zero-byte file, the null key column of a keyless table, the two declared types of
one column listed once with the conflict counted (the keys the max of the two groups, an
undercount under a counted conflict, said in the code).

## Refute round 3 (2026-11-09): holds

No gap at 9d0d414. Checked: the positional tie-break paging six rows over two times one at a
time through views of every odd type (a list, a struct, a map, a blob, an all-null column, a

round-1 fixes untouched. Verified after three rounds; the clause grew at rounds 1 and 2.
