# C-040 evidence - OPC sources

## The design (2026-11-07)

Core already holds the OPC layer whole (C-018 to C-023: the spec, the values, the mapping, the
browser, the worker and its gated handle). What the gateway adds is the step before it: a
source's configuration, as an operator writes it in the project file, compiled into core's
`PollSpec` with every mistake refused where it was written. Veredas 1 did this in its desktop's
`config.rs` (`compile_with`), with `String` errors and a password from the Windows Credential
Manager; here the errors are typed and the password comes from an environment variable the file
names (`docs/questions.md` Q15), through a lookup handed in, so the compile needs no environment
and a test hands it a closure.

The worker and the mapping are core's and are not wrapped: `opc::spawn` and `map_poll_dedup`
are re-exported, so the session uses them as the bench's test did (C-026 drove core's worker
against the bench's server). The test here proves the whole chain against the bench from a
bench file: the rows typed as the rule lays them out, the bits carved, the on-change rule's
heartbeat at the 60th poll, the writes gated by the switch and the whitelist and landing where
the server side reads them.

One check is new against Veredas 1: bits on a text or time tag are refused at compile (core
refuses them at every poll, as a reported hole per bit; a configuration that can never read is
better refused once).

## Refute round 1 (2026-11-09): refuted, one gap and a test's weak reads

The clause allowed bits "out of an int or float word", and compile accepted bits on a float tag,
but core never carves a float's wire word: every poll of such a tag reported a hole per bit
("bit extraction needs an integer value, got Double"), the very configuration-that-can-never-
read the design note refuses for text and time. Bits are carved out of an int word alone now,
refused at compile on a float tag by the same text as on text and time; the clause says so.
The test's misspelled-key reads misspelled required keys, which fail for the missing key with or
without the unknown-field check; they now misspell optional keys in every table too and assert
the unknown-field text. Checked and held by the critic: the password hidden from every Debug,
the lookup called once, the endpoint trimmed and refused when blank, 49 refused and 50 accepted
and 0 refused by text, the name shape with `_` alone accepted, core's node-id refusal quoted, a
column with bits landing both, the three one-column refusals, bit 64 refused and a width clamped
by core, the heartbeat counted from the last kept row, the whitelist and the gate's order, the
wrong-password retry.

## Refute round 2 (2026-11-09): holds

No gap at bfb2133: bits on a float tag refused by name and text, the fixtures of the pure test
reaching the column-clash, bit-range and name checks on an int tag, the misspelled-key reads
covering every table (a `password` key at the source refused as unknown, Q15's guard, among the
probes), the reference's worked example on an int tag. Not counted: a tag typed int whose wire
value is a Double is a configuration that does not match the server, a hole per column and per
bit at poll time that compile cannot know; a field running past bit 63 reads bits 60 to 63 and
nothing above, which the clause neither claims nor forbids. The round's one finding belongs to
C-046: Veredas 1 accepted bits on a float and defaults a tag to float, so the import carried such
a tag as it was and the file no longer loaded; fixed there, the tag carried as an int word with a
note. Verified after two rounds; the clause grew at round 1.
