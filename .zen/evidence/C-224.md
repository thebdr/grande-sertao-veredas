# C-224 evidence: the `.abaco` file

## What it is (2026-11-23)
Phase 3 of `docs/abaco-plan.md`: `veredas_abaco::abacofile` (the file) and `workspace` (the
session), ported from Veredas 1's `abacofile` and `workspace` with its JSON parts made stamped TOML
(`docs/abaco-file.md`). Changed on the way:
- One line per cell in the sheet's `[cells]` table, an inline table keyed by the address, where
  Veredas 1 wrote tab-separated lines with its own escapes: TOML's strings carry any text.
- Every TOML part states its own format (`veredas-abaco`, `veredas-abaco-workbook`,
  `veredas-abaco-sheet`, `veredas-abaco-references`, `veredas-abaco-records`,
  `veredas-abaco-state`), so a part in the wrong place is refused by name.
- The engine's structures (styles, theme, names, a sheet's structure) pass through JSON: their
  `Color::None`, a unit variant of an untagged enum, serialises as JSON's null, which TOML cannot
  hold (`toml` refused the corpus's every workbook, "unsupported unit type"); a null is written
  `nan`, which no JSON value holds. The stamp is written first by hand, as the JSON route sorts
  keys.
- Tools' records are TOML tables (Veredas 1's were JSON values); TOML has no null.
- Veredas 1's `prefs.json` and `history.json` parts are not carried here: the preferences are
  phase 4's; a part this Ábaco does not read is kept anyway.
- New dependencies, reviewed in C-220's test: `toml` (already the workspace's) and `sha2` for a
  reference's fingerprint, with their crates; two of digest's features and crypto-common's that
  other members turn on in the workspace build.

## The stamp (DECISION PENDING, Q345)
The plan reads every stamp through core's header reader (C-045). `veredas-core` pulls its OPC UA
client, tokio, socket2, regex and chrono unconditionally, and its `schema` needs only serde, toml
and thiserror; asked of core through the orchestrator on 2026-11-23 (a default feature holding the
network layers; docs/questions.md Q345). The first commit (`fd086b5c`) read the two keys with
Ábaco's own function; the confrontation below found it had drifted from C-045 at once. Now the
stamp is read by core's own `src/schema.rs`, compiled into Ábaco by path (`#[path]`): the one
reader's code, its order and texts, no copy; it becomes `use veredas_core::schema` the day Ábaco
can depend on core.

## Refute round 1 (2026-11-23): refuted, answered
At `b8affb1b`. Held: numbers bit-exact through the real JSON route (-0.0, 5e-324, `f64::MAX`,
0.1+0.2, 1e15, 2^60); a styled spilled cell, a 2x3 legacy array; `differences` covering every
field of the workbook and the sheet (shared strings and formulas through each cell's text); no
sheet lost by the export over the corpus; the stamp format first; nothing run. Answered
(`tests/abacofile.rs`):

1. **A file the writer wrote was refused when read back**: the engine shows `NIMPL` as `#N/IMPL`
   while its English names hold `#N/IMPL!`; an `e` is read in either spelling (`error_named`).
   `every_error_the_engine_holds_reads_back_…`: an error cell of each of the engine's twelve and a
   formula computing `#N/IMPL` (`FORECAST.ETS`) written and read back the same.
2. **`nan` in a cell read as an empty cell** (the cells went through the JSON route, NaN to null):
   the cells are read apart, each with TOML's own types; `n = nan` and `n = inf` are no finite
   number, `nan` for a text, a boolean or a formula is the wrong type.
3. **A key nothing reads inside a link or a format's rule was dropped** (internally tagged enums,
   read from serde's buffer, which `serde_ignored` never sees): such an object's keys are held to
   the value written back, which these types write whole (`unread_in_tagged`); a link's `targett`
   and a rule's `stop_if_ture` refused by their paths.
4. **A cell's refusal raised by deserialisation named no address**: each cell is deserialised
   alone, its refusal prefixed with its address (`B4: unknown field`, `B1: invalid type`).
5. **The kept part's bytes were never checked**: the test reads them back from the file written
   again, byte for byte, and through a second read.
6. **The `.bak` and the file beside the destination were not proven** (two writes of the same
   bytes): a cell changed between them; the new file in place, the replaced one as `.bak`, nothing
   else beside them (no `.tmp`).
7. **Malformed files accepted**: a style past the workbook's styles or negative, one cell stated
   under two spellings (`b1`, `$B$1`: an address is written as Ábaco writes it), a manifest with no
   sheet, a reference's `sha256` not 64 lowercase hex digits or its `modified` not RFC 3339 in UTC
   to the second (`is_rfc3339_utc`, a real day of its month): each refused by its place.

## Refute round 2 (2026-11-23): refuted, answered
At `23509c57`. Held: every error in either spelling, as a value and as a cached value; `+inf`,
`-inf`, `-nan`, `+nan` refused per cell; unknown keys in `[[sheets]]`, `[[reference]]` and a state

the round trip's spill filter hiding nothing (removed, the corpus still round trips); no panic on
a bad `dxf_id`, `font_id`, merged cell, link position or `sheet_id`; nothing run. Answered
(`tests/abacofile.rs`, `src/abacofile.rs`, `src/files.rs`):

1. **A text or formula holding a line break spanned several lines** (the toml crate writes such a
   string `"""` multi-line; six corpus workbooks, 17 extra lines): strings are written by hand on
   one line, every control character escaped (`quoted`). The corpus round trip counts each sheet's
   `[cells]` lines against its keys; a test writes texts with line breaks, tabs, quotes, U+0007 and
   U+007F and `CHAR(10)` formulas, one line each, read back equal; a unit test reads every ASCII
   character back.
2. **A key nothing reads below a tagged object was dropped** (a colour scale's or an icon set's
   threshold, `colr = …`): once inside an object holding `type`, every object below has its keys

3. **A row's or a column's style past the workbook's was read, and the engine panicked on it**:

4. **A formula's `v` was never checked**: a NaN, an infinity, a table, an array, a date-time, and a

5. **A workbook Ábaco opened could be saved to a file its reader refused** (a `NaN` column width or

   refusing it would refuse saving such a workbook. The engine's own identifier rule (ASCII letters

7. **The engine's refusal of the settings named no part**: `workbook.toml: \`settings\`: …` (the

8. **An integer no double holds was rounded** (`9007199254740993`): refused in `n` and `v`.
9. **A TOML date-time was taken where the engine holds a text** (`dimension`, `metadata.created`):

10. **A failed write left `<name>.tmp`** (a `.bak` that cannot be replaced): any failure after the
