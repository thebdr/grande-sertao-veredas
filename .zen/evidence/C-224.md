# C-224 evidence: the `.abaco` file

## What it is (2026-11-23)
Phase 3 of `docs/abaco-plan.md`: `veredas_abaco::abacofile` (the file) and `workspace` (the
session), ported from Veredas 1's `abacofile` and `workspace` with its JSON parts made stamped TOML
(`docs/abaco-file.md`). Changed on the way:
- One line per cell in the sheet's `[cells]` table, an inline table keyed by the address, where
  Veredas 1 wrote tab-separated lines with its own escapes: TOML's strings carry any text.
- Every TOML part states its own format (`veredas-abaco`, `veredas-abaco-workbook`,
  `veredas-abaco-sheet`, `veredas-abaco-references`, `veredas-abaco-records`,
  `veredas-abaco-state`), so a part in the wrong place is refused by name.
- The engine's structures (styles, theme, names, a sheet's structure) pass through JSON: their
  `Color::None`, a unit variant of an untagged enum, serialises as JSON's null, which TOML cannot
  hold (`toml` refused the corpus's every workbook, "unsupported unit type"); a null is written
  `nan`, which no JSON value holds. The stamp is written first by hand, as the JSON route sorts
  keys.
- Tools' records are TOML tables (Veredas 1's were JSON values); TOML has no null.
- Veredas 1's `prefs.json` and `history.json` parts are not carried here: the preferences are
  phase 4's; a part this Ábaco does not read is kept anyway.
- New dependencies, reviewed in C-220's test: `toml` (already the workspace's) and `sha2` for a
  reference's fingerprint, with their crates; two of digest's features and crypto-common's that
  other members turn on in the workspace build.

## The stamp (DECISION PENDING, Q345)
The plan reads every stamp through core's header reader (C-045). `veredas-core` pulls its OPC UA
client, tokio, socket2, regex and chrono unconditionally, and its `schema` needs only serde, toml
and thiserror; asked of core through the orchestrator on 2026-11-23 (a default feature holding the
network layers; docs/questions.md Q345). The first commit (`fd086b5c`) read the two keys with
Ábaco's own function; the confrontation below found it had drifted from C-045 at once. Now the
stamp is read by core's own `src/schema.rs`, compiled into Ábaco by path (`#[path]`): the one
reader's code, its order and texts, no copy; it becomes `use veredas_core::schema` the day Ábaco
can depend on core.
