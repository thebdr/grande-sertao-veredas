# C-112 evidence - the PROFINET device, discovery and naming

## Built (2026-11-22)

The third bench device of P-020, its first slice: `src/profinet.rs`, `tests/profinet_device.rs`.
It carries Veredas 1's `pnsim` in purpose (a device answering DCP Identify and sending LLDP) but
none of its code: it stands on aranha's codecs and raw link as they are ported now (C-131 to C-134),
the way Q5 set it, so the scanner and the bench cannot drift apart on the wire. What aranha asked
for its scanner (relayed 2026-11-22) is this slice: Hello at start; Identify by all, name and alias
within the response delay; LLDP with the PROFINET fields; Set of name, IP and signal with the
three-byte reply. Veredas 1's pnsim never answered a Set.

How it is built, and why:
- **One thread on a raw link** filtered to PROFINET's EtherType, its own outgoing frames left out
  (aranha's `Options { outgoing: false }`), polling every 5 ms; LLDP goes out on the same link.
  Answers to an Identify wait in a queue until their spread is due.
- **The spread** is drawn from the device's own seeded stream within (factor - 1) x 10 ms, so a run
  repeats under one seed.
- **An unnamed device** (empty station) answers no Identify by name, an empty name included: a
  device fresh from its box is found by an Identify of all.
- **A refused name** keeps the old one and answers 0x05 ("set not possible"), the name checked by
  aranha's `check_station_name`, the standard's rule.
- **Linux only** for the device's run, as aranha's link is; the configuration loads everywhere, so a
  bench file reads on any platform and a device's start says why it cannot run.

C-024 changes with it: the bench's dependency graph admits aranha beside core (the map's row and
Q5 already did); its test's allowed list names both, any other member still refused.

The independent reader is tshark 4.6.6 (in the home folder): the device and the test's controller
share aranha's codecs, so the dissectors read every frame the device sends.

## Refute round 1 (2026-11-22): refuted, answered

Eleven mutants were tried and ten passed the test; the critic's probes found two real defects and
the claims no assertion held. What changed:
- **The shutdown frame was malformed**: it carried PROFINET's chassis-MAC TLV, which 802.1AB
  forbids in a shutdown PDU (tshark: "TLV type 0x7F not allowed in Shutdown PDU"). It now holds the
  chassis, the port and the TTL alone; tshark reads it last in a capture, clean.
- **An unnamed device sent no LLDP at all**: aranha's encoder refuses an empty chassis id and the
  device swallowed the error. An unnamed device's chassis is now its MAC (subtype 4).
- **A name that is not text** was answered 0x02 (a suboption it lacks) though the device holds
  NameOfStation: now 0x05 and kept.
- **A mute let a queued answer out** (772 ms after it, at a factor of 200): answers waiting out
  their delay are dropped while muted, and an Identify answer is counted as it goes out (counted
  after the send, a client reading its answer could find it not yet counted: the reference's
  bench-file test did, once, in a full run).
- **A Get of a pair it lacks** was answered with nothing: each such pair is now a control
  response 0x02 ("suboption not supported or no DataSet available"), every pair in the order asked.
- **Frame ids** were not checked: a request under another service's frame id is now dropped.
- **Identify filters**: by vendor, by vendor and device ids, by role, by IP suite and by MAC now
  match as the standard allows; any other filter never matches (the clause says so).
- **The identification signal**: only 0x0100 (flash once) is counted; another value is refused 0x05.
- **Validation**: a port is `port-xyz` or `port-xyz-abcde` (xyz 001 to 255); an alias is a port
  name, a dot and a station name. An over-long alias had silenced the device's Hello and answers.
- **Unpinned claims, now pinned** (the critic's probes, kept in the test as its `round_1` module):
  a four-block Set answered block by block, a Get's exact pairs and frame id, Sets and Gets not
  addressed to it dropped, the spread across twelve answers, LLDP's interval, the MAC, a conflict
  keeping the address set, the counts.

Not taken: a DeviceInitiative block in the Hello, (2,6) in DeviceOptions, a source MAC apart from
the chassis MAC, and checks on the IP suite; the critic could not ground them and the clause does
not claim them.

## Refute round 2 (2026-11-23): refuted, answered

Round 1's answers held in the code; fifteen mutants still passed the test, each caught by a probe
of the critic's (`~/.cache/veredas/critic-c112-r2/probes`), now the test's `round_2` module.
- **A damaged IP suite or signal block** was answered 0x02, "suboption not supported", though the
  device holds both (it lists them and applies them): the class round 1 fixed for the name. A block
  of a suboption it holds that it cannot read is now 0x05.
- **An LLDP interval past u64::MAX / 4** passed the check and overflowed the TTL's product, the
  thread's panic silencing the device's DCP. The interval is now bounded by 802.1AB's longest (an
  hour) and the product saturates.
- **Round 1's mute pin failed once on a correct device**: replacing `seed = 3` dropped the seed, and
  the clock's draws at a factor of 200 come under the 30 ms before the mute one time in 65. The seed
  is kept, and the pin asserts the dropped answer uncounted (a count at queue time passed before).
- **Unpinned claims**, each with a surviving mutant, now pinned: the vendor, role, IP-suite and MAC
  filters and a filter of another kind; a mute silencing Set and Get; an unnamed device's chassis its
  MAC; the shutdown's chassis and port; LLDP following a rename; a Get under another frame id and a
  Set that is no request dropped; an alias's halves and the port range; a misspelled key in the
  configuration read alone.
- **Wording**: an empty name is taken (the device unnamed), as an engineering tool clears a name; "or
  a stop" left the count's claim (a stopped handle is gone, so nobody reads its count); three bad port
  names, not four; the refusal off Linux is named but no test on this machine reaches it.

## The mute's moment (2026-11-23, after the orchestrator's whole-suite run at 081ffa70)

One run of round 1's mute pin went red on `main` at 081ffa70: an Identify answer read 94 µs after
the test began the mute, counted. That commit came before round 2's answer kept the pin's seed, so
its answer could fall due right at the 30 ms mute; but the race was the device's too: `set_muted`
was a bare flag, and the thread could read it clear, then count and send while the call returned.
Ruled: once `set_muted(true)` returns, no DCP frame leaves. The flag is now set under the state's
lock, and every DCP answer (an Identify falling due, a Set, a Get) is decided and sent under that
lock, so an answer either left before the call took the lock or never does. The new pin holds the
count to it: read when the mute returns, it equals every answer the controller ever receives, over
100 rounds of two hundred answers falling due around the mute at a factor of 2, so that one pass of the device's loop sends many. Against the bare flag it failed within ten rounds in three runs of three (a pass that had read the flag clear went on sending after the call returned); against the lock it passed five runs of five.

## Refute round 3 (2026-11-23): refuted, answered

Round 2's answers and the strict mute held in the code. The critic's probes and mutants are in
`~/.cache/veredas/critic-c112-r3/probes`; each finding is a pin in the test's `round_3` module.
- **A vendor text that is not ASCII silenced DCP**: it passed the check, then aranha's encoder
  refused every frame naming the device (its Hello, its Identify answers, a Get of it) and the device
  swallowed the error. The vendor is now 1 to 255 visible ASCII characters, refused by its text, as
  the reference says.
- **The shutdown after a rename named a chassis and port no frame had named**: it is now made of the
  identity the last LLDP frame named, so a neighbour forgets what it heard.
- **A mute lifted before the device's next pass dropped nothing**: the queue was cleared only when
  the device's thread saw the flag. A mute counter, moved under the lock, now marks every queued
  answer, and one queued before any mute since is never sent.
- **The strict mute was not pinned** (the 100-round pin reads the count under the same lock, so it
  cannot see a frame handed over after the mute returned): the critic's probe stamps every answer
  with the kernel's own send time (a packet socket with `SO_TIMESTAMPNS` on the device's end; `libc`
  a Linux dev-dependency for it) against the moment `set_muted(true)` returned. On the timed list:
  how often a burst meets the mute depends on the load.
- **Pinned too**: the Identify answer's frame id, the Hello's and the Set answer's; a Get too large
  for a frame, now neither answered nor counted.
- **Wording**: 0x02 for a suboption it lacks or does not set (the vendor, the MAC, the ids, the role,
  the options, the alias).

## Refute round 4 (2026-11-24): refuted, answered

Round 3's answers held, each reverted as a mutant and caught by its pin. The critic's probes and
mutants are in `~/.cache/veredas/critic-c112-r4/probes`; each finding is a pin in the test's
`round_4` module.
- **An Identify read before a mute was taken after it**: the Identify arm checked the mute only
  before the lock, where Set and Get check it again under it; a request read before
  `set_muted(true)` returned was matched, counted or queued with the counter as it stood after the
  mute, and, the mute lifted before the device's next pass, its answer left (42 to 82 of 3000
  rounds, instrumented; `identify_passed` moved during the mute in 73 of 1500). It is now checked
  under the lock too: neither taken, counted nor answered.
- **A Set whose answer would not fit one frame was applied and counted, never answered** (aranha's
  encoder refuses 1508 bytes and the device dropped the error), where a Get's is neither answered
  nor counted since round 3. It is now neither applied, answered nor counted.
- **Unpinned claims, each with a surviving mutant**: an empty interface and a refused station named
  only through the bench file, the file's defaults (an `lldp_interval_ms` of 0 by default passed),
  the Get's answer to the asker, the Set's answer a success.
- **Wording**: an unnamed device's LLDP port is `port-xyz`, as round 2 pinned.

## Refute round 5 (2026-11-25): refuted, answered

Round 4's answers held, each reverted as a mutant and caught by its pin. The critic's probes and
mutants are in `~/.cache/veredas/critic-c112-r5/probes`; each finding but the first is a pin in the
test's `round_5` module.
- **A request read before a mute lifted at once was taken after it**: round 4's check under the lock
  saw only a mute still on; with `set_muted(true); set_muted(false)` back to back, a request read
  before it and waiting for the lock found the flag clear (51, 42, 79 and 77 rounds of 750 for an
  Identify, an unmatched one, a Set and a Get, instrumented). The device now notes the mutes so far
  when it reads a frame (an atomic copy of the count `set_muted` bumps under the lock) and takes a
  request only when none came since; an Identify's answer is queued with that count. Unpinned by
  the test: no black-box test sees the moment a frame is read (one still in the kernel when the mute
  is lifted is rightly answered); the critic's instrumented probe `p9` gave 0 in every row with it.
- **Unpinned claims, each with a surviving mutant**: an Identify by ids it lacks, an Identify to
  another station, a group or the broadcast, the shutdown's destination, a port `port-xyz-abcde`
  taken, a Get's order with held and lacked pairs, a Get at the frame's edge, an alias filter on a
  device without one, a Get to the DCP group, LLDP while muted, the undecodable count.
- **Wording**: an Identify to the Identify group or its MAC, of one filter or more; a Get to its MAC;
  its LLDP going on while muted; a block of a suboption it sets (not one it holds and does not set,
  answered 0x02) refused 0x05.

## Refute round 6 (2026-11-26): refuted, answered

Round 5's black-box answers held, each reverted as a mutant and caught by its pin. The critic's
probes and mutants are in `~/.cache/veredas/critic-c112-r6/probes` (`README.md` replays them); each
black-box probe is a pin in the test's `round_6` module.
- **A request read before a mute could still be taken after it**: round 5 noted the mutes just
  after the read, so a `set_muted(true); set_muted(false)` landing between the kernel read and the
  note let it through (instrumented, 2 rounds of 6000 and 5 of 16 000; 418 of 6000 with round 5's
  answer reverted). The frame is now read without waiting and the mutes noted under the one lock
  `set_muted` takes; an empty read waits a millisecond outside it, since aranha's link has no wait
  without a read. The critic's instrumented probe gave 0 of 16 000 with this read; no black-box test
  sees the moment, so the Verification names the probe.
- **A request from a group or the all-zero source was taken**, a Set applied and the answers sent to
  the group or the broadcast: no station sends from one (IEEE 802.3), so such a request is not taken.
- **An LLDP interval under the device's poll was not kept** (1, 2 and 4 ms all sent about every
  5.3 ms): an interval under 10 ms is refused, and the reference says so.
- **Unpinned claims, each with a surviving mutant**: an Identify of no filter (answered passed);
  the IP status not set without an address and after a Set of 0.0.0.0; a damaged block of a
  suboption it does not set answered 0x02 (0x05 passed).
- **Wording**: an Identify's answer names the device as it was when the request was taken (a rename
  between leaves it under the old name), now said and pinned.
- Noticed, not counted by the critic: Start and End Transaction blocks answered 0x02 (a real
  controller's captures, entry 26, will settle whether one wraps its Set in them); two PROFINET parts
  on one interface not refused (C-033's); a conflict flag kept across a Set of a new address.
