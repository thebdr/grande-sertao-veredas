# C-112 evidence - the PROFINET device, discovery and naming

## Built (2026-11-22)

The third bench device of P-020, its first slice: `src/profinet.rs`, `tests/profinet_device.rs`.
It carries Veredas 1's `pnsim` in purpose (a device answering DCP Identify and sending LLDP) but
none of its code: it stands on aranha's codecs and raw link as they are ported now (C-131 to C-134),
the way Q5 set it, so the scanner and the bench cannot drift apart on the wire. What aranha asked
for its scanner (relayed 2026-11-22) is this slice: Hello at start; Identify by all, name and alias
within the response delay; LLDP with the PROFINET fields; Set of name, IP and signal with the
three-byte reply. Veredas 1's pnsim never answered a Set.

How it is built, and why:
- **One thread on a raw link** filtered to PROFINET's EtherType, its own outgoing frames left out
  (aranha's `Options { outgoing: false }`), polling every 5 ms; LLDP goes out on the same link.
  Answers to an Identify wait in a queue until their spread is due.
- **The spread** is drawn from the device's own seeded stream within (factor - 1) x 10 ms, so a run
  repeats under one seed.
- **An unnamed device** (empty station) answers no Identify by name, an empty name included: a
  device fresh from its box is found by an Identify of all.
- **A refused name** keeps the old one and answers 0x05 ("set not possible"), the name checked by
  aranha's `check_station_name`, the standard's rule.
- **Linux only** for the device's run, as aranha's link is; the configuration loads everywhere, so a
  bench file reads on any platform and a device's start says why it cannot run.

C-024 changes with it: the bench's dependency graph admits aranha beside core (the map's row and
Q5 already did); its test's allowed list names both, any other member still refused.

The independent reader is tshark 4.6.6 (in the home folder): the device and the test's controller
share aranha's codecs, so the dissectors read every frame the device sends.

## Refute round 1 (2026-11-22): refuted, answered

Eleven mutants were tried and ten passed the test; the critic's probes found two real defects and
the claims no assertion held. What changed:
- **The shutdown frame was malformed**: it carried PROFINET's chassis-MAC TLV, which 802.1AB
  forbids in a shutdown PDU (tshark: "TLV type 0x7F not allowed in Shutdown PDU"). It now holds the
  chassis, the port and the TTL alone; tshark reads it last in a capture, clean.
- **An unnamed device sent no LLDP at all**: aranha's encoder refuses an empty chassis id and the
  device swallowed the error. An unnamed device's chassis is now its MAC (subtype 4).
- **A name that is not text** was answered 0x02 (a suboption it lacks) though the device holds
  NameOfStation: now 0x05 and kept.
- **A mute let a queued answer out** (772 ms after it, at a factor of 200): answers waiting out
  their delay are dropped while muted, and an Identify answer is counted as it goes out (counted
  after the send, a client reading its answer could find it not yet counted: the reference's
  bench-file test did, once, in a full run).
- **A Get of a pair it lacks** was answered with nothing: each such pair is now a control
  response 0x02 ("suboption not supported or no DataSet available"), every pair in the order asked.
- **Frame ids** were not checked: a request under another service's frame id is now dropped.
- **Identify filters**: by vendor, by vendor and device ids, by role, by IP suite and by MAC now
  match as the standard allows; any other filter never matches (the clause says so).
- **The identification signal**: only 0x0100 (flash once) is counted; another value is refused 0x05.
- **Validation**: a port is `port-xyz` or `port-xyz-abcde` (xyz 001 to 255); an alias is a port
  name, a dot and a station name. An over-long alias had silenced the device's Hello and answers.
- **Unpinned claims, now pinned** (the critic's probes, kept in the test as its `round_1` module):
  a four-block Set answered block by block, a Get's exact pairs and frame id, Sets and Gets not
  addressed to it dropped, the spread across twelve answers, LLDP's interval, the MAC, a conflict
  keeping the address set, the counts.

Not taken: a DeviceInitiative block in the Hello, (2,6) in DeviceOptions, a source MAC apart from
the chassis MAC, and checks on the IP suite; the critic could not ground them and the clause does
not claim them.
