# C-001 evidence - the laws' real walker, probed on a tree that breaks them

The synthetic tests in `tools/leis/tests/leis.rs` prove the laws as pure functions; this probe proves
that `Suite::read` sees a real tree the same way. It covers L1, L2, L3 and L6 (C-001, C-002, C-003,
C-006); L4 and L5 read the same manifests through the same parser.

## The probe (2026-11-05)

A copy of the repo in the scratchpad with three crates added:

| Crate | Listed | Version | Plan | Expected |
|---|---|---|---|---|
| `crates/Bad-Crate` | yes | 1.0.0 | - | L2 (the name), L3 (below 2.0.0) |
| `crates/veredas-perdido` | no | 2.0.0 | - | L1 (not a member); nothing else, it is not a member |
| `crates/veredas-semplano` | yes | 2.0.0 | none | L6 (no `docs/semplano-plan.md`) |

`cargo test -p leis --test leis the_real_tree_obeys_every_law` in the copy exited 101 with exactly:

```
L1 crates/veredas-perdido: has a Cargo.toml but is not a workspace member (list it, or exclude it)
L2 crates/Bad-Crate: a component is named veredas-<nome>, <nome> lowercase ASCII (got `Bad-Crate`)
L3 crates/Bad-Crate: version 1.0.0 is below 2.0.0 (every component starts at 2.0.0)
L6 crates/veredas-semplano: no docs/semplano-plan.md (a role nobody covers, written before the code)
```

Then the real tree, 35/35.

## Trap: never share `target/` between the copy and the repo

The first probe ran with `CARGO_TARGET_DIR` pointing at the repo's own `target/` to save a build.
Cargo keyed the copy's `leis` test binary like the repo's (same layout, same sources) and the next
`cargo nextest run` in the repo reused the copy's binary, whose `env!("CARGO_MANIFEST_DIR")` was
the scratch path: the real-tree test reported the copy's four violations against a tree with no
`crates/` at all. `cargo clean -p leis` and a rebuild put it right. A probe copy builds in its own
target directory, always.
