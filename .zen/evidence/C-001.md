# C-001 evidence - the laws' real walker, probed on a tree that breaks them

The synthetic tests in `tools/leis/tests/leis.rs` prove the laws as pure functions; this probe proves
that `Suite::read` sees a real tree the same way. It covers L1, L2, L3 and L6 (C-001, C-002, C-003,
C-006); L4 and L5 read the same manifests through the same parser.

## The probe (2026-11-05)

A copy of the repo in the scratchpad with three crates added:

| Crate | Listed | Version | Plan | Expected |
|---|---|---|---|---|
| `crates/Bad-Crate` | yes | 1.0.0 | - | L2 (the name), L3 (below 2.0.0) |
| `crates/veredas-perdido` | no | 2.0.0 | - | L1 (not a member); nothing else, it is not a member |
| `crates/veredas-semplano` | yes | 2.0.0 | none | L6 (no `docs/semplano-plan.md`) |

`cargo test -p leis --test leis the_real_tree_obeys_every_law` in the copy exited 101 with exactly:

```
L1 crates/veredas-perdido: has a Cargo.toml but is not a workspace member (list it, or exclude it)
L2 crates/Bad-Crate: a component is named veredas-<nome>, <nome> lowercase ASCII (got `Bad-Crate`)
L3 crates/Bad-Crate: version 1.0.0 is below 2.0.0 (every component starts at 2.0.0)
L6 crates/veredas-semplano: no docs/semplano-plan.md (a role nobody covers, written before the code)
```

Then the real tree, 35/35.

## Refute round 1 (2026-11-05)

Attacked: path spellings (`./`, a trailing slash, backslashes, `tools//leis`, case, `crates`,
`tools/leis/src`, globs, an absolute path, a trailing space), the shapes of `exclude`, a crate
listed and excluded at once, a `Cargo.toml` that is a folder, the reader on nested and root-level
manifests.

Refuted, fixed: the reader walked one level only, so `crates/abaco/veredas-abaco/Cargo.toml`,
`crates/Cargo.toml` and `tools/leis-extra/inner/Cargo.toml` were invisible and the real-tree test
could not tell. `collect_crates` now walks every depth (skipping `target/`, `node_modules/` and
hidden folders), a nested crate is its own L1 violation, and `l1_the_reader_finds_crates_at_any_depth`
plants such a tree and asserts the exact three. `exclude` covers what is beneath an entry, as cargo
reads it (`l1_an_excluded_folder_covers_what_is_beneath_it`, `l1_the_reader_sees_an_exclusion_as_cargo_does`).

Held: every spelling refused, or normalized as cargo normalizes it; exact-string assertions throughout.

## Refute round 2 (2026-11-05)

Attacked: a fixture manifest inside a member (found and named: exclude it, as cargo would need
too), a package nested inside a member and listed, `exclude` spellings (`crates/x/`, `./crates/x`
hide `crates/x` and what is beneath; `crates/x` does not hide `crates/xy`; a wrong case is refused;
`.` and `""` hide nothing), `exclude = ["crates"]`, a junction to a crate outside the repo (found
under its own path), a junction loop (the reader follows it until the path is too long, 151 s, and
still fails the tree), hidden and built folders skipped. Held; the clause now says "outside
`target/`, `node_modules/` and hidden folders" instead of a bare "any depth".

From the C-006 round, closed here: a `veredas-*` or `orcl-*` crate excluded from the workspace
dodged every component law. A suite crate (by name or by folder, `others` holds every found crate
parsed) is a member or nothing: excluding one is an L1 violation, behind an excluded parent too
(`l1_a_suite_crate_is_never_excluded`).

## Refute round 3 (2026-11-05)

Refuted on two: the never-excluded rule looked only under the roots, so a suite crate parked
elsewhere (`apps/veredas-portal` excluded, `bench/veredas-aranha` with its own `[workspace]`, a
`veredas-maquinar` at the repo root) built outside the workspace and no law read it; and an
underscore spelling (`veredas_portal`, `orcl_std`) passed the name check. The reader now walks the
whole repository (the root's own manifest, hidden, `target/` and `node_modules/` folders left out),
a suite crate elsewhere is an L1 violation whether excluded or not, and `is_suite_crate` reads `_`
as `-` (`l1_a_suite_crate_outside_the_roots_is_named`, `l1_an_underscore_spelling_is_the_same_suite_crate`,
`l1_the_reader_scans_the_whole_repository_for_suite_crates`). Held: a manifest that is not TOML
fails closed (the reader errors), a vendored fork with no `[package]` passes, a stray suite crate
under a root keeps its "not a workspace member" message, a hidden folder is left alone by the clause's
own words, a junction loop fails loudly rather than silently.

## Refute round 4 (2026-11-05)

Refuted on one: the reader skipped every hidden folder, so `.parked/veredas-portal` (with its own
`[workspace]`) or `docs/.old/veredas-portal` built outside the workspace unseen, and the round-3
test pinned the skip in place. Hidden folders are walked now (`.github` and `.zen` are committed
here; only `.git/`, `target/` and `node_modules/` are skipped, which the repository never holds), and
a nested suite crate gets the message that sends it under `crates/` as a member instead of a hint
to exclude it that L1 would then refuse. Held: `target/` and `node_modules/` at the top (ignored by
git, never in the repository), a suite crate under `docs/` named, a fixture suite crate named, a
listed top-level suite crate one message, a disguised folder named, an uppercase disguise passed
(the clause folds the underscore only), symlinks followed.

## Refute round 5 (2026-11-05)

Refuted on one: the reader skipped `target/` at any depth while `.gitignore` said `/target`, the top
one alone, so `apps/target/veredas-portal` (own `[workspace]`) was committed, built by itself, and
passed every law. The clause's "which the repository never holds" was false below the top. Now
`.gitignore` ignores `target/` at any depth (a crate built on its own, an excluded fork, makes one of
its own), and `l1_the_skipped_folders_are_ignored_by_git_at_any_depth` asks `git check-ignore` in
the real repository that `target/` and `node_modules/` are ignored wherever they sit and that
`apps/`, a dot folder and `crates/` are not, so the reader's skip list and git's ignore list cannot
drift apart unnoticed. Held: a nested `.git` cannot be tracked, a submodule's checkout is walked,
a non-suite stray in `.cargo/` or `.github/` ignored, an unreadable folder errors loudly.

## Refute round 6 (2026-11-05)

Refuted on one, and it ends the line of attack of rounds 3 to 5: a nested `.gitignore` saying
`!target/` un-ignores the folder, and `git add -f` takes an ignored path, so no list of folder
names can honestly claim "the repository never holds it". The reader asks git now: `git ls-files
--cached --others --exclude-standard` is what the repository holds or could hold, and every
`Cargo.toml` and plan it lists is what the laws see, wherever it sits; a tree that is no
repository is refused (`l1_the_reader_sees_what_git_would_take_not_what_a_name_suggests`: the
un-ignored `bench/target/veredas-parked` and the forced `web/target/veredas-forced` named, the
ignored `target/veredas-built` left out, a tree without git an error). The skip list and the
check-ignore test of round 5 are gone with their claim; `target/` stays ignored at any depth in
`.gitignore` as good hygiene. Held: `check-ignore --no-index` reliable, a `Target` folder on
Windows no escape.

## Refute round 7 (2026-11-05)

Refuted on two edges the git listing opened: a manifest spelled `cargo.toml` is listed by git and
built by cargo on Windows (the filesystem ignores case) but matched nothing; and a submodule's
folder is listed by git while its files never are, so a suite crate brought in as a submodule was
invisible. The reader matches the manifest's name ignoring ASCII case, and reads `git ls-files -s`
for the mode-160000 entries, each a found crate by its folder, with its manifest when checked out
(`l1_the_reader_takes_a_manifest_in_any_case_and_a_submodule_by_its_folder`: `apps/veredas-portal/cargo.toml`,
a real `git submodule add` at `vendor/veredas-aranha`, and a bare pointer `bench/orcl-bancada`, all
named). Held: an untracked folder listed file by file, a space and a non-ASCII name through `-z`,
a tracked file deleted from the tree gone, a `git rm --cached` file seen again as untracked.

## Trap: never share `target/` between the copy and the repo

The first probe ran with `CARGO_TARGET_DIR` pointing at the repo's own `target/` to save a build.
Cargo keyed the copy's `leis` test binary like the repo's (same layout, same sources) and the next
`cargo nextest run` in the repo reused the copy's binary, whose `env!("CARGO_MANIFEST_DIR")` was
the scratch path: the real-tree test reported the copy's four violations against a tree with no
`crates/` at all. `cargo clean -p leis` and a rebuild put it right. A probe copy builds in its own
target directory, always.
