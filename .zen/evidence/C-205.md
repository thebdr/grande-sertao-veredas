# C-205 evidence - the executable

## The design (2026-11-23)

A shell over the library, as portal's and the bench's executables are: `check` (from phase 1,
now one command of three), `run` and `replay`. A run starts the plant's portal session from its
project file in this process (Q313 (a), taken meanwhile; supervisão's Q19 the precedent), waits up
to 30 s for the OPC UA sources and the channels to read live (a log reads when its lines come; the
binding and the waits say what is missing), runs, keeps the run and stops the session. The switch
stands where the project put it (C-200: the crate never arms it).

A replay needs the window in the session's store, and a fresh session holds only what its start
reads in: a log backfilled from a start in the past (C-037). It waits until the ingest's count of
lines holds still across two refreshes (600 ms apart) before it runs. Replaying a window of a
session that is no longer running needs a store opened read only, which is portal's (named in the
plan as later).

The exit codes tell a pipeline what happened without reading the output: 0 passed (or a sound
file), 1 failed (or a file with problems), 2 the command line, 3 aborted, 4 refused before
anything ran, or no session.

## Refute round 1 (2026-11-23): refuted, three findings, all closed

1. **A replay could start before the log was read into the store**: the wait compared its own
   readings of the line count, 600 ms apart, and took two readings of 0 as settled, while portal
   publishes its counters only at a refresh (after a pass, at least 500 ms apart); a log of
   200 000 lines replayed on an empty store 7 times in 8, each kept as an aborted run. The replay
   now waits for every log to read its first line (30 s at most: an empty log reads none), then
   for the line count to hold still across two refreshes, a refresh known by a new count of the
   pump's passes; a read-in still moving after 10 minutes refuses the replay (4).
2. **A run that ran but could not be kept exited 4**, the code for a run refused before it
   started. The test's folder is now made before the session starts (refused with 4 when it
   cannot be, the plant untouched), and a run that ran and then could not be kept exits 5 with
   its verdict printed.
3. **An option's value that was another option** (`--project --runs`) was read as a path, and an
   option given twice took the last copy. Each option is given once with a value that is not an
   option, or the command line is wrong (2).

What held: an inverted window (4, the binding's text, nothing kept), a session that does not
start (4), an OPC UA source that never reads live (30 s, then the run, its waits naming what is
missing), a replay of an empty log, the `T` form of a moment refused (2), the switch never armed,
the session stopped on every path.


## A red run beside other tests (2026-11-23)

`replay_reads_the_window_the_project_s_start_fills` found 5 rows in its run's evidence where 6
were due, once, in the suite under load. The test's own setup: each log line was stamped from a
fresh reading of the store's now and the window's start from a later one, so a stall of more than
500 ms between writing the first line and taking the start put that line before the window. A
stall of 600 ms injected after the first line reproduces it (5 against 6). The lines and both ends
of the window are now placed from one moment taken once (`log_line_at`), the injected stall leaves
the test green, and the wait is asserted exactly: held after 5500 ms, the sixth line. Nothing in
the executable changed.

## Refute round 2 (2026-11-24): refuted, three findings; two closed, one narrowed (Q319)

What held: the options in any order, given twice, a value that is another option, `--opt=v` and a
bare `--` (2); `--runs` naming a file, a broken project and an inverted window refused before the
run (4, nothing on stdout); exit 5 with the verdict on stdout, the session stopped and the run's
folder empty; the session stopped on every early return; the switch never touched.

1. **A log family with empty members let the replay start before its read-in ended** (one member
   of three lines 90 minutes old, 5 to 20 empty members, the newest holding the window's lines):
   portal reads each older member whole and waits for it to hold still before the next, so the
   empty ones pause the start past two still refreshes (about a second), and the replay ran over
   a store without the window, kept aborted (5 empty members: 2 runs of 3, 8: all). Portal shows
   no read-in's end: the stillness stays a guess, the claim narrowed and the limit stated in the
   clause, `DECISION PENDING (Q319)` in `main.rs`, portal asked through Q319 to publish the end.
   Reproduced after this round's change too (an aborted run in 1.3 s): a line after the window
   only ends the wait sooner, it does not hold it longer.
2. **A log the plant keeps writing kept the replay waiting** (a line stamped now every 100 ms:
   38 s to past 150 s on the loaded machine, refused at 600 s on a quiet one): the ingest's count
   of every line was what had to hold still. Portal reads a log in its stamps' order and stores a
   pass's lines before it shows the pass's health, so a log that has read a line stamped after the
   window's end has read the window: it is done, once and for all, and only the other logs' own
   counts must hold still. The critic's case beside a quiet log now passes in 1.9 s; the old wait
   was still waiting at 150 s. The 600 s refusal is now reachable by a test
   (`VEREDAS_COMISSIONADOR_READ_IN`): the 200 000-line log given one second is refused with its
   text, nothing run, nothing kept.
3. **An empty `--runs` kept the run in the working folder**: an empty value is now a wrong command
   line (2), for every option (an empty `--project` was 4).

Trivial, closed with it: a refused run left its new test folder behind; the folders made for a
refused run (4) are removed, deepest first, an existing one kept.

## Refute round 3 (2026-11-24): refuted, four findings, all closed

What held: the session stopped on every path, the switch never armed, exit codes 0 to 5, stdout
empty on 4; a family with its lines in order and a stamped live log beside the window's log
replaying as they should. Trivial, left: `VEREDAS_COMISSIONADOR_READ_IN` not a number falls back to
600 s (a test's knob); a value of blanks is taken as it is (`--runs " "` a folder so named).

1. **A line stamped past the window but early in the read-in ended the wait** (round 2's rule): a
   family whose rotated member held a late line 20 s past the window had it read before the newest
   member, a refresh in portal's pause after it saw it, and 4 replays of 17 ran with no row of the
   window. A stamp past the window is not the present. A log is now done once it has read a line
   stamped at or after the session's start (its files read whole, the newest last); the late line,
   an hour old, leaves the log to the stillness of its lines. The test, an empty member giving the
   pause half a second, replays the family twelve times at once: each passes with six rows, where
   the old rule aborts.
2. **A log with no stamps written live got every replay refused**: its lines are indexed on their
   arrival and never ended. Such a log holds none of a window that ended before the session
   started, and is done for it; the critic's case passes in 1.2 s, where the old wait was refused
   at its bound.
3. **The folders made part of the way, when a run's folder could not be made, stayed** (a test id
   of 300 letters): the removal ran only after the session's refusals. The folders are now made
   one by one and those made are removed on every refusal.
4. **A `..` in `--runs` removed a folder already there**: the folders taken as made were the
   path's lexical ancestors not yet there, `new/../existing` among them. Only a folder this run
   created is counted as made now, so `existing` stays and `new` goes.
