# C-205 evidence - the executable

## The design (2026-11-23)

A shell over the library, as portal's and the bench's executables are: `check` (from phase 1,
now one command of three), `run` and `replay`. A run starts the plant's portal session from its
project file in this process (Q313 (a), taken meanwhile; supervisão's Q19 the precedent), waits up
to 30 s for the OPC UA sources and the channels to read live (a log reads when its lines come; the
binding and the waits say what is missing), runs, keeps the run and stops the session. The switch
stands where the project put it (C-200: the crate never arms it).

A replay needs the window in the session's store, and a fresh session holds only what its start
reads in: a log backfilled from a start in the past (C-037). It waits until the ingest's count of
lines holds still across two refreshes (600 ms apart) before it runs. Replaying a window of a
session that is no longer running needs a store opened read only, which is portal's (named in the
plan as later).

The exit codes tell a pipeline what happened without reading the output: 0 passed (or a sound
file), 1 failed (or a file with problems), 2 the command line, 3 aborted, 4 refused before
anything ran, or no session.
