# C-025 evidence - log emitters

## The port (2026-11-06)

From Veredas 1's `crates/veredas-maquinar/src/logsim.rs` (its inline tests and
`tests/logsim.rs`), now `src/emit.rs` and `tests/emitters.rs`. The family-contract test stays
with portal: the scanner it pins (`FamilySpec`) is the data plane's (P-002).

Changed:
- `EmitterConfig` reads from TOML (`deny_unknown_fields`, `encoding` spelled `utf-8` or
  `utf-16le`, `max_lines`, `encoding` and `seed` defaulted); no `enabled` flag (a bench file's
  emitter runs; a stopped one is removed);
- `file_pattern` is `file`; `family_spec_for` is `family_shape`, returning a `FamilyShape`;
- errors are typed: `NameError` (unchanged variants, `Display` as Veredas 1's text), `EmitError`
  (`Name`, or `Io` with the action, the path and the message) in the status instead of a
  `String`, and `spawn` returns `Result<EmitterHandle, SpawnError>` instead of swallowing a
  thread that could not be spawned;
- a `seed` in the config replays the same values; without one the clock seeds the draws, told
  apart by the stream the caller gives;
- `EmitterHandle::join` stops and waits; the drop does too (Veredas 1's did);
- the interval sleeps in slices of `SLICE` (100 ms), a public constant;
- the write error's path is the file's, not just "writing: ...".

Pinned beyond Veredas 1: rendering edges (a lone percent, a stray `}`, `{}`, a name twice, a
negative value at zero decimals); draws replayed by seed; naming with `{n}` anywhere and twice,
index 0, a tail that is no extension, trimmed whitespace, every forbidden character and a
control character; the rotor's first file as a rotation, the same day late, a bad pattern leaving
it untouched, index 0 read as 1; the family shape for dotted and dashed dates, two-digit fields,
an escaped metacharacter, matched against the names the pattern renders (through core's capture
engine, the regex engine the bench has); a seeded pair writing the same lines; a restart without
count rotation; the blocked folder's error typed with its action and path, the worker still
alive; the BOM exactly once; a stop under a second at a minute's interval; the TOML defaults and
three misspellings.

## Two defects inherited from Veredas 1, found by the shape test (2026-11-06)

The shape's date group and its date format disagreed. Veredas 1's `family_spec_for` put a dotted
or dashed date's separators inside the regex group (`(?P<date>\d{2}\.\d{2}\.\d{4})`) but built the
format from the specifiers alone (`%d%m%Y`), so a reader given both never parsed `28.07.2026`.
And a pattern without `{n}` rotates by inserting `_<n>` before the extension, while its shape
matched the bare name alone, so a family rotated on count lost every sibling past index 1.

`family_shape` now reads the pattern into pieces: the date group runs from the first specifier
to the last one reached through single literal separators and the format holds exactly what the
group covers; a specifier beyond a longer literal (`%Y_T%m`) stays outside as digits of the name;
a pattern without `{n}` gets `(?:_(?P<idx>\d+))?` where `file_name_for` inserts the index. The
test renders names for eight patterns at indices 1, 2 and 10, matches each against its shape
(through core's capture engine), checks the index group against the index (absent for a bare
index 1), and parses the date group with the date format, requiring the year back. Worth porting
to Veredas 1 by its owner.

## Refute round 1 (2026-11-06): refuted

Found and fixed:
- **A restart appended past a gap in the family** (the serious one). `first_free_index` stopped
  at the first missing index, and a count rotation moved to the next index without checking
  whether that file existed, so with `run2`/`run3` present and `run1` archived the new run
  appended to both. Inherited from Veredas 1. The emitter now skips, on every move to a new file
  (the first, a count, a day), any name that already exists, up to `MAX_SKIPS`; pinned with a gap
  on disk, the old files byte-identical. The same fix covers a pattern naming no whole day,
  whose day change came back to an earlier file within one run.
- **The shape escaped every non-alphanumeric literal**, so a non-ASCII name (`Medição`) gave a
  regex the engine refuses, and two `{n}` gave two groups of one name. Only the metacharacters
  are escaped now (the hyphen literal outside a class), a second `{n}` is matched as digits; both
  patterns are in the rendered-names loop.
- **A trailing dot was accepted**: Windows drops it, so the file on disk was not the name
  reported and the shape never matched it. A name ending in a dot or a space, or a reserved
  stem (`CON`, `NUL`, `COM1`...), is refused by name.
- **"Retried" was shown by a different emitter.** The blocked emitter's test now removes the
  blocker and waits for that handle's first line and a cleared error.
- **The stop bound was ten times the claim**: asserted under a slice plus 300 ms.
- **"One clock" had no test across midnight.** The worker's body is a `Writer` that writes one
  line at the instant it is given; the test drives it at 23:59 and 00:00 and reads both files.

Held: `safe_format` on 26 formats chrono rejects; `{n}` before the date, a date-only name, a
pattern ending in `{n}`, literal spaces and punctuation; surrogate pairs in UTF-16; a zero
interval; the TOML defaults; `lines_in_file` after a rotation.

## Refute round 2 (2026-11-06): refuted

The existence check ran only on the call where the rotor rotated. When that call's open failed
(the folder away) and a later call found the folder back holding an earlier run's file of the
name the rotor had moved to, the writer appended. And when `MAX_SKIPS` ran out, it appended to
the last name with no error. Both fixed: the writer claims the one name it has itself opened,
and checks for existence before opening any other name, whenever that happens; when every name
tried exists it writes nothing and reports `NoFreeName` (the limit is lowered by a test). Held:
a name that exists as a folder, the clock moved back a day and forward again, a rendered `{n}`
re-read by chrono (refused as a bad format), `%e`'s padding, the reserved names (on this
Windows 11 `COM0`, `COM¹` and `CONIN$` write as ordinary files and are not refused). The
critic notes the second `{n}` matched as digits makes the family shape looser (a name the
pattern never renders, `run_2026_1_2.log`, matches with index 1): the clause says so; a stricter
shape would need a backreference the regex engine does not have.
