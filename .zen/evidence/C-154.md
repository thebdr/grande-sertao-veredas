# C-154: orcl-interp's program file

## What it is, 2026-11-25
The second step of `docs/orcl/interpreter.md` ("Built in this order"): `orcl_interp::file`, the codec of
`<name>.orclb`. The format is the interpreter's own, with no dependency, since a controller reads its program for
decades and the file should not lean on a crate's encoding (the design's own reason).

How the tests stand against the clause (`tests/file.rs`):
- **Canonical**: the codec writes every count, integer and float at a fixed width, a `bool` and every tag as one
  byte, and reads only those values back. So a file it accepts writes back to the very same bytes, which the
  damage test checks for every accepted copy: every byte of a file holding every kind, damaged three ways (`^0xFF`,
  `^0x01`, `^0x80`), is either refused or read to a program that writes back to the damaged bytes.
- **Pinned**: one small program's bytes are written out by hand, so a change to the format shows as a failed test
  and is made on purpose, with the format's version.
- **The header first**: a language the interpreter does not run is said as such even when the rest of the file is
  damaged, since the reader stops at the language's number.
- **Memory**: a count is refused when it is larger than the bytes left, each counted thing taking at least a byte;
  the reader also never reserves memory ahead of the things it has read.

Not claimed: that the program read fits its types (C-153's loader says so); integrity, which is the download
manifest's (Q36).
