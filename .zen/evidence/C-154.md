# C-154: orcl-interp's program file

## What it is, 2026-11-25
The second step of `docs/orcl/interpreter.md` ("Built in this order"): `orcl_interp::file`, the codec of
`<name>.orclb`. The format is the interpreter's own, with no dependency, since a controller reads its program for
decades and the file should not lean on a crate's encoding (the design's own reason).

How the tests stand against the clause (`tests/file.rs`):
- **Canonical**: the codec writes every count, integer and float at a fixed width, a `bool` and every tag as one
  byte, and reads only those values back. So a file it accepts writes back to the very same bytes, which the
  damage test checks for every accepted copy: every byte of a file holding every kind, damaged three ways (`^0xFF`,
  `^0x01`, `^0x80`), is either refused or read to a program that writes back to the damaged bytes.
- **Pinned**: one small program's bytes are written out by hand, so a change to the format shows as a failed test
  and is made on purpose, with the format's version.
- **The header first**: a language the interpreter does not run is said as such even when the rest of the file is
  damaged, since the reader stops at the language's number.
- **Memory**: a count is refused when it is larger than the bytes left, each counted thing taking at least a byte;
  the reader also never reserves memory ahead of the things it has read.

Not claimed: that the program read fits its types (C-153's loader says so); integrity, which is the download
manifest's (Q36).

## 2026-11-25, later: an implications check
Against C-153 and C-045, which the turn-end gate flagged: distinct from both, and the clause now says how. It also
found two silences, now stated: format 1 holds no table of entries (the design named one; a host finds an entry by
its function's name, and a table comes with a new format version if the front end needs it), and the nightly is
read and kept but not judged (which nightlies a controller runs, Q222, is controlador's, not yet built). The
design's magic is written as the code has it, `ORCLB\0`.

## Refute round 1 (2026-11-25): refuted, high weight; answered
At 68376f68. The one pinned program covered only the header, a `bool` type, a `bool` constant and `Return`, so
swapping two codes in both the writer and the reader (`+` and `-`, `i8` and `u8`, the plain and checked operation
tags, `min` and `max`) passed every test, while old files would run the wrong operation silently. Answered: the
every-kind program's bytes are pinned against `tests/every_kind.orclb`, written once by an ignored test kept for a
change of format made on purpose, and read back to that program. Also answered: the language checked before the
format (a format-2 file is now said to be format 2 whatever its language field holds, and with nothing after its
format); an integer outside its type, and a `bool` of 2, accepted (each now refused at its byte); a count equal to
the bytes left refused (an empty program now reads back). The critic's fuzz of 60 000 files damaged at one to four
bytes, or with a byte inserted or removed, found no panic, and every file it accepted wrote back to its bytes.

## Refute round 2 (2026-11-25): refuted, low weight; answered
At eb68e9d3. Round 1's six file mutants all killed now. Survivors, both low: a bad tag's position taken after its
byte was read (no test checked where a bad tag is refused; now a type's, a value's, an operand's, a scalar's and a
terminator's tag are each refused at their own byte), and a count held against the whole file instead of the bytes
left (the test used `u32::MAX` alone; now a count one past the bytes left is refused at the count, for the
functions and for a function's blocks). Contrived: the reader reserving `with_capacity(n)` for a count, still
bounded by the bytes left. The fixture `tests/every_kind.orclb` was checked to equal the writer's output and to hold
every tag of the model.

## Refute round 3 (2026-11-25): refuted, low weight; answered
At f79d1309. Survivors, all low and of round 2's class: an integer type's, a projection's and a core operation's
tag refused a byte late. The test pinned five kinds of tag; now every kind of tag the reader takes (fourteen sites)
is refused at its own byte, each found as the first byte two programs differ at. `g03` passes, contrived.

## Refute round 4 (2026-11-25): holds
At 908209b9. All earlier file mutants killed but `g03` (a reader reserving its count, still bounded by the bytes
left: contrived, as round 2 left it). Three new mutants (format 0 accepted, a local name's tag of 1 to 200
accepted, a reference slot written as a `u16` both ways) all killed. A fresh fuzz damaged `every_kind.orclb` 60 000
times: 46 074 copies refused, 13 926 accepted, every accepted one writing back to its own bytes, and 13 918 of them
loaded on a thread of 8 MiB with no panic, the slowest in 0.29 ms. The reader does not recurse, and its memory
grows linearly with the file. Nothing survives above contrived weight.
