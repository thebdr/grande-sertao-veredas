# C-132 evidence - DCP

## The port (2026-11-22)

From Veredas 1's `dcp.rs`. Read against Wireshark's DCP dissector (tshark 4.6.6) before and while
porting; what it settled:
- **A Set's control response is three bytes, with no BlockInfo**: option, suboption, error. Veredas
  1 wrote and read five (a BlockInfo word, then the three), and agreed with itself. tshark reads
  the five-byte form as "Status from Reserved", error 2, followed by a reserved block; the test
  `the_dissectors_tell_a_wrong_reading_apart` keeps that frame as the oracle's negative control,
  and this codec reads it as damaged (length 5 where 3 is expected).
- **A Hello's blocks carry a BlockInfo**, as answers do (measured: tshark reads `block_info` then
  the name in a planted Hello).
- **Option 2, suboption 9 is not an IPv4 gateway.** Veredas 1 read it as four bytes of address;
  the dissector has no such field, and the codec now keeps it unread. Suboption 10 (RSI
  properties) is read.
- The OEM device id and the device initiative are read into the identity (Veredas 1 read them
  into blocks and dropped them there).

Also changed:
- a damaged block carries a typed `Damage` (its size, a missing info word, a block running past the
  data, text that is not UTF-8), where Veredas 1 had a sentence in a `String`;
- text that is not UTF-8 is kept as bytes with its reason. Veredas 1 decoded it lossily, so a
  frame written back from a decoded one was not the frame read;
- the device role, the instance and the control response have exactly their sizes; Veredas 1
  took a role of one byte and a control response of any length from three, dropping the rest;
- bytes that make no whole block, and a Get request's odd last byte, are kept (`trailing`);
  Veredas 1 dropped them unseen;
- a PDU is written from its decoded form (`DcpPdu::encode`), so the bench can answer with what it
  read; a block past its 16-bit length and a PDU past 65535 bytes are refused, and a frame past
  1500 by the envelope. Veredas 1 cast the lengths with `as u16`;
- the station name rules are the standard's (labels, hyphens, port names, the address form);
  Veredas 1 checked the character set and the length only, so `-a`, `a..b`, `port-001` and
  `1.2.3.4` were accepted;
- the fixtures name no vendor or product: the MACs are locally administered, the ids made up.

Noise: twenty thousand seeded PDUs with DCP frame ids, services and types, each cut at every
length (about 800 000 decodes); every decode that succeeds writes back to itself, and one with an
overrun settles after one rewrite.

## Refute round 1 (2026-11-22): refuted, seven gaps

- **A Hello went to the Identify group address.** The standard sends a Hello to
  `01-0E-CF-00-00-01` (Wireshark's PROFINET plugin quotes the DCPBoundary text naming both
  addresses). `Mac::DCP_HELLO_MULTICAST` now; the tests pin both addresses and tshark's reading of
  every frame's destination. maquinar was told in the shared notes.
- **The Set gate lived in three helpers.** `DcpPdu::encode` and `frame` wrote any Set, a factory
  reset with a broken name to the broadcast address among them, and tshark read it cleanly. The
  gate is now in the codec: `frame` refuses a Set request to a group address, `encode` a Set block
  outside name, IP suite and signal, a bad name and a qualifier the block may not carry; a Set read
  from the wire decodes and cannot be written again.
- **A zero-length block where an info word is due read as a good empty value.** It is now damage
  (`NoInfo`), as one byte was.
- **Bytes were dropped unseen.** The role's reserved byte is now kept; a pad byte's value and a
  last odd block's missing pad are what a rewrite does not keep, said in the clause and pinned.
- **A Set answer's non-control block was read with an info word**; tshark reads none. A Set answer
  carries no info word in any block now.
- **The 65 535-byte round trip**: the clause now says "within what a frame carries".
- **The Get answer was never read by tshark, and the noise cuts never reached the blocks** (a cut
  shorter than the data length is a header error). The Get answer is now among the dissected
  frames, and each cut restates the data length.
- Not taken: the standard's "labels start with xn- only if RFC 5890 is applied" (the critic could
  not confirm the text here, nor can this session; accepted names are not narrowed on a memory).

## Refute round 2 (2026-11-22): refuted, eight gaps

- **The Set gate read the enum, not the wire.** `Service::Other(4)` or `ServiceType::Other(0)` wrote a
  Set request no check saw (a factory reset with a broken name to the broadcast address, read
  cleanly by tshark), from code or from JSON. A Set request is now known by its bytes (service 4,
  the selection bit clear).
- **Trailing bytes were written into a Set unchecked** (a block hidden there): refused now.
- **The one-device rule held in `frame` only**; `encode` gave a Set's bytes to any envelope. A Set
  request is now written by `frame` alone, with its device; `encode` refuses it.
- **Info words were written wherever a caller put them**, so the codec wrote frames the dissector
  reads wrongly (the five-byte control response among them). `encode` now writes a block's info
  word exactly where the PDU carries one, a damaged block as heard; a typed block only under its
  own code; a Get request's pairs only in a Get request.
- **A Hello answer and a manufacturer's option were read with an info word** the dissector does not
  read: the rule is now the dissector's (an Identify answer, a Get answer, a Hello request; a Set
  request's qualifier; never a manufacturer's option 0x80 to 0xFE).
- **`encode` wrote a PDU past what a frame carries**: refused past 1500 now.
- **The signal took any value, and a Hello any address**: the signal is 0x0100, a Hello goes to its
  group address alone.

## Refute round 3 (2026-11-22): refuted, the gate holding, its proof not

- **"Nothing else a Set does is expressible" was proven on six blocks**: mutants widening the gate
  passed. Every body of every kind, at its own code and at the three allowed codes, with no
  qualifier and with 0 to 3, is now framed: exactly five shapes are written, every other refused by
  its exact error.
- **Unread bytes under a typed code were written**, Veredas 1's five-byte control response among
  them, and a damaged block with an info word where none is read. Refused now: bytes as given only
  where no typed body is read, a damaged block's word only as the decoder would have kept it.
- **The info rule was not the dissector's in three families**, measured with tshark 4.6.6: an IP
  option outside 1 to 3, option 0xFF with another suboption, and a control block outside a Set
  request (the dissector reads a qualifier for option 5 wherever it is, the control response
  excepted). The rule is now the dissector's; options it cannot parse at all (0, 4, 8, 0x7F were
  tried: "parse error") have no reading to hold the codec to, and follow the general rule.
- **Mutants left alive by untested claims**: the device options' order (now read through tshark:
  `pn_dcp.option` lists the pairs' options in order), the full IP suite (now to the byte, read back,
  and read by tshark, which labels the four name servers with its address, mask and gateway fields,
  in order), the manufacturers' range (0x81, 0xC0, 0xFD, 0xFE), a Hello spelled `Other(6)`, a Get
  request pair with a word.
- **A Hello's address held in `frame` only**: `encode` now refuses a Hello as it does a Set request;
  a frame id that is not DCP's is refused on writing.

## Refute round 4 (2026-11-22): refuted, the gate holding, the writer looser than the reader

The critic found the Set and Hello gates holding in the code, 300 000 noisy PDUs decoding and
121 889 of them writing back to their own bytes, and these gaps, now answered:
- **The gates' tests used one frame id each**: a mutant gating only frame id 0xFEFD (or 0xFEFC for
  a Hello) passed, and would have written a broadcast factory reset that tshark reads whole, since
  the dissector reads the service, not the frame id. Both spelling tests now run under each of
  DCP's four frame ids.
- **The writer let through what the decoder never keeps**: a missing word over six bytes (read
  back as a good name "evil"), an overrun mid-PDU, Veredas 1's five-byte control response as
  damaged text, trailing bytes that make a block or a pair. One rule answers all of them: what is
  written must read back as the PDU written; the one difference allowed is the decoder's own, a
  last block that ran past the data read back as the whole block it kept.
- **Four control blocks were bytes as given where the dissector reads a qualifier alone** (5/1,
  5/2, 5/5, 5/6), and reads any further bytes as blocks of their own: a Hello could carry a second
  name the dissector sees and this codec did not. They are typed now (qualifier alone; more kept
  damaged), and the one remaining divergence, such a damaged block written back as heard, is
  pinned by a tshark test.
- **The control family's info rule**: the dissector reads no word for 5/0 and 5/7 and up (measured
  over 2496 frames by the critic, confirmed here); the rule now gives option 5 a qualifier for
  suboptions 1 to 6 only.
- **Counts and survivors**: the damaged table held 17 damaged blocks, not twenty; three more now
  (a signal of four bytes, a reset with bytes, the all-selector with bytes). Unread bytes under
  each typed code, the IP option 1/0, port-like names that are not port names, and the IP family's
  own BlockInfo field are now tested; the dissector's silence on services and types it decodes no
  block of is named in the clause.
Before this commit, 15 mutants of this round's points were run: all killed.

## Refute round 5 (2026-11-22): refuted, the gates holding, damage written back read otherwise

The critic found the Set and Hello gates holding under every frame id, 300 000 more noisy PDUs
round-tripping, and the info rule matching the dissector on 488 frames but for the options it
cannot parse. Answered:
- **A damaged block written back as heard is read otherwise by the dissector in ten families, not
  one** (a too-long block's extra bytes read as blocks of their own: a Hello carrying a second name
  the dissector sees; a too-short one swallowing the next), so the clause's "one place the readings
  part" was false. Rather than chase every family, the codec no longer writes a damaged block at
  all: decoding keeps it with its reason, writing it is refused by name (`DcpError::Damaged`). A
  scanner never needs to send one; the read-back gate's overrun exception goes with it. Veredas 1's
  five-byte control response, which the clause said this codec "will not write" and it did (as
  decoded), is now refused.
- **Mutants passed**: a signal of 0x0000 (one wrong value was tried; five now); one to three
  trailing bytes in a Set (six were tried; the read-back gate caught those); a lone trailing byte
  dropped on decoding (one- and two-byte tails now kept and written back); the IP options 1/4 to 1/8
  with a word (1/4 and 1/8 pinned); "unsupported" answers stripped of their word (an Identify and a
  Get answer of type 5 now read, by tshark too); a Hello gated by its type too (three type
  spellings now); a port-like name's first part unchecked (`port-abc-12345`); the typed codes held
  to the codec's own list (an independent one now).
- **Counts**: every kind of body is now in the gate's table, and the four control blocks are
  asserted to the byte, all four.
Before this commit, the critic's survivors and the new refusal's, ten mutants, were run: all killed.
