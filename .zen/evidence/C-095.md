# C-095: Portal to portal, the reading side

## What is built and what is not (2026-11-22)

The briefing has two portals speak portal's own HTTP interface (C-044): Oficina's portal reads the
one embedded in a controller through SSH's tunnel on the controller's loopback, and carries the
commands on the same link. Built here: the reading side, `peer::PeerClient`, over the interface
as it is, with nothing added to the server. Not built: the commands (Q37 rules how they are made
robust and which switch they pass); a peer as a source of the reader's own session, storing what
it reads (Oficina has not said what it keeps).

## Choices

- **HTTP/1.1 spoken by the reader itself over tokio**, not hyper's client. The first draft used
  hyper's client side, the hyper axum serves on, and it built: then the reachable suite showed what
  turning a feature on in a shared crate costs. Every crate sharing hyper was built anew, the
  database engine's build script among them (a `--workspace` build compiled `libduckdb-sys`; the
  same tree without the change reused the seed's), and supervisão's graph without portal gained
  `try-lock` and `want`, which its review had not read. The reader needs one method, `GET`, on a
  connection closed after one answer: its head read line by line under a 64 KiB limit, its body
  framed by chunks (extensions and trailers read past), by its length, or by the connection's end,
  each case and each breakage tested against a peer the test plays.
- **A connection per call**, no pool: the link is a loopback through a tunnel, a call is a window
  or a page, and a dead connection reused would be one more failure to tell apart.
- **Bounded in time, size and silence.** A tunnel can die without a reset reaching either end, so
  every call has a timeout (ten seconds by default), every answer a limit (32 MiB, far above a
  page or a window), and the stream a silence (15 seconds, three of the server's five-second
  keep-alive comments).
- **Typed where the reader acts, raw where it shows.** The snapshot's name, running flag, clocks,
  window, switch and sources are typed; its health, vitals, counters and recording stay as the peer
  writes them (`raw`), so a newer peer's added field reaches a screen without a new reader.
- **An event of an unknown kind is skipped**, the stream's own convention: a newer peer may add one.
- **A stream that ends stays ended.** Resuming is the reader's: a new stream's hello says where the
  peer is, and the gap is read again by window, which is what a lag event already asks.

## Refute round 1 (2026-11-23, at b5c62c4): refuted, one defect and nine bounds untested

1. **A value that is no finite number ended the stream**: the real portal serves `null` for a
   NaN or an infinity (JSON carries neither), and the reader typed every value `f64`, so a plant
   tag stuck at NaN, a common sensor fault, ended the stream and refused every window over it. A
   value, and a window's point, is `Option<f64>` now: none where no finite number was served, the
   stream going on, the window whole. A test drives a log carrying NaN and `inf` through the
   whole path, the capture, the store, the server and the reader.
2. **The 32 MiB limit** was proven for a declared length only: an answer in chunks and one running
   to the connection's end are refused past it too, asserted now.
3. **The 64 KiB head** was proven for one long line only: two 40 KiB headers are refused together.
4. **The defaults** were never used: a peer that never answers ends a call at ten seconds and a
   silent stream at fifteen, with the default client, while a real portal's idle stream, kept by
   its five-second comments, stays open past seventeen (a default silence under five seconds
   would kill every idle stream).
5. **The timeout's address**, 6. **`Connection: close`**, 7. **which clock is which** (each now
   against the key the peer named), 8. **a page's window**, 9. **the event limit** (a module test):
   asserted now.
10. **A missing key read as none**: a field the interface always writes, `null` for none, is now
   required as a key (`present`), so a snapshot missing `window_ms` is refused, not read as "no
   window".

Ten mutants, each red now: the critic's nine (the timeout naming no address, no
`Connection: close`, the running answer limit off, the running head limit off, a default silence
of 4 s, a default timeout of an hour, the two clocks swapped, the event limit off, a page's window
dropped) and a missing key read as none.
