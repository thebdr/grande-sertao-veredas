# C-074 evidence - the OPC UA server

## The cut (2026-11-22 to 26)

The briefing moves the OPC UA server from maquinar into core, since controlador's embedded portal
serves OPC UA. Maquinar agreed to the cut on 2026-11-22 with five corrections, taken whole
(`maquinar-answers-2026-11-22.md` on the shared notes folder; `docs/core-plan.md`, "The OPC UA
server"). Into core went the start (a thread and a current-thread runtime of its own, bound first
and advertising the bound port), the caller's application, namespace and folder, the variables and
their access levels, the user, the two limits, `parse_value` and `render_value`, the write guard
and the handle. Maquinar keeps `OpcConfig` and its file, the draws, ramps and reactions and their
loop, `stall`, `TICK`, the timer guard and the relay; it switches `opc.rs` onto core's module in a
commit of its own, C-026's test file unchanged, its run recorded again and refuted on the switch.
Maquinar's `opc.rs` was last changed on 2026-11-10, so the cut saved on the 23rd was still its
current code when it landed.

## What the stack does, met here

- A client's write of a scalar of another type passes the stack's own validation (C-026's refute
  round 2): the guard is a write callback on every writable variable, answering
  `BadTypeMismatch` itself, and `BadIndexRangeInvalid` for a ranged write. The callback runs under
  the address space's lock and cannot store the value, so a right one goes to a task on the
  server's runtime that lands it once the lock is free (C-026's refute round 3).
- A write carrying no value never reaches the callback: the stack's `validate_node_write`
  (async-opcua-server 0.19.0, `src/address_space/utils.rs`) answers `BadTypeMismatch` first, so
  it is not counted. The guard's own branch for it stays as a defence. Read in the stack's source
  and shown by the test through the stack's own client.
- A ranged write on the Value attribute does reach the callback (the stack refuses a range only
  on another attribute, `BadWriteNotSupported`), so `BadIndexRangeInvalid` is the guard's answer,
  for an index and for a range alike.
- The stack checks a node's read access for every attribute, not the Value alone
  (`validate_node_read` calls `is_readable` first), so a write-only variable's DataType read is
  refused and core's browser lists that variable untyped. The standard puts AccessLevel on the
  Value; this is the stack's reading, pinned by the browse test.
- A namespace equal to the application's URI is taken by the diagnostics node manager, registered
  first, and every read comes back `BadNodeIdUnknown`: refused before the bind (maquinar's finding,
  kept).

## The first runs (2026-11-26)

Two of the saved test's expectations were wrong and were corrected to what the browser and the
worker do, not the other way round:
- the browser orders a folder's children by display name, byte for byte (`Batch`, `Count`,
  `Start`, `level`), as C-021 states; the saved test expected the spec's order;
- with a limit of two nodes per read, a worker polling four tags has its poll refused whole and
  drops its session, so the test's reads after it found no session. The limits test now gives
  its worker two tags, within the limit, and the reads of two and three are its own.

Then `cargo nextest run -p veredas-core --test opc_server` green three runs in a row, 11 tests,
about 1.5 s each run.

## Refute round 1 (2026-11-27, at fc6646d2): refuted

Eleven mutants of `server.rs` survived the test file. Each one the critic's probe showed the code
doing what the clause says and the mutant not, so these were gaps in the test, not in the code.
The critic's mutants and logs are in `~/.cache/veredas/core/c074-refute/` on the development
machine. Answered:
- **A landing delayed by 300 ms (m09).** The test now writes twenty values and reads each one back
  at once through the same client's next read, then the caller's get. The first answer pinned the
  caller's get at the instant of the `Good` and went red once in sixty runs. The stack answers a
  write from a task of its own, but the session's task may already be due (woken by the worker's
  poll) and send the answer before the landing task runs. What does hold: the stack serves each
  Read in a task of its own too (`async_service_call!` in `src/session/message_handler.rs`), a
  request read after the answer is spawned after the landing task, and the current-thread
  runtime runs them in order. The clause says so: the value lands before any request the server
  reads after the answer.
- **The write handed before it landed (m11).** Through a burst of 4000 rising writes, the caller's
  get at the moment it is handed each one reads that value or a later one.
- **The cap counted over the server's life (m02), the constant moved (m01).** `WRITES_KEPT` is
  pinned at 4096, the dropped count at 404, and after the caller takes the kept writes the next
  one is kept again.
- **The check made after the bind (m03).** Every refusal case asks for a port already taken, and
  must come back as the spec's refusal, not the bind's.
- **An empty id or a trailing space accepted (m04).** The cases " count", "count ", "" and " ".
- **The browse name given as the id (m05).** The browse test compares each child's browse name.
- **Wrong DataTypes (m06), neighbouring wire types taken (m07).** Through the stack's client, with
  every variable readable and writable: the four DataTypes by number, then an Int64, a UInt32
  and an Int16 into the Int32, a Float into the Double and a Byte into the Boolean, each
  `BadTypeMismatch`, counted, nothing landed.
- **The plain bool words dropped (m08).** Eleven more inputs (twelve, said here first, was a miscount round 3 found).
- **The application named by core (m13).** Discovery's endpoints carry the caller's URI and name.

The critic's inexact phrases are taken too: the feature's wiring is C-073's, and the clause now
says so; the no-value write's answer is attributed to the stack by its source, and the guard's
own answer would be the same; and "closes every connection" is now held by a plain TCP
connection's end of file at once after the stop returns. Mutants m10 and m12 were killed in the
round, and stay so.

The kill check before round 2 (2026-11-27): each of the critic's fourteen mutants, applied in turn
to `server.rs` at the strengthened test, killed by the test meant for it (logs `kc-*.log` beside
the critic's). One thing it showed of the real code: the landing task handed a write and only
then counted it, so a caller handed a write could read a status not counting it yet. The count
and the handing now go under the status's lock together, and the clause says a write is counted
by the time it is handed; the raw-client test reads the status after taking the writes.

## Refute round 2 (2026-11-27, at 378dc724): refuted

Round 2's critic held the ordering reading against the stack's source and tokio 1.54.1's
current-thread scheduler: every service, Read and Write included, spawned
(`message_handler.rs`), answers sent from the controller's pending messages, no other runtime or
thread, wakes and spawns on the runtime's thread at the back of one queue. Five mutants survived
and one assertion passed for the wrong reason (logs and diffs in
`~/.cache/veredas/core/c074-refute/round2/`). Answered:
- **Counted after it was handed (m14, m14b).** The burst test checks the status at each write the
  caller takes: never fewer counted than taken.
- **Bound on every interface (m15).** The server must refuse a connection at 127.0.0.2, another
  loopback address, on its port.
- **The folder a component of Objects (m17).** The stack's own browse of Objects must show the
  folder by an Organizes reference. And the folder had no type definition at all, which the
  critic named as an inexact "folder": it is now a FolderType (`ObjectBuilder::is_folder`), and
  the browse pins that too.
- **`render_value`'s other arms (m16).** A Float, an Int64, a UInt32, and a Byte by its `Debug`.
- **The sessions test's "polls on".** Twenty polls from before the second client's refusal were
  waiting; the test now takes them first and needs a poll made after.
Its inexact phrases, taken:
- A Null variant passes the stack's own check and reaches the guard, which refuses it as another
  wire type and counts it: now in the clause and the test.
- A user with an empty name or named `ANONYMOUS` failed in the stack's configuration check after
  the bind; both are refused before it now, by name.
- The stop test took a connection reset too, which a connection still waiting in the listen
  backlog gets: the connection is now accepted and answered (OPC UA's Hello written by hand, its
  Acknowledge read back) and must see its end of file.
Beyond the clause, taken as well: a data namespace equal to OPC UA's own,
`http://opcfoundation.org/UA/`, gave index 0 and every client read `BadNodeIdUnknown`, the same
trap as the application's URI; it is refused before the bind.

The kill check after round 2's answer: m14b (counted 20 ms after the handing), m15, m16, and m17
remade on the moved code are killed, and so is m17b (the folder's FolderType dropped). Round 1's
mutants that still apply stay killed, and those the moved code no longer takes (m01, m02, m11)
were remade on it and are killed (`round2b/` beside the critic's logs). m14 survives: it counts
an instant after handing, a window of a few instructions, which the burst test's check catches
now and then (the critic's probe: 2 of 4000) and not reliably. So that order stands in the clause
as a reading of the code, the count and the handing under one lock, and the test holds what a
test can: a count a moment late (m14b) does not pass.

## Refute round 3 (2026-11-27, at de094eb7): refuted

Five mutants survived, each killed by the critic's probes, which on the real code agree with the
clause (`~/.cache/veredas/core/c074-refute/round3/`). The critic also ran 24 copies of the test

alone, no flake. Answered:

  server reported, so a server registering its own URI passed. A client now reads the server's

  client (maquinar's reading trims and keeps inner spaces too).
- **`parse_value`'s widths (r3m06, r3m07).** i32's two ends, and 0.1 and 1e300 as Doubles.
Its inexact phrases, taken: the inputs counted (33 now); the sessions test now holds that the
first client's worker reports no status at all while the second is refused; and the neighbouring
types' batch reads the four values back before the right writes (round 3's r3m05, landing every

## Refute round 4 (2026-11-27, at 6c602891): refuted

Eight new mutants were tried; seven survived, one was equivalent
(`~/.cache/veredas/core/c074-refute/round4/`). Answered:
- **A drop that leaked its runtime (r4m01).** The drop half of the stop test now holds the same
  teardown as the stop: an accepted and answered connection (a hand-written Hello) at its end of

- **The product URI (r4m03).** Discovery's endpoints carry the caller's URI as the product URI too.

  have left.
Its inexact phrases, taken: the set's refusals and the bind's error by their texts (r4m04,
r4m08), the bind's after the address being the system's words. Its one point on Windows, taken
