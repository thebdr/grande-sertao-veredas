# C-143 evidence - the listener against the bench's PROFINET devices

## On real links (2026-11-24)

Phase 4's proof against the fixture (the plan's "Fixture first"): maquinar's PROFINET device
(C-112, its own clauses proven by maquinar) run as the bench runs it, its executable on a bench
file, two devices on the far ends of two veth pairs in a private namespace, the listener (C-142)
on the near ends through raw links (C-134). The drift it rules out is between the bench's device
and the scanner's reading; the dissectors read every frame kept, so the drift of both from the
standard is ruled out too.

How the bench is run, and why so:
- **Its executable, not its library.** maquinar depends on aranha (its device speaks through
  aranha's codecs and raw link, Q5), so a dev-dependency of aranha on maquinar would be a cycle,
  and `tests/component.rs`'s split build (the codecs alone, the rest of aranha on them, aranha's
  tests copied) cannot hold maquinar. The test builds the executable with cargo and starts it in
  the private network, as its user starts it; closing its stdin stops it.
- **Into a target folder of its own** (under `CARGO_TARGET_TMPDIR`, as the split's): a build of
  one package resolves features apart from the workspace's, and cargo puts its executable in
  place again, so built into the workspace's target it would replace `target/debug/veredas-maquinar`
  under maquinar's own tests of its executable, which may run at the same moment. Measured: the
  first build 40 s at eight jobs and 1.2 GB, later ones fresh in under a second; no database
  engine in its tree.
- **The host's `/sys` is the namespace's**: an interface of the private network is not in
  `/sys/class/net`; its MAC is read from a raw link on it.

What the first runs taught (test faults, fixed): the chassis is kept as a key (`local:...`,
C-141); the dissectors read both segments' frames as one capture, so two interfaces asking ARP
from one address read as a duplicate address (each asks from its own); each interface's worker
sends on its own, so the order of frames sent holds within an interface, not across them. Six
runs in a row green, each under a second.

## The first refute round, answered (2026-11-25)

The critic (its own copy, 31 mutants, the scanner's alone against a bench built from the pristine
tree, and the codecs' against a bench rebuilt from the same mutated tree) found every value the
clause lists asserted and the scanner's misreadings of them killed, and refuted on what the test
took on trust:
- **The dissectors read the station name alone**, so a codec drifting from the standard on both
  ends (the bench uses aranha's codecs) went unseen: device ids or mask and gateway swapped in the
  writer and the reader alike passed. Every heard DCP frame's ids, address, mask, gateway, vendor
  text and role, and every LLDP frame's chassis and port id, are now read by the dissectors
  against the bench file's literals.
- **Every expected MAC came from the code under test** (`RawLink::mac`, which the listener and the
  bench's device use too), so a MAC misread on both ends passed. The test sets the four MACs on
  the interfaces before anything opens them, and expects those.
- **"Nothing damaged" was read before the bench stopped**, so its leaving frames were never
  checked: it is read on the final snapshot too.
- **"An Identify by name" was never shown to be by name**: each sent Identify is read by the
  dissectors as asking by `bomba-1`, with no all-selector.
- The own filter cannot fail here (no other sender on the private network's interfaces, and a
  packet socket never hears its own sends): it is C-142's to prove, and is.

The critic's five survivors, run in place (a codec mutant rebuilds the bench from the same
mutated tree, so it changes both ends; each built outside the suite lock, its test run under it):
device ids swapped on both ends, a MAC read short on both ends, mask and gateway swapped on both
ends, a leaving frame named damage, an Identify by name written as the all-selector; all killed.

## The second refute round, answered (2026-11-25)

The critic (its own copy, ten mutants each in a tree of its own with the bench pre-built from it,
a strengthened copy of the test, hand-made frames through tshark) found the first round's cause
again where the first answer had not reached: values read only through the codecs the bench and
the listener share, so a drift on both ends, or the bench's writers drifting alone, passed (eight
mutants, none killed by the test):
- **The device's word on its address** (the IP block's info): its conflict bit inverted, or its
  "set" written as set by DHCP, on both ends, passed; the dissectors read it now. (A conflict bit
  set is only an expert note to tshark, below the complaint threshold, so "no complaint" alone
  does not catch it.)
- **The PROFINET chassis MAC** an LLDP frame names its device by: written and read reversed, a
  group address on the wire, passed, since the listener keys LLDP by it through the shared
  decoder; the dissectors read it against the MAC the test set, while the port is not leaving.
- **The time to live**: "said it is leaving" came from the shared decoder's TTL of 0, so a TTL off
  by one on both ends passed; the dissectors read each interface's times to live, its last frame
  and only its last the leaving one.
- **The Hello and the Identify answer, as DCP calls them, and the answer as this request's**: the
  answer under another transaction id, under another frame id, or to the group address, and the
  Hello under the request's frame id, passed; the dissectors read each heard DCP frame's frame id
  by its service, and an answer's transaction id and destination.

The eight, run in place with the bench rebuilt from each mutated tree, are reported below.
The eight, each built outside the suite lock with the bench rebuilt from the same mutated tree and
run under it: the IP conflict bit inverted on both ends, set written as DHCP on both ends, the
chassis MAC reversed on both ends, the time to live one off on both ends, the answer under another
transaction id, under the Get/Set frame id, to the group address, and the Hello under the request's
frame id: all killed. The bench sending no chassis MAC is outside the clause's words, killed all the
same by the chassis MAC's read; keying LLDP by its source is equivalent on this fixture, where a
port's MAC is its device's.
