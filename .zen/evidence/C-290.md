# C-290 — The release manifest — lab notebook

## Refute round 1 (2026-11-22)

Refuted, six findings, none caught by the test:
- The executables were a model of cargo's discovery (`[[bin]]` names, `src/main.rs`, `src/bin/`,
  `autobins`), wrong where cargo drops an inferred target an explicit one already claims (a bin
  named `porteiro` at `src/main.rs`: cargo builds `porteiro` alone), where edition 2015 turns
  discovery off once a bin is explicit (the test's own fixture had no edition and asserted the
  wrong set), and where a bin's required features are not among the defaults (cargo does not
  build it).
- Members were filtered by `starts_with("crates/")`: `./crates/x` was skipped without a word and
  `crates/x/` read as a member with no manifest, both spellings cargo and L1 accept.
- `entrega check` returned at the first load-time refusal and never judged the manifests that read.
- An annotated tag's id passed as the commit: rev-parse, merge-base and `git show` all peel it.
- The repository's own check looped over no manifest.

Answered: the components are read by cargo itself, `cargo metadata --no-deps --offline` on the
commit's tree taken out of git (`git archive`), a bin left out unless the default features reach
its required ones; the commit's object type must be `commit`; `load_dir` returns what reads and
every refusal, and the executable says them all; the fixtures carry edition 2024 like the real
members; new tests pin each finding; the repository test requires the first release.

## Refute round 2 (2026-11-22)

Refuted, three findings:
- The required-features closure was still a model of cargo, wrong for `dep/feature` entries, an
  optional dependency's implicit feature, `default` itself and features turned on by unification
  across members: an executable cargo builds was left out of the manifest and of the bundle.
- Each folder was read against `canonicalize()` of the scratch tree while cargo's paths are not
  canonical: a scratch folder behind a link (and every Windows path) made every component vanish
  with no refusal.
- The scratch folder was named by the process and the commit: two calls at once in one process
  (libtest's threads) deleted each other's tree; nextest's process per test hid it.

Answered: a component's executables are every `bin` target cargo names, no feature read; the cut
builds them and refuses, by name, one cargo did not build with the default features (C-291). Each
folder is read against the `workspace_root` cargo prints. The scratch folder is a `TempDir` of the
call's own (`components_at_in` takes its parent, for the link's test). Tests: bins with required
features all named; a scratch folder behind a link; eight calls at once agreeing, none leaving a
folder; the file run three times under `cargo test`'s threads, green.

## Refute round 3 (2026-11-22)

Refuted, two findings:
- `git archive` applies `export-ignore`, `export-subst` and smudge or line-ending filters taken from
  `.git/info/attributes`, `core.attributesFile` and the git config, none of them in the history:
  with `crates/veredas-portal/src/bin/** export-ignore` in `.git/info/attributes`, a manifest
  leaving `porteiro` out checked clean, and two clones of one history could judge one manifest
  two ways. The cut's source for the builder and the bundle's docs came the same way.
- A refusal by cargo kept its first line only: a member folder the commit lacks said "failed to
  load manifest" with a path in the deleted scratch folder, the cause dropped; the test asserted
  the prefix alone.

Answered: `git::export_tree` writes a commit's tree from git's objects as stored (`ls-tree` and
`cat-file --batch`, no attribute or filter), executables and links kept, a path filter for the
bundle; the check, the builder's source and the bundle's docs all use it. Cargo's whole reason is
kept, its causes joined, the scratch path dropped. Tests: export rules in `.git/info/attributes`
and a local `core.attributesFile` and a smudge filter changing nothing that is read and a manifest
leaving `porteiro` out still refused; the export's modes, link and path filter; cargo's reason and
a missing member's cause asserted.

## Refute round 4 (2026-11-22)

Refuted, two findings; the export's parsing held (a tab, a newline, a quote and "ç" in names under
`core.quotePath`):
- Replace refs (`refs/replace/*`, never fetched by a clone) and `.git/info/grafts` rewrote what git
  read: a replaced `Cargo.toml` blob made the true manifest fail and a false one pass, a smuggled
  `[[bin]]` passed, a replaced commit read another tree, and a replace graft or a grafts line made a
  side commit pass as an ancestor of HEAD.
- A link committed with an absolute target, or one climbing out of the tree, let a file outside
  the history decide: the verdict on a past commit moved with no commit at all.

Answered: every git the tool runs goes through `git::command`, with `GIT_NO_REPLACE_OBJECTS=1` and
`GIT_GRAFT_FILE=/dev/null` (the cut's own `rev-parse`, `status` and `show` included); the export
refuses a link that leaves the tree, by its path. Tests: a replaced blob (version and bin), a
replace graft and a grafts line; an absolute and a climbing link; `leaves_tree` on six paths.

## Refute round 5 (2026-11-22)

Refuted, three findings, all through what a tree's links or names do on disk:
- A link judged as text stays inside the tree while it reaches out through another link
  (`r -> ../..`, then `Cargo.toml -> r/../../outside.toml`): one commit and one manifest got two
  verdicts, decided by a file in the scratch folder's parent.
- A member folder that is itself a link (`crates/veredas-portal -> ../fonte/portal`): cargo reads
  the folder it points to, while "one tree" compared the link's own blob, which never changes.
- A path that is not UTF-8 was written under a replacement character, so cargo named a bin no
  manifest can list.

Answered: a release's tree holds no link and no path that is not UTF-8; the export refuses either
by its path (the suite's repository holds neither: every path at d74be94 is a plain file). Tests:
a chained pair of links, a member folder as a link, a name that is not UTF-8, each refused by path.
Stated as a limit, not a finding: "a version names one tree" compares the component's folder; code
it reads from outside that folder (an `include!` of a path outside it) is not judged.

## Refute round 6 (2026-11-22)

Refuted, two findings:
- Cargo read outside the exported tree: a path dependency `../../../../fora` resolved into the
  scratch folder's parent (the verdict changed with a file there), and a root `Cargo.toml` that is
  a plain package sent cargo looking upward, where a planted `[workspace]` named members of its own.
- A tree made with `git mktree` holding a `..` entry was written outside the scratch folder.

Answered: the commit's root manifest must hold `[workspace]` (checked before cargo runs); cargo's
workspace root must be the exported tree, every package's manifest and every path dependency inside
it, each refused by name; any path with a `..`, `.` or empty part is refused before anything is
written. Tests: a path dependency out of the tree with and without the file it names, a package
at the root with a workspace planted above, a `..` entry with nothing left in the scratch parent.

## Refute round 7 (2026-11-22)

Refuted, three findings:
- A release naming a commit the repository lacks made `check_together` fail on `ls-tree` and
  throw away every "one tree" refusal collected, a false git error said in their place.
- Bin names were ASCII alone, while cargo names and builds `ação`: no manifest could check.
- Cargo reads member globs against the workspace root's absolute path unescaped: a scratch folder
  under `t[1]` made `crates/*` match nothing.

Answered: `check_together` leaves a release whose commit is no commit to `check`'s refusal, and a
tree git cannot give is a refusal, never an error; a bin's name takes letters of any script; the
scratch folder lies under the tool's cache whatever `TMPDIR` says, a parent holding a glob
character refused by name, cargo run from inside the tree (its messages then name the tree's own
paths). Tests pin each.

## Refute round 8 (2026-11-22)

Refuted, two findings:
- A commit whose root `Cargo.toml` is not UTF-8 raised an I/O error out of `components_at`, through
  `check` and `check_together`, and every refusal collected for the other releases was lost.
- The glob check judged the cache path as given: a relative one under `t[1]` passed it and cargo
  then misread the members.

Answered: whatever fails in reading one commit's tree is that commit's refusal (`components_at_in`
turns any error into one; a root manifest that is not UTF-8 is named as such), never an error out
of the check; the scratch parent is made absolute before the glob check, and the cache's path too.
Tests: three releases with one unreadable root manifest, both refusals said; a relative cache under
`t[1]` refused by its absolute path through the executable.
