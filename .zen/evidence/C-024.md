## Refute round 1 (2026-11-06): refuted, two gaps

- **A file the crate pulls in from outside its folder passed.** The vendor reader walked the
  crate folder alone, so an `include_str!`, `include!` or `#[path]` of a file elsewhere (the
  plan says the schema tests load the documents under `docs/`) was never read; the critic
  compiled a planted term in through both forms and the clause's command stayed green. The
  reader now follows every `include_str!`, `include_bytes!` and `include!` argument and every
  `#[path = ...]`, as a literal or as `concat!(env!("CARGO_MANIFEST_DIR"), ...)`, resolved from
  the including file's folder (the manifest dir for the `concat!` form), nested includes too,
  each file read once, a missing file left alone; pinned on a planted crate whose outside files
  each hold a term.
- **"Test-only and light" was a claim nothing checked.** The laws judge edges between members
  (a dev-dependency free), not external crates, so `duckdb` or `eframe` in any table would have
  passed. The test now walks the bench's resolved dependency graph from its node through
  `cargo metadata` (normal, build and dev, transitively) and requires it empty of `duckdb`,
  `libduckdb`, `eframe`, `egui`, `winit` and any `veredas-*` but core and the bench itself; the
  walk is proven to reach direct and transitive crates (`async-opcua-core`, `parking_lot`,
  `regex-syntax`), the ban list on planted names. The clause now says this.

Held: `src/main.rs` beside a `[[bin]]` of the same name on another path (one binary); duplicate
binaries and a bin with a crate type or `proc-macro` refused by cargo itself; `required-features`
and an underscored name; `[[test]] harness = false`; every law on the real tree, the plan commit
before the code commit.

## Refute round 2 (2026-11-06): refuted, two gaps again

- **Nine include forms rustc accepts passed the reader**: raw strings (`r"..."`, `r#"..."#`),
  brackets and braces as delimiters, whitespace inside `#[ path = ... ]`, `path` inside
  `cfg_attr`, `concat!` of plain literals, `concat!( env!(...)` with a space, and an include
  through a macro variable. The reader now tokenises: for each include macro it reads the
  argument's string literals as rustc does (plain with escapes, raw with any hashes) up to the
  matching delimiter and joins them, `env!("CARGO_MANIFEST_DIR")` standing for the manifest dir;
  for attributes it reads `path = <literal>` anywhere inside `#[...]`. An include whose argument
  holds no literal (a macro variable) or never closes is reported as unresolvable and fails the
  check: the bench never does that, and the clause says so. The planted crate pulls in fifteen
  outside files, one per form, each with its own term; the markers of the planted source are
  built at run time, since the reader scans this test file too and a planted `include` inside
  one of its strings read as one of the bench's own.
- **The graph walk removed duplicates by name**, so of two versions of one crate only the first
  popped was expanded, its subtree unseen (seven nodes of the real graph today). It walks by
  package id now, with `--all-features`, so an optional banned crate behind a feature that is
  off is seen too. Pinned on planted packages: two versions in either order, an optional
  dependency, a rename, a target table that is never true, a dev table, a clean package.

Noted by the critic, not a gap: the UI ban names the egui family (what Veredas 1's bench used);
the clause now says so rather than "no UI crate".

## Refute round 3 (2026-11-06): refuted on the include reader, which is gone

Five more forms rustc accepts passed the tokeniser (an unclosed `#[` in a comment switching the
attribute scan off, a `#[path]` inside an inline module, `env!("CARGO_PKG_NAME")` in a
`concat!`, a comment between the macro and its argument, `use std::include_str as grab`). A
reading of the text approximates the compiler and always will. The reader now takes the list
from the compiler: a nested `cargo build --all-targets` into the test's own target dir (what the
running test was built into, so nothing is built twice), then every dep-info file whose crate
root lies under the package, their listed files joined (a stale dep-info can only add). Pinned
on a planted crate built for real, twenty outside files pulled in by every form of three rounds,
a module never declared and an include under `cfg(any())` not read. The dependency walk held.

## Refute round 4 (2026-11-06): refuted, the build's own limits

Dep-info lists what one build compiled: a file under `cfg(unix)` passed on Windows, a file
behind a non-default feature and a doctest's include escaped, and a dep-info whose crate root
lies outside the crate folder (a `[[test]]` with a `path` elsewhere) was skipped. Now the nested
build runs with `--all-features`; a dep-info is the crate's when its root is one of the
package's targets as cargo lists them, and every target must have one; `cargo test --doc` must
report no doctest. The platform limit stays and the clause states it: what this platform's
`cfg` compiles in is seen here, the other platform's by its own run (the record is Windows',
CI's is Linux'). The planted crate adds a test target outside its folder, a feature-gated file
and a `cfg(windows)`/`cfg(unix)` pair, this platform's read and the other's not.

## Refute round 5 (2026-11-06): refuted, narrowly, on the profile

The nested build was the debug profile only, and `debug_assertions` is a `cfg` of this platform:
a file behind `cfg(not(debug_assertions))`, what a release build (the shipped executable) pulls
in, was never read. Now a `cargo check --release` of all targets with every feature runs beside
the debug build (a check writes the same dep-info, after expansion, without the codegen; about
two minutes cold, seconds after), its dep-info read the same way, every target required in each
profile. The clause now states its limit plainly instead of pointing at a run that does not
exist: a file behind a `cfg` no run compiles (another OS, `doc`, `doctest`) is outside the check.
Pinned on the planted crate: a `cfg(debug_assertions)` file and one behind its negation both
read, a `cfg(doc)` file read by neither. Held: a stale dep-info can only add, `required-features`
under `--all-features`, a `[[test]]` with `test = false` failing closed, ignored doctests listed
and so caught, `doctest = false` and a cross-compiling config failing closed.

## Refute round 6 (2026-11-06): holds

A release-only `include_bytes!` behind `cfg(not(debug_assertions))` in a planted test target
was found by the release check (the test went red with the file named), which also shows a
check writes the same dep-info as a build. Read and held: every target kind under check, no
`cfg` a check misses, `cfg(test)` in both profiles, a `dep:` feature not cached failing closed,
no `cfg` from `opt-level`. Noted, not a gap: a custom profile whose `debug-assertions` differs
from both dev and release, or `cfg(panic = "abort")` behind a profile with `panic = "abort"`,
would escape; neither exists, and either is a manifest change. The critic saw one red run of the
vendor check while this session was editing the bench's sources: a race that fails closed.
