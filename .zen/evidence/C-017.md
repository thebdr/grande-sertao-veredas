# C-017 evidence - the channel file

## The design (2026-11-05, Q9 and Q10)

The operator asked for configurable framing (Q9). The file format choices are Q10: TOML with
`format` and `version`, roles as strings, hex delimiters, behavioural rules as sections, every
key defaulted and misspellings refused (`deny_unknown_fields` on every table). The reader parses
the header alone first, so a file of another format or an unknown version is refused before its
body is judged (a version 2 file with keys this reader does not know reads as "unknown version",
not as a misspelling). Envelope and tail names share one map in a decoded frame, so a name used
in both is refused. The worked example in `docs/channel-schema.md` is the test's input, read
from the document itself: the documentation cannot drift from what loads.

## Refute round 1 (2026-11-05)

Refuted. The documentation's prose said a 12-byte envelope and a 4-byte tail; the example is 11
and 3 between the delimiters, a keep-alive 16 bytes. The prose now states those numbers and a
golden data frame, and the test reads them out of the prose and checks each against the loaded
file, so the words cannot drift from what loads. Four acceptances were wrong: a sequence field
without `[sequence]` loaded and every frame went out unnumbered (now refused; an empty
`[sequence]` takes the defaults); `value = 0` on a computed field passed a check written as
`value != 0` (the value is now optional and any stated value is refused); `max_frame` had no
ceiling though a peer may declare a frame that large and its bytes are held (now 16 MiB); and a
cycle of one number with `skip_duplicates` would skip every frame after the first (refused). The
segment header and tail were pinned by count and width only; they are pinned as name, size and
role, and every default of a minimal file is pinned, with each limit accepted at its edge.
