# C-017 evidence - the channel file

## The design (2026-11-05, Q9 and Q10)

The operator asked for configurable framing (Q9). The file format choices are Q10: TOML with
`format` and `version`, roles as strings, hex delimiters, behavioural rules as sections, every
key defaulted and misspellings refused (`deny_unknown_fields` on every table). The reader parses
the header alone first, so a file of another format or an unknown version is refused before its
body is judged (a version 2 file with keys this reader does not know reads as "unknown version",
not as a misspelling). Envelope and tail names share one map in a decoded frame, so a name used
in both is refused. The worked example in `docs/channel-schema.md` is the test's input, read
from the document itself: the documentation cannot drift from what loads.

## Refute round 1 (2026-11-05)

Refuted. The documentation's prose said a 12-byte envelope and a 4-byte tail; the example is 11
and 3 between the delimiters, a keep-alive 16 bytes. The prose now states those numbers and a
golden data frame, and the test reads them out of the prose and checks each against the loaded
file, so the words cannot drift from what loads. Four acceptances were wrong: a sequence field
without `[sequence]` loaded and every frame went out unnumbered (now refused; an empty
`[sequence]` takes the defaults); `value = 0` on a computed field passed a check written as
`value != 0` (the value is now optional and any stated value is refused); `max_frame` had no
ceiling though a peer may declare a frame that large and its bytes are held (now 16 MiB); and a
cycle of one number with `skip_duplicates` would skip every frame after the first (refused). The
segment header and tail were pinned by count and width only; they are pinned as name, size and
role, and every default of a minimal file is pinned, with each limit accepted at its edge.

## Refute round 2 (2026-11-05)

The round-1 fixes held, each probed. Refuted twice. A `connect` inside the cycle loaded, and with
a two-number cycle a counted probe stamped with the connect number went uncounted, so the next
data frame repeated the last and was dropped between two real channels (C-012 round 5 found the
same). The file now refuses a `connect` inside `first..=last`, the reversible choice recorded as
`docs/questions.md` Q11. And no test misspelled a key in `[sequence]`: with its
`deny_unknown_fields` removed the suite stayed green. Now pinned with `firts = 1`, and the edge
pinned with `connect` just outside the cycle on either side.

## Refute round 3 (2026-11-05)

The `connect` rule held at every position and width. Refuted on coverage alone: a one-line
mutation sweep over the checks of `load` left four survivors with the suite green: the tail
dropped from the fixed bytes, the floor of `max_frame` made inclusive, `connect` freed from the
field width, and `max_peers` raised to a floor of 2. Each is now pinned (a limit of 4 under the
5 fixed bytes of a layout with a tail; `connect = 256` on a 1-byte field; a limit of exactly
the 4 fixed bytes accepted and its keep-alive encoded; one peer accepted), and each of the four
mutations, re-run, now fails the suite.

## Refute round 4 (2026-11-05)

The round-3 pins held. The critic then swept 73 one-line mutations over the reader (every check
of `load`, `fields` and `delimiter`, every role list, every field copied into the spec, every
default, `deny_unknown_fields` on each of the six tables, both header checks) and ten survived
the schema test: `on_connect`, `keepalive_counts` and `idle_ms` replaced by their defaults (the
test only ever met them at their defaults); `sequence` allowed in a segment, `length` or `count`
in the tail; the computed-value check narrowed to sequence and length; the fit check limited to
1-byte fields; a segmented layout made to need a count, or a length. The code was right on every
input. Each is now pinned (the keys read away from their defaults; the three wrong-part roles,
a count given `value = 0` and 65536 in a 2-byte field refused with their messages; a segmented
layout accepted with a length, a count, and both), and each of the ten, re-run, fails the
schema test alone.

## Refute round 5 (2026-11-05)

All 82 mutations of the round-4 sweep (the critic corrected its count from 73) are killed by the
schema test alone. Seven more, aimed at claims the sweep had not touched, survived: the segment
header and the tail ignoring the framing byte order (always little-endian), and acceptance at
the top of each width (size 8 refused, a panic on any 8-byte field or 8-byte sequence, 255
refused in a byte, a 2-byte cycle capped at 255). The code was right on every input. Pinned: a
big-endian layout with a segment and a tail encoded byte for byte and every field read big;
an 8-byte field holding u64::MAX encoded; an 8-byte sequence with its rules; 255 in a byte; a
2-byte cycle to 65535. Each of the seven, re-run, fails the schema test alone.

## Refute round 6 (2026-11-05)

Asked for an exhaustive sweep over every claim of the clause and of the key reference, the
critic ran 47 new mutations; 13 were killed and 34 survived the schema test. Fourteen were in the
reader, and the code was right on each: the header matched loosely (a version below the known
one, a trimmed or case-folded format); delimiters limited to one byte, or the empty check only
on `start`; field checks proven in the envelope only (names, sizes, a shared role, a computed
value, a too-wide default, a blank name, a field's own byte order, a segment's default value).
Twenty were edits to the documentation that the test never read: the worked example's numbers
in prose, and every default, the ceiling, the size range and the known version of the key
reference. Now the test reads each of those from the text and compares it with what the reader
does, and pins each reader check in every part. All 36 survivors, re-run one at a time (the 16
in code checked to compile first), fail the schema test alone; with the earlier 89 that makes
125 one-line mutations, each killed by this test.

## Refute round 7 (2026-11-05)

The full sweep, 143 mutations (118 in the reader, 25 in the documentation): every mutation of
the reader is killed by this test alone. Five edits to the documentation survived, statements
the test never compared with the reader: the floors of `write_timeout_ms`, `outbox_limit_bytes`
and `max_peers` ("at least ..."), the format named in the header paragraph, and the worked
example's segment id (the prose could name an id its own quoted bytes contradict). The test now
reads each floor and checks the reader refuses one below it and accepts it, compares the stated
format with `FORMAT`, and builds the golden frame from the id the prose names. All five, re-run,
fail the schema test alone, and so do the 36 of round 6.

## Refute round 8 (2026-11-05)

All 143 earlier mutations killed by this test alone. A new class survived, 24 edits to the names
the key reference gives: sections, the keys of each table, the header keys, role names, the
parts a role is documented for, the required and optional flags, the hex delimiter example and
the words "delimiters included". The test now reads each name from the text and compares it with
what the reader accepts: each table's documented keys equal the list the reader gives when it
refuses an unknown key there; the documented roles and byte orders equal its variant lists; each
role loads in exactly the parts its entry names; a section flagged required is refused when
absent and one flagged optional loads absent; each delimiter example loads; the frame limit
counts the delimiters. All 24, re-run, fail the schema test alone. The critic marked the end of
the reference: what remains is prose restating refusals already pinned exactly, or framing and
channel behaviour belonging to C-010 and C-012.

## Refute round 9 (2026-11-05)

All 171 mutations swept so far were killed by this test alone. One gap: two optional keys, the
framing's `tail` and a field's `value`, had no documented default, and nothing checked that every
optional key states one. Every key in the reference now states in parentheses that it is required
or the value it takes when left out (`tail` (none), `value` (0), `segment` (none), `start`,
`end` (none), a field's `role` and `byte_order`, `name` and `size` (required), the header keys
(required)). A new test walks all 28 keys the reader knows, table by table (the reader's own
lists): a file without the key is refused when the reference says required, and otherwise loads
with exactly the value the reference states. The earlier mutations were re-expressed against the
new wording and re-run with 20 new ones (the stated defaults and statuses, `tail` made required
and `value` defaulting to 1 in the reader): all killed. While checking, the mutation runner used
here was found to leak (a code mutation stayed applied while the documentation mutations after it
ran, and CRLF rewriting hid patterns that did not apply); it now restores both files before every
mutation and compares ignoring line endings, and every list was re-run with it.

## Refute round 10 (2026-11-06): holds

The full sweep re-expressed against the uniform key form, with mutations for every required and
default statement: 189 one-line mutations (119 in the reader, 55 earlier documentation edits,
15 new statements), each killed by the schema test alone, the runner checking that no mutation
leaked into the other file and that every pattern applied exactly once.
