# C-028 evidence - the catalog file

## The design (2026-11-06)

The second plain-text file schema after the channel file (C-017), on its pattern: TOML, `format`
and `version` first, the header judged before the body, `deny_unknown_fields` on every table,
the documentation's worked example loaded by the test and its prose read for the numbers it
states (the golden bytes of an answer, the text of an outcome).

A message holds one `fields` list: `capture` reads it, `compose` writes it. `payload` (a regex)
reads text, `template` writes it. `len` fixes a body's length both ways: written bodies are
padded to it and refused beyond it; a received body of another length is not this message and
reads as nothing, whatever its fields would read as (a 7-byte answer holds every field of the
8-byte one; the test pins that it is refused).

`id_field` names the frame field that carries the id, so the bench's channel (and portal's)
knows where to put and read it without the catalog knowing the layout: a segment header field
in a segmented layout, an envelope field in one without. The catalog's `byte_order` is the
bodies', apart from the framing's.

A bad pattern, which capture treats as a warning that drops one capture, is a refusal here:
the file is the operator's, and a catalog that silently reads one message less is a drift.

## Refute round 1 (2026-11-06): refuted, at the altitude C-017 reached after ten rounds

The critic's mutation sweep (a `git archive` copy with its own target dir) found three reader
mutations and ten documentation edits the test did not kill, two false statements in the prose
(the ids were not the channel example's; an open-ended text field was written and read back
empty), and messages that load but can never round-trip (a payload with nothing to write, a
padded text body against an end-anchored pattern, a template longer than its length).

Now: the prose says the ids ride the channel example's `id` field; the reference's Keys section
is a list the test parses, each key with its statement in parentheses, and the test walks it:
each table's key list equal to the reader's own (read out of its refusal of a misspelled key),
each required key missing refused, each optional key missing loading with the stated default;
the prose's numbers (32, 8, 16, little-endian) read from the text; a nonzero pad, every type one
byte past the body and at its edge, a blank field name of spaces, `max` 0, padded names, a
field shadowing a repeat's numbered name or a payload group, two repeats of one name, each
refused by name. Compose's new refusals (no length, overlap, over the ceiling, cannot fit) reach
the catalog. A message with a payload and nothing to write is refused a write rather than
written empty; a padded text body against an end-anchored pattern is documented and pinned
both ways. Held: `version` 0, `-1` and `1.0`, a trailing space in `format`, a duplicate key,
a negative id, `u64::MAX`, every missing required field.

## Refute round 2 (2026-11-06): refuted, 21 documentation edits and 3 reader mutations survived

The key walk read only the first word of each statement; everything else the reference said
was free to drift. Every rule it states is now quoted beside the behaviour that pins it, in
`every_rule_the_reference_states_is_the_reader_s`: the type names and the byte-order words as
sets against the reader's own refusals, the ceiling's MiB against `MAX_BODY`, the second clause
of the field `len` statement walked, both unique rules, no shared byte, the field over text,
NUL padding and a NUL refused, too long, trailing whitespace, a sign on an unsigned type, hex
exact, refused beyond the length and at load past it, open-ended without a length, trimmed
placeholders and literal braces, the four template refusals, read-only messages, numbering
from 1, group 1 else the whole match, the most read, `max` 0. The reader: a repeat's numbered
names are compared as names (so `a2` at max 2 is refused, `a0`, `a01` and `a+1` are not), a
payload group that is a repeat's numbered name and two repeats whose numbered names meet are
refused, a repeat-only message is refused a write. The reference says so.
