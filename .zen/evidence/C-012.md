# C-012 evidence - one TCP telegram link

## The port (2026-11-05)

From Veredas 1's `crates/veredas-telegram/src/channel.rs`, now `src/telegram/channel.rs`; its
inline tests are `tests/telegram_channel.rs`, over real loopback TCP (two channels, or a channel
and a raw `std::net::TcpStream` so PRG and garbage can be written exactly).

Changed: `OUTBOX_LIMIT` is public (the deaf-peer test floods past it; a status pane can show it);
`next_prg` compares `== u8::MAX` instead of `>= 255` (clippy denies the absurd comparison on a
`u8`; same values); three nested `if let` collapsed into let-chains (edition 2024, clippy).
The channel's private `String` errors stay private: they surface as `ChannelEvent` and status
text, never as a returned error.

## Refute round 1 (2026-11-05)

Refuted, two bugs inherited from Veredas 1, and fixed:
- The service tick was a fresh `sleep(TICK)` inside `select!`, re-armed on every pass, so every
  command restarted it. Reading, flushing, probing and dialling ran only when 20 ms passed with no
  command: a burst of 300 frames to a reading peer delivered 0 and dropped the peer as "not
  reading"; a frame every 10 ms for 3.5 s delivered 0, never read the peer's own frame, and
  dropped it at 2.57 s. One `interval` now lives for the channel's life, and a queued frame is
  handed to the socket at once with a non-blocking write (partial writes kept), so the outbox only
  fills while the socket refuses bytes. A flush waits for the socket at most `WRITE_TIMEOUT` in all.
  The old deaf-peer test passed through the outbox overflow whether the peer read or not; a paced
  deaf peer now meets the write timeout and its `Disconnected` reason says so.
- Idle probes take PRGs from the sender's counter while the receiver ignored keep-alive PRGs, so
  after 254 probes (about 42 minutes of quiet at the spec's 10 s) the next data frame carried the
  last data frame's PRG and was skipped without a word. A keep-alive's PRG is now the last one
  seen (the connect keep-alive's 0 aside), pinned on a raw socket and between two channels.

The weak assertions are exact now: the connect keep-alive's PRG 0 in both roles, PRGs 0, 1..=255,
1..=45 over 300 frames, the idle probe counted within its window and absent while the peer talks.
The old idle test expected both ends to probe, which only phase luck made true: a peer that hears
the other's probes is not silent and rightly sends none.

Held: peer ids never reused; a departed peer's reply never reaching its successor; a new
connection's PRG state fresh; the dialler's backoff; a bind failure reported and stopped.

## Reshaped (2026-11-05): content-agnostic

After the operator's decision (`docs/questions.md` Q8) the module names no vendor and cites no
vendor document; the clause states the same capability in generic words. Its shape (start and
end bytes, the envelope, the sequence and keep-alive rules) is still one device's layout, fixed
in code: Q9 takes keeping it, pending a configuration schema.

## Refute round 2 (2026-11-05)

The round-1 fixes held for one peer. Refuted on several peers and a deaf one, all fixed:
- each tick gave every peer a 1 ms read timeout, which Windows' timer stretches to about 15 ms:
  with two peers the tick outlasted its period, the random `select!` then took about one command
  per tick, and a 300-frame burst took 3 s with two peers and 37 s with four (a stop behind a
  backlog to four deaf peers took 122 s). Reads are `try_read` until the socket has nothing, and
  every queued command is handled on each wake-up, Stop included;
- the flush awaited a deaf peer's socket inside the tick, so every other peer went unread for the
  whole 2 s write timeout (and 2 s more per deaf peer). The write timeout is now a clock started
  when the socket last took a byte and checked on each tick, never awaited;
- the outbox counted 256 frames, so a burst bigger than the socket buffer plus 256 frames dropped
  a peer that was reading. It is bounded by bytes (16 MiB, a memory bound) and whether a peer
  reads is the write timeout's judgement alone;
- the deaf-peer flood relied on Windows' small loopback buffers (Linux grows them to megabytes);
  it now feeds the peer until it is judged;
- the 254-probe test reached the collision about half the time; it now aims B at A's received
  number and repeats until B carried it.
Open, in Q9: whether a device's keep-alives consume sequence numbers.
